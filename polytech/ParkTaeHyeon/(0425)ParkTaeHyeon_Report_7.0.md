# Java (자바) 프로그래밍 언어의 3대 특징

서버 개발 생태계에서 리눅스와 가장 찰떡궁합으로 쓰이는 백엔드 절대강자 언어인 `Java`의 핵심 철학을 요약합니다.

## 1. 객체지향 프로그래밍 (OOP, Object-Oriented Programming)
자바는 C언어처럼 절차대로 위에서 아래로 함수만 실행하는 것이 아니라, 현실 세계의 사물(Object)을 모델링하여 부품(클래스)을 만들고 이 부품들을 조립해 거대한 시스템을 개발하는 방법론을 따릅니다.

* **캡슐화 (Encapsulation):** 알약의 캡슐처럼 데이터(변수)와 기능(메서드)을 하나의 캡슐 안에 묶어 외부에서 함부로 접근하지 못하게(Private) 보호합니다.
* **상속성 (Inheritance):** '자동차'라는 부모 설계도가 있다면, 그 설계도를 물려받아(상속) '오픈카'라는 자식 클래스를 만들면서 기존 코드를 100% 재활용합니다.
* **다형성 (Polymorphism):** '소리친다'라는 하나의 명령을 내려도 개, 고양이, 사자 등 상속받은 객체들에 따라 각각 다른 목소리 형태로 행동(오버라이딩)하는 성질입니다.

---

## 2. 절대적인 이식성 (WORA, Write Once Run Anywhere)
> "한 번 작성하면 어디서든 실행된다."

C언어로 짠 파일은 윈도우용 파생본, 맥용 파생본, 리눅스용 파생본을 각각 따로 다르게 코딩해야만 합니다. 그러나 Java는 **JVM(자바 가상 머신)**이라는 만능 번역기가 존재하여, 우리가 코드를 한 번만 짜면 JVM이 깔려 있는 윈도우, 리눅스, 안드로이드 모바일 등 세상의 모든 기기에서 코어 수정 없이 곧바로 실행해 줍니다. 

**[리눅스와의 완벽한 앙상블]**
바로 이 이식성 때문에 윈도우 개발자의 로컬 PC에서 짠 Java 코드는 구동 환경이 완전히 다른 리눅스(RedHat, Ubuntu) 라이브 서버에 올려도 아무 충돌 없이 완벽하게 동작합니다.

---

## 3. 메모리 강제 통제 (가비지 컬렉션, GC)
C/C++에서는 개발자가 직접 램(메모리)에 `malloc/free` 선언을 해 자리가 끝나면 치워줘야 합니다. 이걸 까먹으면 메모리가 줄줄 새어나가서 며칠 뒤 서버가 터지는 **메모리 릭(Memory Leak)** 참사가 일어납니다.

하지만 Java 개발자는 메모리 주소에 아예 접근조차 할 수 없습니다! 오직 자바 가상 머신의 **가비지 컬렉터 (Garbage Collector, 쓰레기 수집기)** 시스템이 주기적으로 메모리를 정찰하며, 사용이 끝난 메모리 찌꺼기들을 스스로 주워서 파기시켜 버리므로 시스템 안정성이 비약적으로 향상됩니다.
