# 아파치 (Apache) HTTP 웹 서버

1995년에 등장하여 2010년대 중반까지 전 세계 인터넷의 60% 이상을 무리 없이 감당했던, 현존하는 가장 위대한 오픈소스 웹 서버 소프트웨어입니다. 

HTTP 규약을 통해 누군가 내 서버의 IP를 치고 포트 80번으로 들어왔을 때 만들어놓은 HTML이나 이미지를 뱉어주는 거대한 가판대 역할을 합니다.

## 1. 아파치의 아키텍처 철학 (안정성)
아파치는 클라이언트 접속 시 "무조건 새로운 다중 프로세스(혹은 스레드) 방을 하나 찍어내서 전담 마크한다"는 **MPM(Multi-Processing Module)** 방식을 씁니다. 엄청나게 안정적이지만, 1만 명이 접속하면 방(프로세스)을 1만 개 만들어내어 메모리가 과부하로 터져버리는 동시접속(C10K) 약점이 있어 현대에서는 Nginx에게 점유율을 일부 빼앗기고 있습니다.

> **아파치 구성 핵심 3요소**
> * **코어(Core):** 프로토콜의 표준 규약 준수, 네트워크 소켓 유지 등 절대 변하지 않는 심장.
> * **모듈(Module):** 압축/보안(SSL)/가상호스팅 등 아파치는 다양한 플러그인(레고 블록) 모듈을 뗐다 붙였다 할 수 있는 유동적인 구조입니다.
> * **로드러(Loader):** 이 모듈 블록을 실시간 구동 중에 서버 재시작 없이 메모리에 적재해 주는(.so 파일) 기수입니다.

## 2. Ubuntu 환경에서의 아파치 설치 및 통제 가이드

우분투/데비안 리눅스의 표준 패키지로 매우 쉽게 설치 및 통제할 수 있습니다. (레드햇 계열에서는 `httpd`라는 이름으로 불리지만, 우분투 계열에서는 `apache2`라고 부릅니다.)

### [설치 및 서비스 구동]
```bash
# 1. 패키지 설치
sudo apt update
sudo apt install apache2 -y

# 2. 서버 실행 상태 제어
sudo systemctl start apache2     # 켜기
sudo systemctl stop apache2      # 끄기
sudo systemctl enable apache2    # 서버 재부팅 떄도 알아서 자동으로 켜지게 예약
```

### [주요 핵심 디렉터리 구조]
설치가 완료된 순간부터 아파치 제국의 관리는 리눅스의 `/etc` 경로 하위에서 이루어집니다.

1. `/etc/apache2/apache2.conf`
   * 시스템 환경, 권한 등 아파치 전체 서버의 운명을 좌우하는 **최상위 글로벌 설정 파일**입니다.
2. `/etc/apache2/sites-available`
   * 서버 1대에서 도메인을 여러 개로 쪼개어 돌리는 **가상 호스팅(Virtual Hosing)** 설정 파일을 보관하는 장소입니다.
3. `/var/www/html`
   * 외부 인터넷에 80번 포트로 내보낼 진짜 HTML 홈페이지 파일 소스들을 업로드해 두는 실제 디렉터리 경로명입니다.
4. `/var/log/apache2/`
   * 누가 내 사이트에 접속했는지(`access.log`), 접속 에러 혹은 서버 폭발이 났는지(`error.log`) 등 운영 이력 블랙박스가 기록됩니다.

### [실무 데몬 관리 명령어 팁 (Debian 계열 전용)]
```bash
# 설정 파일 내용이 문법에 맞는지 런타임 적용 전 미리 테스트해주는 치트키
sudo apache2ctl configtest

# 활발한 접속 중인 클라이언트 연결을 끊지 않고 설정파일 내용만 스무스하게 새로고침 (실무 필수)
sudo apache2ctl graceful

# 특정 모듈(예: ssl 보안)을 활성화하거나 비활성화
sudo a2enmod ssl
sudo a2dismod ssl
```
