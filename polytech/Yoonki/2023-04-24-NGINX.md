# 현대 웹의 심장: Nginx (엔진엑스)

과거 수십 년을 지배했던 Apache(아파치) 웹 서버를 밀어내고, 현재 넷플릭스 등 글로벌 트래픽의 극한을 다루는 테크 기업들이 가장 사랑하는 러시아 발 초고속 웹 서버이자 프록시 소프트웨어입니다. 

## 1. 아파치 웹 서버와의 아키텍처 비교 (C10K 극복)

아파치와 Nginx의 가장 결정적인 차이는 **접속자를 응대하는 뼈대(Architecture)**에 있습니다.

* **Apache (스레드/프로세스 기반):** 유저 1만 명이 접속하면 1만 개의 대응 스레드를 새로 찍어내어 1:1로 대응시킵니다. 안정적이지만 1만 개의 방을 생성하느라 메모리와 CPU가 고갈(C10K 문제)되어 서버가 다운됩니다.
* **Nginx (비동기 이벤트 기반 / Event-Driven):** 고정된 극소수의 워커(Worker) 하나가 쉬지 않고 회전(Loop)하며 만 명의 손님 주문을 동시에 이벤트 큐에 쑤셔 넣고, 처리되는 순서대로 즉각 비동기로 서빙합니다. 손님이 10배로 늘어도 서버 메모리 사용량은 거의 0 상태를 평온하게 유지하는 마법을 보여줍니다.

## 2. Nginx의 4대 핵심 활용 분야

초창기 단순한 정적 웹서버를 넘어, 오늘날 Nginx는 차세대 인프라의 스위치 보드로 역할이 확대되었습니다.

### 1) 역방향 프록시 (Reverse Proxy) 보안막
사용자가 백엔드의 진짜 리눅스 웹 서버나 톰캣(Tomcat) 포트로 다이렉트 접속하지 못하도록, 맨 앞에 Nginx가 대신 요청을 받아 보안 처리와 필터링을 한 뒤 내부 애플리케이션으로 넘겨주는 최전방 방패 역할을 합니다.

### 2) L7 로드 밸런서 (Load Balancer)
트래픽이 폭증할 때, `upstream` 지정을 통해 들어오는 접속자들을 뒤에 깔려있는 Node.js나 Spring 서버 3~4대에게 공평하게 Round-Robin(순차 배분)으로 나누어주는 트래픽 분산 처리기 역할을 무료로 완벽히 수행합니다.

### 3) 정적 콘텐츠(Static) 캐싱 엔진
무거운 HTML, 사진(jpg), CSS 파일을 캐시 메모리에 쥐고 있다가, 뒷단의 WAS로 굳이 묻지 않고 본인이 메모리에서 직접 고속으로 쏴주어 메인 서버 연산 부하를 100배 줄여줍니다.

### 4) SSL 종단(Termination) 처리기
뒤에 있는 개발 서버들은 복잡한 https 암호화를 신경 쓰지 않고 단순 처리만 하게 냅두고, Nginx 혼자서 무거운 인증서 복호화와 SSL/TLS 트래픽 암호화 터널링을 대리 독박하여 풀어내는 아키텍처를 구현합니다.
