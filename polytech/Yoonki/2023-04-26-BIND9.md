# BIND9 프라이빗 DNS 서버 구축

사용자는 브라우저에 접속할 때 `172.217.166.78` 같은 암호 같은 IP 주소를 외우지 못합니다. 
`google.com` 이라는 영문 도메인을 치면, 세계 어딘가에 있는 전화번호부 서버가 "아, 그 도메인은 저 숫자의 IP 주소야!" 라고 번역해 주는데 이를 **DNS (Domain Name System)** 서버라고 합니다.

인터넷 제공자(KT, SKT)의 막강한 공인 DNS에 기대지 않고, 우리 사내망이나 개인 연구소에서만 독자적으로 쓸 목적으로 가장 널리 세팅하는 오픈소스 데몬 프로그램이 바로 **`BIND9` (Berkeley Internet Name Domain)** 입니다.

---

## 1. BIND9의 핵심 구성 요소 

1. **`named` 데몬 프로세스:** 통신 소켓 53번(UDP/TCP)을 열어놓고 접속자들의 도메인 질문 쿼리를 수신하고 응답을 돌려줍니다.
2. **`named.conf` 메인 설정 파일:** (`/etc/bind/`) DNS의 보안 정책 설정이나 "내가 어떤 도메인들을 소유하고 있다"라는 **Zone** 목록을 선언하는 글로벌 규약 센터입니다. 
3. **`Zone File` (도메인 번역 장부):** 해당 도메인의 A 레코드(IP), NS(네임서버), MX(메일) 등의 실제 상세 번역 테이블 데이터를 담아둔 텍스트 원장입니다.

## 2. 나만의 로컬 DNS 서버 구축 및 설정 (Ubuntu)

`polypoly.com` 이라는 가상의 도메인을 `192.168.19.100` 리눅스 서버에서 직접 돌려보는 시나리오 실습입니다.

### 1단계: 패키지 설치
```bash
sudo apt update
sudo apt install bind9 bind9utils bind9-doc -y
```

### 2단계: 존(Zone) 도메인 뼈대 등록
`/etc/bind/named.conf.local` 파일을 에디터로 열어 도메인 이름과 실제 읽을 파일 경로를 매핑해 줍니다.
```nginx
zone "polypoly.com" {
    type master;
    file "/etc/bind/db.polypoly.com";
};
```

### 3단계: 실제 도메인 Zone 원장 파일 작성
이제 `/etc/bind/db.polypoly.com` 새 파일을 만들고, 글로벌 DNS 호스팅 규칙(SOA, TTL)에 맞춰 매핑 주소를 기입합니다.
아래 코드는 BIND9의 표준 문법입니다.

```text
$TTL    604800
@       IN      SOA     polypoly.com. admin.polypoly.com. (
                             3         ; Serial (수정 시마다 숫자 올려줌)
                        604800         ; Refresh
                         86400         ; Retry
                       2419200         ; Expire
                        604800 )       ; Negative Cache TTL
;
@       IN      NS      ns.polypoly.com.
@       IN      A       192.168.19.100
www     IN      A       192.168.19.100
```
> **[문법 해석]**
> * `$TTL`: 컴퓨터들이 해당 질의값을 캐시에 보관할 유효시간 (604800초 = 7일)
> * `SOA`: 이 도메인의 최고 관리 책임 서버와 관리자 정보 세팅 영역시작점
> * `IN A`: 핵심 코어. 호스트 이름과 `192.168.19.100` IPv4 주소를 매칭 시킨다는 의미. 이제 `www.polypoly.com`을 부르면 저 아이피로 인도됩니다.

**설정이 끝났으면 서버 재기동을 때려 방어 구역을 활성화합니다.**
```bash
sudo systemctl restart bind9
```

## 3. 다른 클라이언트(PC)들의 DNS 주소 변경

이제 내 스마트폰이나 다른 리눅스 서버들이, KT 인터넷의 DNS(168.126.63.1)를 바라보던 것을 끊고, 방금 만든 사설 BIND9 서버(`192.168.19.100`)에게 물어보도록 눈을 돌리게 해야 합니다. 

### Ubuntu 리눅스 클라이언트
최신 넷플랜(Netplan) 환경 혹은 `systemd-resolved` 데몬을 통해 DNS 설정값을 바꿔칩니다.
```bash
sudo vi /etc/systemd/resolved.conf

# 아래 내용 추가
[Resolve]
DNS=192.168.19.100

# 데몬 재시작
sudo systemctl restart systemd-resolved
```

### Red Hat / Rocky Linux
`nmcli` 커맨드라인 툴을 이용해 바로 네트워크 카드의 DNS 배를 틀어버립니다. (예: `ens33` 랜카드)
```bash
nmcli con mod ens33 ipv4.dns 192.168.19.100
nmcli con up ens33
```

이제 클라이언트 컴퓨터에서 `ping www.polypoly.com`을 날리면 성공적으로 `192.168.19.100`으로 매핑되어 핑이 나감을 확인할 수 있습니다.
