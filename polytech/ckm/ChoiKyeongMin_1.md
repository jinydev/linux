# 인프라 코드 관리: Git과 SourceTree

서버 인프라를 코드로 구성하는 시대(IaC)가 오면서 엔지니어들도 리눅스 설정 파일과 배포 스크립트를 `Git`으로 버전 관리하는 것이 필수가 되었습니다. 터미널 기반의 `git` CLI 명령어에 익숙하지 않은 사람들을 위해 생산성을 올려주는 **Git GUI (그래픽 툴)** 종류와 개념을 알아봅니다.

---

## 1. 대표적인 Git GUI 클라이언트 비교

### 1) SourceTree (소스트리)
* **특징:** Atlassian(Jira/Bitbucket 개발사)에서 배포하는 가장 대중적인 무료 클라이언트.
* **장점:** 완전한 한글 화를 지원하여 국내 사용자가 압도적으로 많습니다. 브랜치(Branch)가 뻗어나가고 병합(Merge)되는 과정이 지하철 노선도처럼 매우 시각적이고 화려하게 표현됩니다.
* **단점:** 프로그램 자체가 Electron/WPF 기반이라 무겁습니다. 변경된 소스 코드 라인이 수천 줄 단위로 넘어가면 로딩이 심하게 버벅거리는 현상이 있습니다.

### 2) GitHub Desktop
* **특징:** GitHub 본사에서 직접 만든 공식 클라이언트.
* **장점:** 매우 가볍고 빠릅니다. GitHub 저장소와의 연동이 클릭 한 번으로 끝날 만큼 강력하며 변경된 코드(Diff)를 보여주는 속도와 가독성이 뛰어납니다.
* **단점:** 브랜치 그래프 시각화 기능이 거의 없어서 복잡한 병합 히스토리를 파악하기 힘들고, 한글 지원을 하지 않습니다.

### 3) GitKraken (깃크라켄)
* **특징:** 개발자들 사이에서 가장 아름답고 미려한 UI로 평가받는 크로스 플랫폼 툴.
* **장점:** Windows, Mac, Linux 모든 환경을 동일한 UI로 지원하며, 실행 취소(Undo) 마법 등 고급 기능을 쉽고 아름답게 제공합니다.
* **단점:** 대규모 저장소를 띄울 때 메모리(RAM)를 꽤 많이 잡아먹으며, 개인 프로젝트 외에 프라이빗 저장소 용도로는 유료 결제가 필요합니다.

---

## 2. SourceTree를 통한 형상 관리 기초

`SourceTree`를 설치한 후 저장소를 다루는 필수 용어와 절차입니다.

### 1) 저장소(Repository) 셋팅
* **Local (로컬):** 내 랩탑 혹은 현재 접속 중인 리눅스 시스템 서버 내의 디렉터리입니다.
* **Remote (원격 저장소):** 코드를 동기화하고 백업하는 클라우드 기지국(GitHub, GitLab)입니다. 
* **Clone (복제):** 타인의 혹은 빈 원격 저장소(`https://github.com/...`) 주소를 따서, 내 로컬 컴퓨터의 특정 폴더로 모든 소스를 복사해 내려받는 명령어입니다.

### 2) 코드 변경 및 백업 (Stage ➡️ Commit ➡️ Push)
소스트리에서 파일을 수정하면 'Unstaged(스테이지에 올라가지 않음)' 영역에 뜹니다.
1. **Stage (올리기):** 수정된 수십 개의 파일 중 이번 작업 목적에 맞는 파일들만 골라서 체크(+)합니다.
2. **Commit (커밋):** 스테이지에 올라간 파일들의 스냅샷 도장을 찍습니다. 이때 `Fix: Nginx 포트 오타 수정` 처럼 커밋 메시지를 작성하여 로컬 저장소에 영구 박제합니다.
3. **Push (푸시):** 커밋되어 내 컴퓨터에만 쌓인 역사들을 클라우드(GitHub) 원격 저장소 서버로 밀어 올려 공유합니다.

---

## 3. 원격 데이터 업데이트 및 제어

* **Fetch (패치 - 안전함):** 누군가 원격 저장소에 새 코드를 올렸는지 '확인만 다운로드'해 옵니다. 내 로컬 파일엔 아직 적용하지 않아 코드가 깨질 위험이 없습니다.
* **Pull (풀 - 병합):** `Fetch` + `Merge`의 합체기입니다. 원격 저장소의 최신 내역을 가져온 즉시 내 파일들에 강제로 덧씌워서 덮어버립니다. 충돌(Conflict)이 날 수 있습니다.
* **Stash (스태시 - 임시 대피소):** `login` 브랜치에서 코딩을 열심히 치고 있는데 갑자기 치명적인 긴급 버그가 터져서 브랜치를 변경해야 할 때, 지금까지 치던 코드를 커밋하지 않고 포장만 해서 주머니에 숨겨놓는(임시 저장) 매우 유용한 기능입니다. 
* **Revert (리버트 - 되돌리기):** 코드를 망쳤을 때, 망치기 이전 상태를 그대로 복사해와서 '새로운 정상 커밋'을 추가해 덮어씌우는 방식입니다. 함부로 과거를 지워버리는 `Reset`과 달리 기존 기록을 남기면서 복구하므로 협업 시 안전합니다.
