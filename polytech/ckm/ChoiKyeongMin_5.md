# 리눅스 압축 2편: 엔진 종류 (gzip, bzip2, xz, zip)

`tar` 명령어로 파일들을 예쁘게 하나의 꾸러미로 묶어냈다면(아카이빙), 이 거대한 용량을 실제로 어떻게 구겨 넣을지 압축 엔진(Algorithm)을 골라야 합니다. 엔진의 성능에 따라 압축에 걸리는 CPU 속도와 최종 용량 다이어트 폭이 크게 좌우됩니다.

---

## 1. 리눅스 표준 고속 엔진: `gzip` (.gz)

GNU zip의 준말로, 수십 년간 리눅스 세계의 영원한 대문자 디펜스 표준입니다.
* **장단점:** 압축 속도가 매우 빨라서 서버의 CPU를 괴롭히지 않습니다. 다만 최고 수준의 용량 다이어트(압축률)를 기대하긴 어렵습니다.
* **관련 명령어:** `gzip [파일명]`, `gunzip [파일명]`
* **Tar 연계 옵션:** `-z` 옵션 사용 (`tar cvfz hello.tar.gz 대상폴더`)

## 2. 중간 성능 엔진: `bzip2` (.bz2)

블록 정렬 알고리즘을 사용한 엔진으로 gzip보다 더 파일을 작게 구겨 넣을 수 있습니다.
* **장단점:** gzip 보다는 파일 용량이 확실히 작아지지만, 연산 로직이 훨씬 복잡해 압축하는 데 소요되는 연산 CPU 시간이 두 배 정도 더 걸립니다.
* **관련 명령어:** `bzip2 [파일명]`, `bunzip2 [파일명]`
* **Tar 연계 옵션:** `-j` 옵션 사용 (`tar cvfj hello.tar.bz2 대상폴더`)

## 3. 현대 최강의 압축률 엔진: `xz` (.xz)

LZMA2 라는 극강의 데이터 무손실 알고리즘을 내장한 차세대 압축 끝판왕입니다.
* **장단점:** 현존하는 툴 중 가장 지독하게 파일 용량을 쥐어짜서 작게 만들어주기 때문에, 우분투 데비안 소스코드를 배포하는 전 세계 오피셜 미러 사이트들의 최애 포맷으로 채택되었습니다. 단점은 그만큼 압축 '시간'이 너무너무 오래 걸립니다.
* **관련 명령어:** `xz [파일명]`, `unxz [파일명]`
* **Tar 연계 옵션:** `-J` (대문자 J) 옵션 사용 (`tar cvfJ hello.tar.xz 대상폴더`)

## 4. 윈도우 호환 통합 엔진: `zip` (.zip)

위에 언급된 도구들은 리눅스 세계관에 국한되어 강력하지만, 저 파일들을 윈도우 PC로 옮겼을 때 압축 풀기가 곤란할 수 있습니다. 그래서 윈도우의 알집과 똑같은 포맷으로 아카이빙(묶기)과 압축(줄이기)을 일체형으로 끝내버리는 패키지가 `zip` 입니다.

* **특징:** 원본 파일이 사라지면서 새 압축 파일로 바뀌어버리는 gzip 등의 종특과 달리, `zip`은 윈도우처럼 원본 폴더들은 안전하게 놔두고 별도의 `.zip` 파일을 하나 예쁘게 복제 생성해 줍니다. 윈도우 호환성이 100%라 파일 송수신 시 매우 유리합니다.

```bash
# 기본 압축. 하위 폴더 내용까지 싹 쓸어담기(-r)
$ zip -r back_image.zip /var/www/image/

# 압축 해제. 그냥 윈도우의 '여기에 풀기'와 완벽히 같습니다.
$ unzip back_image.zip

# (심화) 암호를 걸어서 보안 압축 문서 만들기 (-e)
$ zip -e secret_files.zip ./myfolder/*
```

> **🔥 [성능 & 시간 비교 종합 요약]**
> * 압축률(용량 축소) 짱 먹는 순위: **xz > bzip2 > gzip**
> * 압축 끝나는 CPU 스피드 짱 먹는 순위: **gzip > bzip2 > xz** 
> * 즉, 무조건 좋은 xz가 능사가 아니며 내 서버 장비의 남은 CPU 사정에 맞춰 골라 쓰는 것이 핵심입니다.
