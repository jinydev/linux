# 리눅스 빌드의 심장: GCC 컴파일 프로세스

우리가 C언어로 작성한 텍스트 파일(`hello.c`)이 컴퓨터가 읽을 수 있는 0과 1의 바이너리 실행 파일(`hello`)로 변신하기까지, 리눅스의 표준 번역기인 **GCC (GNU Compiler Collection)**가 수행하는 마법의 4단계를 알아봅니다.

---

## 1. 전처리 (Preprocessing) 단계
가장 먼저 소스코드 안에 있는 `#` 기호로 시작하는 지시자들을 찾아서 치환해 주는 밑작업 단계입니다.
* **동작:** `#include <stdio.h>`를 만나면 실제 `stdio.h` 파일의 내용을 그 자리에 통째로 복사해서 붙여넣습니다. `#define MAX 100`을 만나면 소스코드 내의 모든 `MAX` 글자를 `100`으로 일괄 변환(리플레이스)합니다.
* **결과물:** 순수하게 C언어 코드만 남은 **확장 소스 파일 (`.i`)** 이 임시로 만들어집니다.
```bash
# 전처리 과정만 단독으로 수행해서 결과물 확인하기
gcc -E hello.c -o hello.i
```

## 2. 컴파일 (Compilation) 단계
전처리가 끝난 C언어 코드를, CPU 아키텍처에 맞는 **어셈블리어(Assembly Language)**로 번역하는 핵심 단계입니다.
* **동작:** 사람이 치는 고수준 연산 로직(if, for, int)을, 기계어 바로 윗 단계인 원시적인 어셈블리 명령어(`MOV`, `ADD`, `PUSH` 등) 체계로 1:1 대응 번역합니다.
* **결과물:** 어셈블리어 코드가 적힌 **어셈블리 파일 (`.s`)** 이 만들어집니다.
```bash
# 어셈블리어 단계까지만 컴파일 진행하기
gcc -S hello.c
```

## 3. 어셈블 (Assembly) 단계
어셈블리어를 진짜 컴퓨터 CPU 칩셋이 읽고 전기를 통하게 할 수 있는 0과 1의 비트(기계어, Machine Code)로 완벽히 조립하는 단계입니다.
* **결과물:** 바이너리 포맷으로 뭉쳐진 **오브젝트 파일 (`.o`)** 이 생성됩니다. (단, 아직 메모리에 올라가 온전히 실행될 수는 없는 깡통 상태입니다.)
```bash
# 오브젝트 파일(.o)까지만 생성하기
gcc -c hello.c
```

## 4. 링크 (Linking) 단계
나 혼자 짠 코드가 아니라 `printf()` 처럼 남이 짠 외부 라이브러리 함수나 운영체제 시스템 콜과 이 오브젝트 파일을 물리적으로 하나로 합체시켜 주는 마지막 배포 단계입니다.
* **동작:** 내 오브젝트 파일(`.o`)의 비어있는 메모리 링커 함수 주소들을, 진짜 로컬 라이브러리 파일 체인들과 풀칠해서 연결해 줍니다.
* **결과물:** 마침내 리눅스 시스템에서 `./hello` 로 구동 가능한 **최종 실행 모듈 파일 (`Executable`)** 이 완성됩니다.
```bash
# 한 큐에 4단계를 전부 통과해서 최종 실행파일(hello) 만들기
gcc -o hello hello.c func.c
```
