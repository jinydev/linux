# 서버 사이드 렌더링의 고전: PHP

HTML의 한계를 극복하고 사용자의 요청에 따라 게시판, 로그인, 장바구니 데이터를 동적으로 그리기 위해 탄생한 리눅스 서버 시대의 동역자, **PHP (Hypertext Preprocessor)**의 구조적 특징을 알아봅니다.

---

## 1. PHP의 동작 원리
PHP는 전형적인 **인터프리터(스크립트) 언어**이자 서버 사이드 스크립트입니다.
개발자가 HTML 소스 라인 중간중간에 `<?php ... ?>` 갈고리를 걸고 C언어와 비슷한 문법으로 코드를 박아두면, 사용자가 페이지를 요청할 때 리눅스의 아파치(웹서버)가 미리 이 코드를 한 줄 한 줄 해석(연산)하여 최종적으로 순수 HTML 글자들만 클라이언트(브라우저)에게 뱉어 보냅니다. 따라서 해커가 브라우저 우클릭 소스 보기를 눌러도 PHP의 원본 비밀 코드는 절대 볼 수 없습니다.

## 2. PHP의 생태계 및 발전 역사
* **1990년대의 영광:** 웹 1.0 시절, 단순 CGI를 벗어나 가장 직관적으로 데이터베이스(MySQL)를 바인딩해 웹사이트를 찍어낼 수 있는 생산성을 무기로 전 세계 웹사이트의 70% 이상이 PHP로 작성되었습니다(여전히 워드프레스 생태계 등을 통해 높은 점유율 유지).
* **PHP 7과 모던 웹 (2015~):** 객체지향과 거리가 멀었던 원시 스파게티 구조의 한계(PHP 5 시절)를 직면하다가, 엔진을 갈아엎고 속도를 2배 이상 끌어올린 메이저 업데이트인 PHP 7과 PHP 8이 등장하며 속도와 타입 엄격성을 확보했습니다. 현대에는 `Laravel(라라벨)`과 같은 걸출한 객체지향 프레임워크 위주로 사용됩니다. 

---

## 3. 실무 아키텍처로서의 장단점

### ✅ 도입 장점 (무적의 생산성)
1. **압도적인 접근성:** `index.php` 파일 하나 만들고 우분투 `/var/www/html/`에 복사만 하면 즉시 완성입니다. 톰캣이나 Node.js 같은 복잡한 포트나 WAS 구동 설정 과정이 전혀 필요 없습니다.
2. **이식성:** Linux (LAMP), Windows (WAMP), 심지어 Mac까지 세상의 어떤 운영체제나 값싼 웹호스팅이라도 무조건 돌아간다는 이식성의 제왕입니다.

### ❌ 도입 시 치명적 단점 (유지보수 재앙)
1. **스파게티 소스코드:** HTML 디자인 태그와 로직(if, for, MySQL 접속 코드)이 한 파일 안에서 위에서 아래로 마구잡이로 뒤섞여 짜여지기 쉬워, 규모가 커지면 유지보수가 불가능한 쓰레기 코드가 되기 십상입니다.
2. **상태 유지 기능 부족:** 메모리에 계속 상주하는 최신 데몬형 코어가 아니라 파일 단위로 그때그때 처리하고 박살 내는 인터프리터이므로, 대규모의 실시간 스트리밍(웹소켓, 채팅 등)이나 마이크로서비스(MSA)를 구축하기에는 매우 불리합니다.
