# 리눅스 시스템 기초 및 권한(Permission) 체계 총망라

> 본 문서는 리눅스의 등장 역사부터 배포판의 갈래, 그룹 권한 설계, 하드/소프트 링크의 구조, 그리고 필수 VIM 에디터 조작법까지 리눅스 OS 교과목 전반을 압축 요약한 핵심 치트시트입니다.

---

## 1. 운영체제(OS)로서 리눅스의 태동
1991년 리누스 토발즈가 개발한 커널 위로, 스톨만(Richard Stallman)이 이끄는 자발적 생태계 운동인 **GNU(GNU's Not UNIX) 프로젝트**의 수많은 오픈소스 자유 소프트웨어들이 결합되어 탄생했습니다.
* **강점:** 유닉스와의 높은 이식성, 완전한 오픈 소스 공개(보안 구멍 발견 시 즉시 패치 가능), 하드웨어 리소스 최적화 효율성(구형 PC 재활용), 전 세계 인터넷 서버의 90% 이상을 구동하는 신뢰도 높은 백엔드 능력. 

### 주요 배포판(Distribution) 파벌 요약
1. **RedHat (레드햇) 계열:** 유료 기술 지원으로 기업 금융 서버를 장악한 RHEL, 그리고 이를 백업하던 오픈 커뮤니티 실험장인 Fedora(페도라)와 무료 쌍둥이 복제본 CentOS(현재 Rocky로 계승).
2. **Debian (데비안) 계열:** 전 세계 수만 명의 순수 자유 기여자들이 개발하는 데비안 생태계를 바탕으로, 가장 방대한 패키지 저장소와 직관적 편의성을 탑재한 클라우드 1위 OS **Ubuntu(우분투)**. 그리고 해킹 방어용 Kali 리눅스 등 파생.

## 2. 파일 권한(Permission)과 소유권 관리

리눅스 시스템은 한 서버에 여러 사람이 동시 접속하는 환경이므로, 내가 만든 파일과 옆에 있는 사람이 만든 파일의 경계를 철저히 비밀번호 치듯 차단해야 합니다. 

### 1) 퍼미션 구조 파악 (ls -l)
터미널에서 `ls -al` 을 치면 파일 왼쪽에 `-rwxr-xr-x` 와 같은 10자리의 암호가 보입니다. 
* **첫 글자 (Type):** `-` 이면 일반 파일, `d` 이면 디렉터리, `l` 이면 링크파일입니다.
* **나머지 9글자 (Target):** 권한을 3글자씩 쪼개어 각각 **[소유자] - [그룹] - [기타 3자]** 에게 부여된 권한을 선언합니다.

| 분류 구분 | 권한 기호 | 의미와 속성 | 숫자값 배점 |
| :-- | :-- | :-- | :-- |
| **권한 종류** | `r` (Read) | 파일을 열어 읽을 수 있음 (디렉터리 내부를 목록으로 봄) | **4** |
| | `w` (Write) | 파일을 수정하거나 지울 수 있음 (디렉터리에 몹을 만들거나 지움) | **2** |
| | `x` (eXecute) | 프로그램 파일이라면 실행을 시킴 (디렉터리 속으로 들어갈 수 있음) | **1** |

> 📌 **퍼미션 절대 수치 변환 (Chmod):**
> 만약 소유자에게 읽기/쓰기/실행 모두(`4+2+1=7`), 나와 같은 파트 그룹원에겐 읽기와 실행만(`4+0+1=5`), 남들에겐 실행 권한만(`0+0+1=1`) 주고 싶다면, 명령어는 `chmod 751 파일명` 이 됩니다.

### 2) 소유권(Ownership) 변경
* `chown [유저명]:[그룹명] 파일명`: 이 파일의 실제 주인을 다른 사람이나 다른 팀으로 통째로 양도해버리는 시스템 관리자급 명령어입니다.

## 3. 리눅스 파일 복제 철학: 링크 (Link)

같은 파일 데이터를 다른 방(폴더)에서도 참조해야 할 때, 하드디스크의 낭비를 막고 데이터 무결성을 지키는 아키텍처입니다.

* **Hard Link (하드 링크, `ln 원본 대상`):** 디스크에 기록된 진짜 물리적 데이터 주소(Innode)에 빨대를 직접 여러 개 꽂는 방식입니다. 원본 파일을 폭파시켜 지워버려도, 하드링크가 한 개라도 살아있으면 디스크 데이터는 소실되지 않고 좀비처럼 온전히 작동합니다. 별도의 디스크 공간도 전혀 차지하지 않습니다.
* **Symbolic Link (심볼릭 링크, `ln -s 원본 대상`):** 윈도우의 '바로 가기 아이콘'과 100% 동일합니다. 단순히 원본 파일의 길(이름)만을 가리키는 텍스트 이정표입니다. 만약 원본 파일이 지워지면 심볼릭 링크 파일은 길을 잃은 빨간색 에러 마크가 뜨며 동작하지 않게 됩니다.

## 4. 서버 시스템 관리자 전용 편집기: VI (VIM)

GUI 마우스가 없는 검은 텍스트(CLI) 환경 속에서 시스템 설정 파일을 수정하기 위한 유닉스 맹장 에디터입니다. 타이핑 치는 화면과 명령을 내리는 화면이 분리된 모드(Mode)형 에디터입니다.

### [모드 전환의 이해]
1. **명령 모드 (커맨드 상태):** VIM을 처음 켜면 무조건 들어가는 대기 상태입니다. `dd`를 누르면 줄이 잘려 나가고, `yy`를 치면 줄이 복사되는 단축키 트리거 상태입니다. 글씨(ABC)를 칠 수 없습니다.
2. **입력 모드 (알파벳이 쳐지는 상태):** 명령 모드에서 키보드의 **`i` (현재 자리 삽입), `a` (오른쪽 빈칸 삽입), `o` (아랫줄 새로 만들어 삽입)** 중 하나를 누르면 밑에 `[INSERT]`가 뜨고 글씨가 실제 타건됩니다. 입력을 다 하고 나갈 땐 무조건 `ESC`를 칩니다.
3. **마지막 행 모드 (종료 및 지시):** 저장이나 문장 찾기를 수행할 땐 명령 모드에서 `:`(콜론), `/`(슬래시) 기호를 눌러 화면 맨 밑에 타건 창을 오픈합니다.

### [실무 생존 VIM 마스터 치트시트]

| 행위 목적 | 명령키 (명령/마지막행 모드에서 결행) |
| :-- | :-- |
| **저장하고 탈출하기** | `:wq` (저장 후 종료), `:q!` (저장 안 하고 그냥 강제로 무시하고 종료) |
| **복사와 붙여넣기** | `yy` (한 줄 통째로 복사), `p` (커서 밑에 줄에 붙여넣기, Paste) |
| **잘라내기(삭제)** | `dd` (한 줄 통째로 잘라내어 지워버림), `x` (한 글자 딜리트 백스페이스 삭제) |
| **잘못 지웠어! 되돌리기** | `u` (Undo, 방금 작업 되돌아가기 취소) |
| **단어 검색하기** | `/검색단어` (치고 엔터 치면 커서가 날아감. `n`을 누를 때마다 다음 단어로 점프) |
| **글자 일괄 변환 파서** | `:%s/틀린단어/바꿀단어/g` (그 문서에 있는 모든 틀린 단어를 새 단어로 일괄 Replace 치환) |
