# 저장소의 뼈대: 물리적 파일 시스템(File System) 구조

하드디스크나 SSD 같은 물리적 저장매체에 0과 1로 된 수많은 데이터를 어떠한 규칙과 방식으로 정리하고, 또 빠르게 찾아올지 결정하는 논리적 규격을 **파일 시스템(File System)**이라고 부릅니다. 윈도우의 `NTFS`나 USB의 `FAT` 포맷 형식이 모두 파일 시스템의 일종입니다.

## 1. 리눅스의 4대 주요 파일 시스템 규격

### 1) ext 규격 (ext4)
리눅스 진영을 상징하는 전통적인 표준 파일 시스템(Extended File System)입니다. 
* ext1(한계 큼) ➡️ ext2(상용화) ➡️ ext3(저널링 도입) ➡️ **ext4 (현재 표준)**
* 현재 전 세계 대부분의 우분투/데비안 서버 인프라는 기본적으로 이 ext4로 포맷되어 돌아갑니다. 단일 파일의 극단적인 대용량 처리와 조각 모음 방지에 탁월합니다.

### 2) XFS
실리콘 그래픽스(SGI)에서 개발한 고성능 엔터프라이즈(기업용) 파일 시스템입니다.
* ext4보다 병렬 I/O(입출력) 처리 능력이 훨씬 강력하여 엄청난 크기의 대용량 데이터베이스나 클라우드 스토리지 서버에 주로 채택됩니다. 현재 CentOS 7 및 Rocky Linux 레드햇 계열 서버의 기본 디포트 파일 시스템으로 선정되어 있습니다.

### 3) 윈도우용 파생 (NTFS, FAT)
리눅스 서버에 윈도우용으로 포맷된 외장하드 등을 꽂았을 때 인식하는 규약입니다.
* **NTFS:** 마이크로소프트의 윈도우 표준 하드디스크 포맷입니다. 리눅스에서는 과거 읽기 전용으로만 다루었으나 현재는 읽기/쓰기 모듈(`ntfs-3g`)이 잘 탑재되어 있습니다.
* **FAT32 / exFAT:** 윈도우와 맥(macOS), 스마트폰 간 호환성이 가장 뛰어난 공용 징검다리 포맷입니다. 하지만 최대 파일 크기 제한(FAT32는 단일 4GB 컷)이 있으며, 보안성이 매우 떨어집니다.

## 2. 파일 시스템의 핵심 기능: "저널링(Journaling)"

> 서버에 갑자기 정전이 발생해 컴퓨터 전원이 툭 꺼졌을 때, 저장 중이던 워드 문서나 데이터는 어떻게 될까요? 

저널링(Journaling)이 탑재되지 않았던 옛날 포맷(ext2, FAT32 등)은 전원이 갑자기 나가면 파일의 주소록이 꼬여 하드디스크 전체 파일이 망가지기도 했습니다.

현대의 파일 시스템(ext4, XFS, NTFS 등)에는 **저널링 백업 기술**이 탑재되어 있습니다. 실제 데이터를 디스크에 완전히 옮겨적기 전에, 일종의 임시 일기장(Journal) 영역에 "나 이제 이거 기록할 거다!"라고 미리 변경 내역을 적어둡니다. 중간에 정전이 발생해도 컴퓨터가 켜졌을 때 이 일기장과 실제 저장소를 비교하여 어긋난 부분을 자동으로 복구해 주는 서버 기술의 핵심입니다.

## 3. macOS의 전용 파일 시스템 (APFS)
* 과거 맥북은 `HFS+` (Mac OS 확장) 포맷을 사용했으나, 최근 iOS 기기와 맥북이 플래시 메모리(SSD)를 주력으로 탑재하면서 SSD 낸드 칩의 수명 연장과 광속의 암호화 성능에 100% 최적화된 새로운 전용 무결성 파일 시스템인 **APFS (Apple File System)**로 메인보드 전체의 체질을 개선했습니다.
