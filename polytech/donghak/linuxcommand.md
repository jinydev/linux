# 저장 장치 마운트(Mount)와 파티셔닝

파일 수준의 가공을 넘어, 리눅스 서버에 새 하드디스크 장비를 꽂거나 USB를 연결했을 때 시스템 내부에서 물리적 장비를 논리적 폴더로 인식시키는 장치 수준의 제어 원리를 다룹니다.

## 1. 마운트(Mount)의 완벽한 이해
**마운트(Mount)란, 새롭게 꽂힌 물리적인 디스크(USB 등)라는 생명체를 기존 리눅스 운영체제의 특정 디렉토리 구조(폴더 팔)에 관절처럼 딸깍 연결하여 읽고 쓸 수 있게 만드는 작업입니다.** 

### 윈도우(PnP)와 리눅스 서버의 차이 
*(과거 오개념 정정)* 
우리가 윈도우나 맥에 USB를 꽂으면 내 컴퓨터에 `D:` 드라이브 등이 바로 뜨는 것을 "플러그 앤 플레이(PnP)"라 부르며 편하게 썼습니다. 
과거 보고서에는 "리눅스는 구조적으로 PnP가 되지 않아 관리자가 몽땅 수동으로 해야 한다"라고 적혀있었으나, 이는 절반만 맞는 말입니다. **현대의 리눅스 핵심 커널 안에는 `udev`라는 강력한 장치 인식 데몬이 있어 하드웨어를 꽂자마자 밀리초 단위로 자동 인식**해냅니다. GNOME 등 데스크톱용 리눅스 환경에선 윈도우처럼 자동으로 USB 아이콘이 뜨지만, "오직 텍스트만 뜨는 무거운 실무 서버 환경(CLI)"에서는 외부 직원의 USB를 통한 해킹을 막기 위한 엄격한 **보안** 상의 의도로 이 자동 마운트 접착을 꺼두었을 뿐입니다. 따라서 서버 관리자는 보안 명령인 `mount` 도구를 수동으로 쳐서 장치를 허락해야 합니다.

### 리눅스의 단일 계층 트리 구조
윈도우는 여러 디스크를 `C:`, `D:`, `E:` 처럼 각자의 뿌리로 완전히 분리합니다. 
반면 리눅스는 오직 최상단 루트 `/` 라는 가장 깊은 뿌리 단 하나만 존재합니다. 새 디스크를 꽂으면 `/media/usb` 처럼 그 뿌리 아래에 부하 폴더로 편입시켜버리는 구조를 띱니다.

## 2. fstab (부팅 시 마운트 자동화)
재부팅을 하면 기껏 수동으로 마운트 해두었던 장치들이 모두 튕겨져 나가는(언마운트) 현상이 발생합니다. 이를 막기 위해 **서버가 부팅될 때 자동으로 하드디스크들을 붙여주는 주소록 파일이 바로 `/etc/fstab`** 입니다.

```bash
# fstab 내역 조회
cat /etc/fstab

# UUID=xxxxxxx 형태의 고유 아이디와 매칭될 경로(디렉토리), 그리고 파일시스템 유형(xfs 등)이 나열되어 있습니다. 
```

## 3. 대표적인 마운트 명령어 실습

```bash
# 최고 관리자 권한 획득 필수
sudo su -

# 1. 새 하드디스크/CD를 꽂을 빈 폴더 자리(마운트 포인트)를 생성합니다.
mkdir /mnt/cdrom

# 2. 물리 장비 경로(/dev/cdrom)를 방금 만든 폴더 뼈대(/mnt/cdrom)에 연결합니다.
mount /dev/cdrom /mnt/cdrom

# 3. 사용이 끝난 후 USB를 뽑기 전에 "하드웨어 안전하게 제거"를 수행합니다.
# 주의: 내가 접속해 있는 디렉토리 안에서 umount를 치면 'Target is busy' 에러가 납니다. cd / 로 나가서 치세요.
umount /dev/cdrom
```

## 4. 물리적 공간 쪼개기: 파티션 (fdisk)
물리적인 디스크 공간을 C드라이브, D드라이브용 논리 방으로 쪼개는 작업입니다.

* **`fdisk`**: 전통적인 파티션 분할 도구 (MBR 방식 주로 지원, 2TB 한계 존재)
* **`gdisk` / `parted`**: 현대의 대용량 HDD/SSD 시스템을 위한 최신 GPT 지원 유틸리티

```bash
# 시스템에 장착된 전체 디스크 종류와 파티션 나누기 정보 목록 출력
fdisk -l
```
