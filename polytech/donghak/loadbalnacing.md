# L4 로드밸런싱 (Load Balancing) 아키텍처

아무리 고성능의 램과 최고급 CPU를 장착한 수천만 원짜리 초대형 서버라도, 네이버나 카카오처럼 초당 10만 명의 트래픽이 접근(Request)하면 그 메모리 용량을 견디지 못하고 터져버립니다. 무한히 장착 자원을 늘리는 것(스케일 업)에는 한계가 있기 때문에, 동일한 성능의 여러 대의 서버 묶음으로(스케일 아웃) 부하를 아름답게 분산 배치시켜주는 네트워크 최전선의 지휘자 기술이 방파제처럼 필요한데, 이것이 바로 **로드 밸런싱(Load Balancing)** 입니다.

![로드 밸런서 개념도](https://upload.wikimedia.org/wikipedia/commons/thumb/c/cd/Load_balancing.svg/600px-Load_balancing.svg.png)

## 1. 5대 로드밸런싱 분배 알로리즘 기법
무작정 트래픽을 던지는 것이 아니라, 로드밸런싱 앞단의 거대한 네트워크 분배 스위치는 수학적인 최적화 확률로 계산하여 뒷단의 웹 서버들에게 트래픽 패킷을 토스합니다.

1. **라운드로빈 (Round Robin)**
   * **원리:** 은행 창구에서 번호표를 순서대로 배부하듯, A서버 ➡️ B서버 ➡️ C서버 순서대로 기계적으로 하나씩 공평하게 요청을 배분합니다. 
   * **특징:** 각 서버들의 하드웨어 메모리와 성능이 완전히 100% 동일할 때만 사용하는 것이 가장 안전한 표준 분배 방식입니다.
2. **가중 라운드로빈 (Weighted Round Robin)**
   * **원리:** 이번에 추가 산 C서버가 A나 B서버보다 최신형 CPU라 성능이 좋다면, C에 가중치를 둡니다. (A서버 1개 ➡️ B서버 1개 ➡️ C서버 3개 배분 순서)
   * **특징:** 서버들의 처리 능력이 섞여있는 비대칭 인프라 환경에서 사용합니다.
3. **IP 암호 해시 방식 (IP Hash System)**
   * **원리:** 접속한 클라이언트(스마트폰)의 고유 IP 주소를 수학적인 해시함수로 버무려 무조건 특정 지정된 서버로 고정 매핑시킵니다. 
   * **특징:** 사용자가 장바구니에 물건을 담을 때 엉뚱한 서버로 토스되면 장바구니가 비워지는 "세션 유지의 실패" 현상을 완벽히 방지하여 사용자가 항상 동일 백엔드 서버에 묶이도록 보장합니다.
4. **최소 연결 배분 (Least Connection)**
   * **원리:** 로드밸런서가 백엔드 서버 3대의 "현재 연결된 접속 클라이언트 숫자가 몇 명인지" 실시간 체크하여 가장 사람(세션)이 적고 한가한 서버에게 최우선으로 일감을 몰아줍니다.
   * **특징:** 실시간 게임이나 방송처럼 한 번 접속하면 세션이 길게 가거나 연결의 수명이 불규칙할 때 가장 효과적으로 부하를 분산시킵니다.
5. **최소 응답 시간 (Least Response Time)**
   * **원리:** 최소 연결 세션 수 확인은 기본에 더불어 "서버에게 찔렀을 때 반환되는 탁구 속도(레이턴시 핑)"까지 종합 계산하여 가장 쾌적한 챔피언 서버에게 배분합니다.

## 2. 서버 스케일링(Scaling)의 2가지 아키텍처 전략

* **스케일-업 (Scale-Up):** 수직 확장(Vertical). 트래픽이 많아지면 기존에 사용하던 8GB 메모리를 빼다 버리고, 보드에 64GB 램이나 새 최고급 CPU 칩을 장착하여 **개별 서버 1대의 괴물 헐크 같은 육체적 근력 자체를 향상**시키는 재벌식 방식입니다. 업그레이드 동안 시스템을 꺼야 하며, 물리적 최대 장착 한계치가 뚜렷합니다.
* **스케일-아웃 (Scale-Out):** 수평 확장(Horizontal). 거인 한 명을 키우는 대신, 저렴한 일반병 군대 수십 명을 뽑습니다. 8GB짜리 저렴한 리눅스 서버 **수십 대를 클러스터 병렬로 이어 붙여** 쪽수로 밀어붙이는 것으로, 고장 난 서버는 빼다 버리고 새것을 무중단 증설할 수 있어, 최근 AWS를 비롯한 현대 클라우드 인프라의 핵심 디자인 패턴이 되었습니다. 바로 여기서 필연적으로 로드밸런서가 필수 지휘관으로 등판합니다. 

## 3. 강력한 이점 요약
위대한 무중단 서비스들은 모두 로드밸런서 시스템 뒤에 수천 대의 서버들을 숨겨두고 있습니다.
* **무중단 점검(고가용성):** 새벽에 A서버를 업데이트하기 위해 잠시 코드를 재부팅해도, 로드밸런서가 알아서 A서버로 접속자를 던지지 않고 헬스체크(Health Check) 우회로 B, C서버로만 돌리므로 사용자는 서버 점검을 눈치채지 못합니다.
* **거대 트래픽 해소:** 병목 구간을 일절 해결합니다.
* **DDOS 방어(보안):** 수십만 건의 좀비 악성 트래픽이 몰려와도 방파제 역할의 L4 레이어 차단벽이 앞단에서 폭탄돌리기를 대신 맞아주어 내부 핵심 DB 서버를 사수합니다.
