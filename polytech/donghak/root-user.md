# 리눅스 시스템 권한: root 계정과 일반 유저 

리눅스는 1대의 고성능 컴퓨터에 수십, 수백 명의 개발자가 SSH로 동시 접속하여 작업하는 것을 전제로 탄생한 '다중 사용자(Multi-User)' 운영체제입니다. 따라서 각 타인의 폴더나 주요 시스템 커널 파일을 함부로 삭제하지 못하도록 엄격한 계정 분리가 이루어집니다. 

## 1. 사용자의 신분 서열과 권한 등급
리눅스는 사람의 텍스트 ID (예: `alice`) 가 아니라 주민등록번호 같은 **고유 식별 번호 UID(User ID)** 값을 기준으로 시스템 등급을 매깁니다. 내 계정 정보와 UID 목록은 서버의 `/etc/passwd` 파일에서 확인할 수 있습니다.

### 👑 Root (슈퍼 관리자) 계정
* **UID:** `0`
* 리눅스 세계의 전지전능한 신(God)입니다. 시스템 운영체제의 어떠한 핵심 폴더든 읽고 쓰고 지울 권한이 있으며, 모든 포트를 마음대로 켤 수 있습니다. 
* `UID 0`이라는 숫자가 부여된 순간, 그 계정의 아이디가 무엇이든 무조건 최고 관리자로 시스템은 인식하게 됩니다. 

### ⚙️ 시스템(System) 계정
* **UID:** `1 ~ 999` (과거 구형 리눅스는 499까지였으나, 최신 배포판은 999까지 할당)
* 아파치 웹서버, 메일 데몬, 네트워크 프로세스 등 백그라운드 프로그램들이 자신만의 권한으로 조용히 실행되기 위해 존재하는 '가상의 AI 계정들'입니다. (`daemon`, `apache`, `bin` 등) 직접 비밀번호를 치고 터미널에 로그인할 권한은 박탈되어 있습니다. 

### 👤 일반 사용자 (Normal User) 계정
* **UID:** `1000` 번부터 순차적으로 부여
* 실제 인간 직원들이나 프로그래머들이 부여받는 기본 계정입니다. 본인의 홈 디렉토리(`/home/alice`) 안에서만 폴더를 지우고 만들 자유구역 권한을 가집니다. 다른 유저의 폴더나 `/etc/` 같은 핵심 시스템 영역은 읽기만 가능하고 수정을 위해 접근하는 순간 `Permission Denied` 에러를 맞게 됩니다.

## 2. 계정 권한 확인 명령어 (`id`)

터미널에 접속 후 내 신분을 파악할 때 사용합니다.
```bash
# 내 기본 권한 증명 확인
$ id
uid=1000(donghak) gid=1000(donghak) groups=1000(donghak), 27(sudo)
```

* **UID (User ID):** 내 고유 식별 번호
* **GID (Group ID):** 나를 포함해 여러 사람들을 통제하기 위해 묶어둔 '부서/소속 동아리' 고유 번호입니다. 리눅스에서 계정을 생성하면 무조건 본인 이름과 동일한 1인 동아리(그룹)이 즉시 생성되어 자동으로 귀속됩니다.

## 3. root 계정의 보안 리스크와 `sudo`의 미학
리눅스 서버 인프라 망에서 해커들은 이 UID 0 권한을(Root 셸) 탈취하기 위해 온갖 공격을 가합니다. 
> *"막강한 힘에는 무거운 책임이 따르기 때문에, 평소에는 절대 root로 로그인하지 마십시오."*

* 시스템 핵심 코드를 파괴할 위험을 줄이기 위해, 실무 서버에서는 `root` 계정으로 SSH 접속하는 길을 설정 설정(sshd_config)에서 아예 영구히 차단해놓는 것이 정석입니다.
* 대신에 신뢰받는 일반 유저(`donghak` 등)를 `sudo`(최고 관리자 권한 대행 그룹) 리스트에 올려두고, 평소엔 일반 유저로 활동하다 시스템 설치 같은 위험한 액션이 필요할 때만 명령어 앞에 **`sudo yum install ~`** 처럼 일시적인 슈퍼맨 뱃지를 빌려 사용하는 것이 현대 서버 보안의 가장 절대적인 원칙입니다.
