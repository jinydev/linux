# 두 가지 운송 수단: TCP 와 UDP 프로토콜

OSI 7계층 중 4계층(전송 계층)에서는 두 컴퓨터 프로그램 간에 데이터를 교환하게 돕는 핵심 통신 규약 두 가지를 제공하는데, 이것이 바로 **TCP**와 **UDP**입니다.

## 1. 꼼꼼한 전송 철학: TCP (Transmission Control Protocol)
신뢰성과 도착을 우선순위로 삼는 "등기 우편" 모델입니다. 인터넷 트래픽의 대부분(웹 HTTP, 이메일, 파일 전송 등)이 TCP 기반입니다.

* **연결 지향 (3-Way Handshake):** 데이터를 쏘기 전, 상대방 서버에게 똑똑 노크하며 "연결할게? 준비됐어? 응 준비됐어!" 과정을 거치며 가상 회선 파이프를 확실히 뚫어놓은 뒤에만 데이터를 보냅니다.
* **패킷 추적 구조 (Packet Tracking):** 1GB 영화를 보낼 때 수천 조각(패킷)으로 쪼개서 각 조각에 순번(Sequence Number) 마크를 찍어 분리 발송합니다.
* **재전송 보장 (신뢰성 100%):** 상대가 "나 99번 패킷 못 받았어!" 라고 하면, TCP가 책임지고 그 누락된 99번 조각 하나를 다시 찾아내 재전송해 주어 파일이 1byte 조차도 깨지지 않게 결벽증적으로 완벽히 보장합니다.
* **흐름 제어 / 혼잡 제어:** 수신자의 램 버퍼가 다 차가면 보내는 속도를 섬세하게 늦추어 주고, 광랜 망 자체 병목 트래픽이 터질 것 같으면 스스로 대역폭 데이터 송출량을 줄여 배려합니다.
* **단점:** 이 모든 꼼꼼한 검사 팩트체크 로직 때문에 처리해야 할 용량이 크고, **속도가 느립니다.**

## 2. 속도 지향의 파괴자: UDP (User Datagram Protocol)
신뢰성이고 뭐고 다 집어 던지고, 닥치는 대로 쏘는 "기관총" 모델입니다.

* **비연결형 프로토콜 (Connectionless):** 수신자가 살아있는지 없는지, 준비가 되었는지 노크조차 안 합니다. 파이프를 뚫지 않고 목표물 IP와 포트 구멍을 향해 일방적으로 마구잡이 데이터를 퍼붓습니다 (Datagram 방식).
* **패킷 드랍 발생 (오류 무시):** 중간에 라우터에서 패킷 데이터 쪼가리를 떨어뜨려 분실되어도 "내 알 바 아냐" 하고 쿨하게 무시하며 넘어갑니다. (재전송 절대 없음)
* **장점:** 확인 절차가 전혀 없고 헤더 사이즈가 극도로 작아 **어마어마하게 속도가 빠르고 네트워크 서버 부하가 낮다**는 장점이 있습니다.
* **주요 사용처:** 중간 화면이 좀 깨지더라도 현재 상황을 0.001초라도 빨리 보는 것이 중요한 **유튜브/넷플릭스 실시간 스트리밍 시청, 롤(LoL) 등 리그오브레전드 온라인 게임 좌표 동기화, VoIP(인터넷 전화)** 등에 압도적으로 활용됩니다. (스트리밍 시 파일이 유실되면 옛날 프레임을 복원하는 게 아니라 쿨하게 화면이 픽셀 형태로 뭉개지거나 목소리가 끊기고 곧바로 다음 프레임 데이터를 받습니다.)

## 3. TCP 와 UDP 전격 비교 한눈 요약표

| 비교 기준 | TCP (Transmission Control Protocol) | UDP (User Datagram Protocol) |
|---|---|---|
| **통신 연결 방식** | 사전에 연결을 맺고 시작 (연결형) | 그냥 때려 부음 (비연결형) |
| **순서 보장 여부** | 보낸 패킷 조각 순서대로 수신자가 재조립 (보장) | 보낸 순서 상관없이 잡히는 대로 도착함 |
| **재전송 여부** | 오류 지점이 발견되면 즉시 재전송 조치 | 오류 무시, 복구 기능 없음 |
| **처리 스피드** | 철저하게 절차를 지키느라 상대적으로 느림 | 초고속 통신 |
| **실무 주 사용처** | 신뢰가 절대적인 웹페이지(HTTP), 파일(FTP), 메일 | 속도가 절대적인 실시간 스트리밍, 온라인 통신 게임 |
