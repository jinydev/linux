# 인프라 아키텍처 및 네트워크 환경
## 0417. 분산 컴퓨팅(Distributed Computing) 모델의 이해
<hr/> 

> 현대 애플리케이션의 덩치가 비대해지고 데이터 트래픽이 폭증하면서 한 대의 슈퍼컴퓨터 성능(스케일 업 - Scale UP)만으로는 거대한 데이터를 적절히 감당하기 불가능해졌습니다. 이에 대한 해결 방법론으로서, 여러 대의 평범한 리눅스 장비들을 수평적으로 연계하여 거대한 성능을 끌어내는 분산 컴퓨팅(Scale OUT) 패러다임이 업계의 완벽한 표준으로 잡히게 되었습니다.

## 1. 분산 컴퓨팅의 개념과 장점

분산 컴퓨팅이란 여러 대의 독립된 컴퓨터 인스턴스를 네트워크상으로 거미줄처럼 연결시켜, 사용자(Client)의 관점에서는 마치 **하나의 단일하고 거대한 컴퓨터 시스템**을 이용하는 것처럼 동작하게 만드는 병렬 컴퓨팅 구축 환경입니다.

- **고가용성 확보 (High Availability):** 
  분산 처리되는 어느 특정 컴퓨터 노드(Node)나 장비에 물리적인 하드웨어 장애(고장)가 발생하더라도 서비스 시스템 전체가 정지(Down)되지 않으며, 인접한 건강한 장비가 즉시 작업을 가로채어 계속 업무를 수행합니다. 데이터 소실이 일어나지 않습니다.
- **수평적 성능 확장성 무한대 (Flexibility & Scalability):**
  크리티컬한 연산력이 더 필요하다면 비싸고 좋은 부품으로 갈아 끼울 필요 없이 단순히 똑같은 컴퓨터 장비를 증설(추가)해서 꽂아주기만 하면 선형적으로 모든 성능이 높아집니다.
- **비용 절감 효과:** 고가의 서버 한 대를 구축하는 비용 대신, 저렴한 다수의 서버를 연산 장비 풀(Pool)로 운용하여 높은 가성비를 만들어냅니다.

*대표적인 초기 사례 모델로 여러 네트워크 내 유휴자원 컴퓨팅 파워를 수학적 연산에 집중 동원한 **그리드 컴퓨팅(Grid Computing)** 등을 꼽을 수 있습니다.*

## 2. 리눅스(Linux) 인프라 위에서의 현대 분산 아키텍처

위와 같은 분산 컴퓨팅이 완벽히 동작하게 돕는 하단 OS가 **네트워크 운영체제(Network OS)**에 최적화된 "리눅스"입니다. (과거 "각 서버가 분산 운영체제라는 특수 OS를 설치해야 한다"는 식의 루머는 명백한 환각이며 단지 리눅스 커널 위에서 분산 소프트웨어 미들웨어를 띄우는 것뿐입니다.) 리눅스 네트워크의 핵심 활용처는 크게 세 부류로 나눌 수 있습니다.

### 사례 1. 분산 파일 시스템 스토리지 (Network Storage)
한 장소의 하드 디스크에 데이터를 구겨 넣는 것이 아니라 NFS나 Ceph 류의 프로토콜 매커니즘을 통해 공간을 무한대로 뻗어가며 여러 리눅스 머신에서 동시에 하드 디스크를 네트워크 디스크로 공유 및 수정합니다.

### 사례 2. 분산 데이터베이스
대용량 트래픽 처리를 위해 RDB 위주의 저장성을 극복하고 여러 대의 분산 서버들이 메모리 버퍼를 나누어 트랜잭션을 분산 저장해 속도를 최대치로 끌어올린 NoSQL 모델(Cassandra DB, MongoDB)이나 Redis 인메모리 캐싱 아키텍처 모델입니다. 

### 사례 3. 클라우드 기반 컨테이너 오케스트레이션 탑재
오픈소스 생태계를 점령한 혁신입니다. **Docker(도커)**를 이용해 애플리케이션들을 OS 종속성 없이 경량 패키지로 조각(컨테이너화)낸 뒤, **쿠버네티스(Kubernetes - k8s)**라는 강력한 진휘자를 리눅스 군단 위에 올립니다. 컨테이너가 죽으면 살리고, 트래픽에 맞춰 자동으로 배를 불려주며 완벽한 분산 컴퓨팅 생태계를 구성합니다.
