# 시스템의 나침반: hosts 파일

인터넷 브라우저에 `www.naver.com` 이라는 도메인을 입력할 때, 컴퓨터는 글자를 이해하지 못하므로 반드시 외부로 나가서 "이 글자가 숫자로 된 무슨 IP인지 찾아주세요!" 하고 **DNS(Domain Name System) 114 전화번호부 서버**에 질문을 날려야 합니다.

하지만 외부 DNS 서버까지 물어보러 가기 전에, 컴퓨터가 **가장 최우선으로 자신의 내부 디스크를 뒤져보는 자신만의 로컬 주소록**이 있습니다. 이것이 바로 **`hosts` 파일**입니다.

## 1. hosts 파일의 핵심 역할과 원리
* **인터넷 속도 향상:** 자신이 자주 가는 도메인과 IP를 로컬에 직접 적어두면 외부 DNS에 왕복할 필요가 없습니다.
* **가짜 도메인 테스트:** 개발할 때 등, 내 PC의 IP(127.0.0.1)를 임시로 가상의 라이브 도메인(`test.com`)인 것처럼 속여 개발 환경을 띄웁니다.
* **방어 및 차단:** 도박이나 광고 서버 도메인을 `127.0.0.1` 같이 존재하지 않는 IP로 강제 매핑해놓으면 해당 광고 사이트들의 접속(로드)을 원천 차단 시킬 수 있습니다.

> 🚨 **해킹(Pharming, 파밍)의 타겟:** 
> 바로 이 우선순위 로직 때문에 치명적인 해킹 포인트가 됩니다. 해커가 피해자의 PC에 바이러스를 심어 `hosts` 파일을 몰래 변조하면 끝납니다. 
> 파일에 `12.34.56.78(해커의 위장 해킹 서버) www.naver.com` 이라고 적어버리면, 사용자는 브라우저에 네이버를 치더라도 진짜 네이버 대신 해커가 만들어둔 네이버 로그인 화면으로 강제 납치당해 아이디와 비밀번호를 털리게 됩니다.

## 2. 운영체제별 위치 및 작성법

| OS 구분 | 경로 | 
| :-- | :-- | 
| **Linux / Mac** | `/etc/hosts` |
| **Windows** | `C:\Windows\System32\drivers\etc\hosts` | 

### 올바른 작성 규칙 (Syntax)
파일을 관리자 권한으로 열어서 작성합니다.
1. 줄 앞부분에 `#`을 붙이면 무시(주석 처리)됩니다.
2. 한 줄에 무조건 **[IP 주소]** 한 칸 띄우고 **[호스트/도메인명]** 형태를 지켜야 합니다.
3. `http://`와 같은 프로토콜 식별자나 `/`, `*` 같은 기호는 절대 넣으면 안 됩니다.

**[작성 예시]**
```bash
# 1. 특정 접속 방어 (광고 차단 등)
0.0.0.0      ad.doubleclick.net

# 2. 로컬 개발 환경 
127.0.0.1    dev-mysite.com

# 3. 진짜 도메인 하드코딩
192.168.1.10 intranet.company.local
```
