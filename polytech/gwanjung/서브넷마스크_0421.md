# 서브넷(Subnet) 마스크의 원리

초창기 네트워크 설계자들은 IP 주소 약 43억 개를 배분할 때 클래스(A, B, C)라는 고정된 박스로 나눠주는 실수를 범했습니다.
기관에서 PC를 고작 100대만 지니고 연결하려 하는데, 신청할 게 C클래스(254개 제공)가 다 떨어져 할 수 없이 A클래스 상자를 주면, 나머지 **1677만 개의 황금 같은 IP 주소가 그 상자 안에서 썩어 낭비**되는 문제(IP 고갈 사태)가 벌어졌습니다.

이를 해결하기 위해, 획일화된 클래스의 벽을 부수고 내가 필요한 수량만큼만 주소망을 칼로 잘라 도려내 사용하는 통제 도구를 만들었는데 이것이 바로 **서브넷 마스크(Subnet Mask)** 입니다.

---

## 서브넷 마스크의 구조적 역할
IP 주소는 언제나 통신을 위해 두 가지 영역으로 완전히 이분화(분리)되어야 합니다.
* **Network ID (동네 주소):** 같은 대역에 소속되어 통신하는 전체 무리의 이름
* **Host ID (번지 수):** 그 무리 안에 속해 있는 개별 PC들의 고유 호스트 식별자

서브넷 마스크는 `255.255.255.0` 같이 IP 주소와 완벽하게 똑같이 생긴 32비트 4옥텟의 숫자 배열로 생겼습니다. 이 서브넷 마스크 숫자를 실제 사용자 IP 위에 덧대어(AND 비트 연산) 찍어누르면 마법같이 Network ID가 분리되어 떨어져 나옵니다.

### 원리 (AND 비트 연산 마스킹)

> 기준 IP 주소: `192.168.32.0` 
> 기본 C클래스의 서브넷 마스크: `255.255.255.0`

위의 기본값을 내부 2진수로 쪼개면 아래와 같은 원리입니다.
서브넷 마스크는 `1`이 끝없이 연속적으로 이어지다가 어느 순간부터 `0`의 연속으로 변합니다.

* `1`로 채워진 구간: "이곳까지가 고정된(손댈 수 없는) 네트워크(동네) 구간이야!"
* `0`으로 채워진 구간: "여기 0에 해당되는 비트 자리만큼은, 너희들이 마음대로 PC(Host)한테 분배해서 번호표를 줘도 좋아!"

```text
  IP주소: 11000000.10101000.00100000.00000000  (192.168.32.0)
서브넷마스크: 11111111.11111111.11111111.00000000  (255.255.255.0)
--------------------------------------------------------------
 AND 연산 = 11000000.10101000.00100000.00000000  (192.168.32.0) --> 이 대역의 Network ID를 산출해 냄.
```

### Prefix 단축 표기법 (CIDR 기호)
실무에서는 `255.255.255.0` 이라고 길게 쓰기가 너무 힘들기 때문에, 위 2진수 덩어리에서 단단하게 칠해져 있는 `1`의 개수를 세어 슬래시 뒤에 압축해서 붙여버립니다. 
이를 **CIDR (Classless Inter-Domain Routing)** 프리픽스 표기법이라고 부릅니다. 

* 예시: `192.168.32.0/24`
* 의미: "아이피 대역망을 쓰는데, 왼쪽부터 연달아 칠해진 서브넷 마스크의 `1`의 갯수가 **24개**인(즉 3개의 옥텟 `255.255.255`가 가려진) 서브넷 망을 쓰고 있습니다"라는 완벽한 실무 표기법입니다.
