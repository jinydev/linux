# 쉘(Shell)의 계층 구분: 로그인/비로그인/서브

리눅스의 사용자와 리눅스 심장(커널) 사이를 통역해 주는 터미널 환경인 쉘(Shell)은 구동 방식에 따라 환경 변수와 초기화 세팅이 크게 3가지로 나뉘어 동작합니다.

## 1. 로그인 쉘 (Login Shell)
인증(아이디/패스워드) 절차를 거쳐 사용자가 가장 처음 접속했을 때 수행되는 근본 쉘입니다. 사용자의 리눅스 홈 위치에 들어가면 등록되어 있는 전역 설정과 `.bash_profile`, `.bashrc` 같은 환경 변수 초기화 스크립트들을 싹 다 한 번씩 읽으면서 터미널 세팅을 온전하게 로드합니다.
터미널 입력기를 종료할 때 `exit`뿐 아니라 `logout` 명령어로 시스템 계정 자원 자체를 안전히 종료할 수 있습니다. 

* 텍스트 모드 기반 (SSH 접속 등)
* `su -` 또는 `su -l [usename]` 명령어로 다른 계정에 넘어갈 때, 상대방 계정의 완전히 새로운 환경 변수 값들까지 초기화해 탑재하는 방식입니다. (실무에서 가장 많이, 그리고 무조건 쓰는 옵션입니다)

```bash
# user1 환경에서 로그인을 수반한 user2 전환
[user1@localhost ~]$ su -l user2
Password:
[user2@localhost ~]$ whoami
user2
[user2@localhost ~]$ logout
[user1@localhost ~]$ 
```

---

## 2. 비로그인 쉘 (Non-login Shell)
초기 로그인 과정을 생략하고 파생되어 열리는 쉘입니다. 로그인할 때만 로드되는 무거운 `.bash_profile` 초기화 스크립트 등은 읽지 않고 `.bashrc` 정도만 최소한으로 읽습니다. 
인증 단계를 거친 게 아니므로 쉘을 끝낼 때 `logout`명령은 에러가 나며 먹히지 않고 `exit`로 빠져나갑니다.

* 바탕 화면이 있는 그래픽(GUI) 환경의 리눅스에서 마우스 클릭으로 수시로 터미널 새 창을 띄울 때.
* `su [username]` 처럼 `-l` 이나 단일 `-` 하이픈 옵션 없이 계정만 덜렁 넘어갔을 때. (사용자 이름만 user2로 바뀌었지 시스템 변수나 폴더는 아직 기존 user1 것에 렌탈하여 머물고 있는 기형적 상태가 됩니다.)

```bash
[user1@localhost ~]$ su user2
Password:
[user2@localhost ~]$ whoami
user2

# 로그인 구동 개념이 아니기 때문에 logout 커맨드가 터집니다.
[user2@localhost ~]$ logout
bash: logout: not login shell: use 'exit'

[user2@localhost ~]$ exit
[user1@localhost ~]$ 
```

## 3. 서브 쉘 (Sub Shell)
현재 띄워져 있는 투명한 부모 쉘 껍데기 환경(프로세스) 안에서 한 번 더 자식으로 파생되어 실행되는 작은 쉘 프로세스입니다. 

* 터미널 창 안에 내가 무심코 1회성 명령어 모음인 `test.sh` 쉘 스크립트 파일을 실행시킬 때, 현재 내 환경 통째로 돌리는 게 아니라 서브 자식 쉘을 아주 작게 복사해서 파생시킨 뒤 그 안에서 내부 코드가 돌고 끝나면 닫게 만듭니다. (부모 환경 오염 방지)
* 부모 쉘의 시스템 변수 등을 상속받아 복사해갈 수는 있지만, 자식 쉘 내부에서 지지고 볶고 변수를 아무리 고쳐도 끝나면 파괴될 뿐 원본 부모 쉘에는 역으로 영향을 미치지 않습니다.
* 터미널에 `bash` 또는 `sh` 라고 쳐도 내가 있는 껍질 안에 또 다른 서브 자식 쉘이 실행되어 겹칩니다. `exit`를 누르면 자식 쉘이 닫히며 원래 부모 단계로 올라옵니다.
