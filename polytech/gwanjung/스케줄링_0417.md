# CPU 스케줄링 (Scheduling)의 역학

컴퓨터의 핵심인 프로세서(CPU)는 하나 또는 소수에 불과하지만, 우리가 띄우는 프로세스(프로그램)는 수백 개에 달합니다. 
운영체제가 어떤 프로세스에게 CPU 자원을 얼마나 오랫동안 빌려줄지 결정하고 지휘하는 정책을 **CPU 스케줄링(Scheduling)**이라고 합니다. 이 지휘봉의 효율성에 따라 컴퓨터의 렉과 속도가 좌우됩니다.

---

## 1. 스케줄링이 필요한 이유 (프로세스 상태)

CPU가 프로세스를 처리하던 도중, 디스크에 있는 대용량 파일을 읽어오라는 I/O (입출력) 명령이 떨어지면 CPU는 하드디스크가 일할 때까지 하릴없이 놀게 됩니다. 이걸 **'대기 상태(Waiting)'**라고 합니다.

"CPU가 쉬게 놔둘 수 없다!" 운영체제는 이때 즉시 현재 프로세스를 대기 리스트로 밀어내고, CPU를 차지할 준비가 끝난(Ready queue) 다른 프로세스를 불러들여 공백 없이 연산을 돌리는 교차 스케줄링을 단행합니다. 이것이 현대 멀티태스킹의 핵심입니다.

## 2. 스케줄링 성능 평가 척도

CPU 스케줄러가 얼마나 일을 잘하고 있는지 평가하는 양대 지표입니다. 

### ⚙️ 시스템(운영체제) 입장의 척도
기계를 극한으로 혹사시키는 것이 목표입니다.
* **CPU 이용률 (CPU Utilization):** 전체 시간 중 CPU가 놀지 않고 불태워 일한 시간의 비율. (목표: 100%에 근접)
* **처리량 (Throughput):** 1초, 1시간 등 단위 제한 시간 동안 완료한 프로세스 건수. (결과물의 양)

### 🧑‍💻 프로그램(사용자) 입장의 척도
내가 클릭했을 때 지체 없이 얼마나 빨리 반응해 주는지가 목표입니다.
* **소요 시간 (Turnaround Time):** 프로세스가 대기열 큐(Queue)에 들어선 순간부터, 모든 작업을 완료하고 종료될 때까지 걸린 통계적인 총 시간.
* **대기 시간 (Waiting Time):** 프로세스가 CPU를 받기 위해 줄을 서서 멍하니 기다린 시간의 총합.
* **응답 시간 (Response Time):** (매우 중요) 사용자가 버튼을 클릭한 후, **"최초로"** 프로그램 화면에 반응(CPU 할당)이 나타나기까지 걸린 시간.

> **💡 이상적인 스케줄링 목표:** 
> CPU 이용률과 처리량은 **극대화(Max)**하고, 반환 시간과 대기/응답 시간은 **최소화(Min)**하며, 모든 프로세스가 굶어 죽지 않고 공정하게 자원을 배분받는 균형(Fairness)을 잡는 것입니다.
