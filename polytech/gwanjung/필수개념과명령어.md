# 서버 구축을 위한 필수 운영 개념과 패키지 관리

리눅스를 다루기 위한 거시적인 기본 개념과 패키키 관리 시스템, 그리고 네트워크 지식의 핵심을 요약합니다.

## 1. 런레벨 (Runlevel)과 `init`/`target`
리눅스는 부팅 시 목적에 따라 켜지는 "모드(Mode)"가 0번부터 6번까지 총 7개의 런레벨로 나뉩니다.
* **0번 (Poweroff):** 시스템 즉시 종료
* **3번 (Multi-User, CLI):** 마우스가 없는 검은 터미널 화면 체제로 부팅. (실무 서버의 기본값, 시스템 자원 최소화)
* **5번 (Graphical GUI):** X 윈도우 그래픽 데스크톱 화면까지 띄우는 무거운 부팅. (개발용)
* **6번 (Reboot):** 즉시 시스템 재부팅

과거에는 `init 3` 으로 불렀으나, 현대 `systemd` 체제에서는 이것이 `.target` 파일 매핑(예: `multi-user.target`)으로 진화했습니다. 확인은 `/usr/lib/systemd/system/` 등에서 조회합니다.

## 2. 사용자 관리 계정 분리
리눅스의 절대권력자 아이디는 **`root` (슈퍼 유저)**입니다. 시스템을 파괴할 수도 있으므로 평소엔 쓰지 않고, 일반 권한 사용자를 만들어 관리하는 것이 보안의 기본입니다.

* `adduser 사용자명` : 새로운 사용자의 공간과 계정 생성. (`/etc/passwd`, `/etc/shadow` 등에 기록됨)
* `userdel 사용자명`, `usermod` : 삭제 및 권한 수정
* `passwd 사용자명` : 빙글빙글 화면에 안 보이는 형태의 비밀번호 지정 
* `groupadd 그룹명` : 권한을 편하게 일괄로 묶어줄 부서(그룹) 생성

## 3. 리눅스의 진화: 패키지 관리자 (`dpkg` vs `apt`)

스마트폰에 앱스토어가 있듯, 리눅스(데비안/우분투 계열)에는 수만 개의 오픈소스 프로그램 저장소를 땡겨오는 **의존성 기반 패키지 툴**이 내장되어 발전해 왔습니다.

### 1) 구시대의 도구: `dpkg` 
* 다운로드 받은 `.deb` 설치 파일을 하드디스크에서 강제로 풀어서 오프라인 설치하는 툴입니다.
* **치명적 단점 (의존성 지옥):** 파이어폭스 컴포넌트를 설치 명령을 날려도, 파이어폭스가 필요로 하는 X 윈도우 폰트 파일이 없으면 설치가 마비되는 "의존성 지옥" 문제가 발생합니다.
* 사용법: `dpkg -i 패키지.deb` (설치), `dpkg -l` (리스트업), `dpkg -r 패키지명` (가볍게 삭제), `-p` (설정파일까지 영혼 삭제) 

### 2) 클라우드 시대의 해결사: `apt-get` / `apt`
* 의존성 지옥의 구원자. 내가 인터넷에 연결된 채로 파이어폭스 이름을 부르면, 툴바, 폰트, 자바 등 필요한 모든 하위 `.deb` 파일 수십 개를 백그라운드에서 추적해 동시 다운로드 후 연달아 자동 조립해 줍니다.
* **사용법 요약**
```bash
# 1. 낡은 패키지 주소록(저장소 목록) 최신화. (뭔가 설치 전 무조건 1순위 타격)
sudo apt update

# 2. 패키지 및 부하 의존성 부품 일괄 자동 설치 (-y는 Yes 생략)
sudo apt install -y 패키지이름

# 3. 설치 전 패키지 검색이나 정보/의존성 구조만 살짝 보기
apt-cache search 검색어
apt-cache depends 패키지이름

# 4. 휴지통으로 제거
sudo apt remove 패키지이름
```

## 4. 네트워크 필수 통신 기본
* **TCP/IP:** 가장 신뢰성 있는 연결 상태 지향(TCP)과 IP 주소 기반의 통신 인터넷 필수 규약 덩어리입니다. 
* **게이트웨이 (Gateway):** 내 컴퓨터가 가상머신 등의 좁은 우물망(내부망)을 탈출해 거대한 구글 같은 인터넷 바다로 나아가기 위해, 반드시 지나가야 하는 첫 번째 외부(공유기 등) "출구 IP 전초기지"입니다.
* **DNS (Domain Name Server):** `www.naver.com` 글자를 치면 내부적으로 `223.130.200.x` 숫자 IP로 변환해 찾아주는 전화번호부. `/etc/resolv.conf` 에 세팅됩니다.
* **테스트 기본 무기:** `ping 대상IP` (상대방 컴퓨터의 네트워크가 살아서 응답하는지 찔러보는 탁구공 사격)
