# Bash 쉘의 심장: 확장(Expansion)과 인용(Quoting)

커맨드라인 프롬프트(`$`)에 타이핑을 완료하고 **Enter(엔터)** 키를 누르는 순간, 리눅스의 `bash` 쉘은 이 텍스트 명령어를 곧이곧대로 운영체제 입에 넣어주지 않습니다. 뒤에서 텍스트를 파열시키고 치환하는 **"확장(Expansion)"**이라는 마법 처리를 먼저 수행합니다.

## 1. 쉘의 자동 확장 기법들

### 1) 경로명 와일드카드 확장 (`*`)
`*` 기호는 "그곳에 있는 어떤 문자가 와도 허용한다"는 뜻입니다. 
치안 쉘이 엔터를 감지하면 `*`를 파일명으로 자동 인식하여 치환합니다.
```bash
# 내가 입력한 것
$ echo D*

# 쉘이 엔터 후 D로 시작하는 Desktop, Documents 단어로 치환해서 echo에 던진 결과
Desktop Documents
```

### 2) 틸드(`~`) 디렉터리 확장
`~` 모양 물결표는 현재 사용자의 "Home 디렉터리 경로" 전체 텍스트로 폭파되어 치환됩니다.
```bash
$ echo ~
/home/me

$ echo ~root    # root 계정의 홈 디렉터리로 치환
/root
```

### 3) 산술 확장 (`$(( ))`)
계산기 프로그램을 띄우지 않아도 쉘 내부에서 이중 괄호 `$((표현식))`를 치면, 문자가 사칙연산의 답안 텍스트로 자동 치환됩니다.
```bash
$ echo $((2 * 10 + 5))
25
```

### 4) 중괄호 확장 (Brace, `{ }`)
가장 강력하고 반복적인 텍스트 노가재를 없애주는 쉘 스크립트의 꽃입니다. 프리앰블(앞글자)과 포스트스크립트(뒷글자)를 기준 삼아 내부 컴마 덩어리를 복사 복제합니다.
```bash
$ echo Front-{A,B,C}-Back
Front-A-Back Front-B-Back Front-C-Back

# 파일 수백 개 만들기
$ touch log_{2015..2020}.txt
log_2015.txt log_2016.txt ... log_2020.txt
```

### 5) 매개변수(통칭 변수) 확장 (`$`)
쉘이나 OS가 미리 담아놓은 거대한 메모리 값(변수)을 달러 기호 `$변수명`으로 찔러버리면 값이 터져 나옵니다.
```bash
$ echo $USER
me (현재 접속한 사용자 아이디로 확장됨)
```

## 2. 확장의 통제: 인용 (Quoting)

쉘의 이런 오지랖(자동 확장 기능) 때문에, 가끔 띄어쓰기가 들어간 파일 이름 등을 건드릴 때 시스템이 문자를 가위질(단어 분할)해서 명령어가 망가지는 사태가 터집니다. 
이 쉘의 오지랖을 정지시키고 **"이 구역은 온전한 하나의 글자 문장이야!"** 라고 바리케이드를 치는 것이 **인용(Quoting 따옴표)**입니다.

```bash
# 띄어쓰기가 들어간 two words.txt 라는 단일 파일을 실행해보자.
$ ls -l two words.txt
ls: cannot access two: No such file or directory
ls: cannot access words.txt: No such file or directory
```
-> 띄어쓰기 때문에 `ls` 명령어가 `two` 와 `words.txt` 2개의 다른 파일로 오해하고 찢어서 찾아버렸습니다!

```bash
# 쌍따옴표 바리케이드 적용
$ ls -l "two words.txt"
-rw-rw-r-- 1 me me 18 Feb 20 13:03 two words.txt
```
-> **쌍따옴표(`" "`)**나 **홑따옴표(`' '`)** 기호로 텍스트를 감싸버리면, 쉘이 공백을 찢어버리지 않고 투명한 한 덩어리의 포장지 텍스트로 안전하게 명령어의 인자로 넘깁니다.
