# 리다이렉션 (Redirection)과 파이프 (Pipe)

리눅스(Bash) 환경에서는 터미널에 명령어를 치면 모니터로 결과가 나오는 것이 당연해 보이지만, 이 '결과가 나가는 방향'을 파일로 돌리거나 다른 프로그램으로 넘겨줄 수 있습니다. 이를 가리켜 **리다이렉션(Redirection)**과 **파이프(Pipe)**라고 부릅니다.

## 1. 리눅스의 3가지 표준 스트림 (Stream)

모든 프로그램은 기본적으로 3개의 데이터 통로를 가지고 태어납니다.

* `0 (stdin)`: **표준 입력**. 키보드나 마우스로부터 들어오는 데이터.
* `1 (stdout)`: **표준 출력**. 명령어가 성공적으로 실행되어 화면(모니터)에 정상적으로 뿌려주는 텍스트 결과.
* `2 (stderr)`: **표준 에러**. "파일을 찾을 수 없습니다", "권한이 없습니다" 등의 오류 메시지.

## 2. 입출력 리다이렉션 기호 (`>`, `<`)

명령어의 결과 화면(stdout)을 모니터 대신 **'텍스트 파일'**로 꽂아 넣습니다.

| 기호 | 방향 | 의미 | 예시 커맨드 |
| :--: | :--: | :-- | :-- |
| `>` | 표준 출력 (덮어쓰기) | 저장. 파일이 없으면 만들고, 파일이 이미 있으면 내용을 모두 폭파하고 새로 덮어씁니다. | `ls -l > result.txt` |
| `>>` | 표준 출력 (이어쓰기) | 추가. 기존 파일 내용 뒤에 새로운 결과를 이어서 안전하게 덧붙입니다. | `echo "Hello" >> log.txt` |
| `<` | 표준 입력 | 파일 안의 내용을 명령어의 입력 소스로 밀어 넣습니다. | `sort < list.txt` |

### (고급) 에러 메시지만 따로 빼내기 (`2>`)
관리자 권한이 부족해 화면에 `Permission denied` 에러가 수백 줄 출력될 때, 이 꼴 보기 싫은 에러 창만 휴지통이나 별도의 로그 파일로 치워버리는 기법입니다.
```bash
# 정상 결과는 모니터로 나오지만, 에러 메시지 덩어리는 error.log로 숨어버립니다.
find / -name "secret.txt" 2> error.log

# 정상 결과, 에러 결과 가릴 것 없이 모조리 통합해서 다 집어넣습니다. (Bash 전용)
명령어 &> all-logs.txt
```

## 3. 파이프 (`|`)
리다이렉션(`>`)이 결과를 '파일'로 넘기는 것이라면, **파이프(`|`)는 결과를 '다음 명령어'표준 입력으로 곧장 토스하는 마법의 파이프**입니다.

> 명령어 A의 결과가 모니터에 뜨기 전에 파이프에 빨려 들어가서 명령어 B의 재료로 쓰입니다.

```bash
# 전체 시스템 서비스 목록 수천 줄 중에서, "ssh" 문자가 들어간 줄만 필터링해 줘!
systemctl list-units | grep "ssh"
```
