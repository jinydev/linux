# 보안의 최전선: 방화벽 (Firewall)

**방화벽(Firewall)**은 성문을 지키는 경비병입니다. "이 문은 열어주고, 이 IP 주소에서 오는 택배는 수상하니 폐기해라" 같은 '보안 규칙(Rule)'을 기반으로 내부 네트워크와 외부의 위험한 인터넷 트래픽 사이를 통제합니다.

## 1. 방화벽의 분류 (장비/환경)

* **하드웨어 방화벽:** 데이터 센터 초입에 공유기처럼 거대한 무쇠 박스 형태로 설치되어, 수십만 개의 데이터 패킷을 실시간으로 썰어버리는 장비입니다.
* **소프트웨어 방화벽:** 각 컴퓨터 OS 내부(윈도우 방화벽, 리눅스의 `iptables`)에 프로그램 형태로 설치되어 해당 PC 단말만 보호합니다.
* **클라우드 기반 (WAF, 프록시 등):** AWS나 Azure 등에서 클라우드 로드밸런서 앞에 논리적으로 거대한 장벽 네트워크를 쳐서 디도스(DDoS) 등을 선제 차단합니다.

## 2. 방화벽 기술의 발전 (필터링 수준)

1. **단순 패킷 필터링 (초창기):** 택배 상자에 적힌 보내는 사람(소스 IP)과 받는 곳(목적지 포트)이라는 겉면 송장만 보고 차단하는 구식입니다. 알맹이에 다이너마이트가 들어있는지 검사할 권한은 없습니다.
2. **상태 기반 추적 방화벽 (Stateful Inspection):** 오늘날 대부분의 표준 방화벽. 내부 PC가 먼저 요청한 "네이버 응답" 등 합법적으로 연결된 연결(세션)의 상태 꼬리표를 추적해 불법 난입자만 걸러냅니다.
3. **어플리케이션 게이트웨이 / WAF:** 단순 IP 통제를 넘어, 데이터 패킷 알맹이를 모조리 뜯어(DPI) "이건 정상적인 글쓰기가 아니라 SQL 인젝션 공격이다"라고 파악해 파쇄해버리는 고지능 방화벽입니다.

## 3. 리눅스의 현대 방화벽: `firewalld`

과거 리눅스의 `iptables`는 관리자가 직접 복잡한 규칙 룰셋을 입력하고, 변경할 때마다 방화벽 데몬을 껐다 켜야 했기 때문에 짧은 인터넷 단절이 발생했습니다.
**CentOS 7 및 최신 리눅스 진영**은 인터넷을 끊지 않고도 방화벽 룰을 즉각 삽입하는 **동적(Dynamic) 구조의 `firewalld`**를 표준으로 사용합니다. 

### 핵심 개념: 존(Zone) 시스템
`firewalld`는 서버의 위치에 따라 방어막 수준을 달리하는 **존(Zone)** 개념을 씁니다.
* `public`: (기본값) 공개 구역. 매우 엄격하며 내가 허락한 서비스(포트) 외에는 얄짤없이 쳐냅니다.
* `trusted`: 믿을 수 있는 구역. 사무실 내부망 대역은 무사통과시킵니다.
* `drop`: (블랙홀) 들어오는 모든 접속을 응답조차 안 하고 그대로 쓰레기통에 폐기하는 방어막.

### `firewalld` 주요 명령어 치트시트

```bash
# 1. 방화벽 작동 상태 확인
sudo firewall-cmd --state

# 2. 현재 내 서버에 기본 적용된 구역(Zone) 확인
sudo firewall-cmd --get-default-zone

# 3. Public 구역에 거대한 구멍 열어주기 (웹 80 포트 오픈)
# 주의: --permanent (영구적) 옵션을 안 주면 서버 재부팅 시 구멍이 닫힙니다.
sudo firewall-cmd --permanent --zone=public --add-service=http

# 4. 방화벽 수정 후 즉시 '기절 없는' 재장전 적용
sudo firewall-cmd --reload

# 5. 현재 열려있는 포트와 허용 서비스 목록 전체 점검
sudo firewall-cmd --list-all
```
