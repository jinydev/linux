# 리눅스 프로세스 (Process)와 백그라운드 제어

단순히 하드디스크 창고에 얌전히 저장되어 잠자고 있는 멈춘 코드를 `프로그램(Program)`이라 부른다면, 이를 마우스로 더블 클릭해 메모리(RAM) 위로 끌어올려서 **살아 숨 쉬며 능동적으로 동작하는 녀석**을 가리켜 **`프로세스(Process)`**라고 부릅니다. 

마우스 기반(GUI)인 윈도우와 다르게, 명령어 기반의 리눅스(CLI) 환경에서는 이 프로세스들을 터미널의 전면부(Fore)와 후면부(Back)를 활용해 자유자재로 유체 이탈시키며 통제하는 묘기를 펼칠 수 있습니다. 

---

## 1. 포그라운드(Foreground)와 백그라운드(Background)

### 포그라운드 프로세스
우리가 리눅스 창에 `ls` 혹은 `find /` 등 명령어를 치면 즉시 화면을 꽉 채우며 결과를 보여주는 흔한 방식입니다. 
* 명령을 수행하는 동안 터미널 프롬프트(`$`)가 사라지며, 저 파일 검색이 백만 년 걸리더라도 완료될 때까지 관리자는 키보드를 손에서 놓고 가만히 멍때려야 합니다. (혹은 강제로 취소 `Ctrl + C` 해야 합니다.)

### 백그라운드 프로세스 (끝에 `&`)
"명령어는 돌아가게 놔두고, 나는 내 키보드 프롬프트를 빼서 다른 일을 하겠다!"라는 개념입니다.
주로 수 시간 걸리는 무거운 서버 압축이나 데몬 서비스 기동에 필수입니다.

```bash
# 압축 프로그램 뒤에 한 칸 띄우고 '&'를 붙이면 화면 뒤쪽 창고로 작업이 넘어갑니다.
tar -czvf backup.tar.gz /var/log/ & 

# 결과 출력(예: [1] 10234)
# -> "1번 작업으로 넘어갔으며 프로세스 번호(PID)는 10234이다! 터미널 프롬프트를 다시 넘겨주마!"
```

## 2. 작업 제어(Job Control) 및 프로세스 스케줄링

백업이 화면 뒤로 밀려나면(백그라운드), 뒤에 잘 돌아가고 있는지 혹은 멈췄는지를 다음과 같은 명령으로 추적합니다.
- `jobs` : 현재 터미널 뒤에서 돌아가는 프로세스 번호 조회
- `fg %1` : 백그라운드로 밀어둔 1번 작업을 다시 포그라운드(메인 화면)로 끌고 옵니다.
- `bg %1` : 잠시 멈춘 작업을 뒤에서 다시 이어 달리게 시킵니다.

> 💡 **참고 (프로세스 스케줄러 기능)**
> 시스템에 무거운 프로세스가 10개나 밀려 있어 버벅거릴 때, 운영체제 CPU 스케줄러(Scheduler)는 긴급한 프로세스부터 처리하도록 조율을 시도합니다. 우분투 환경의 관리자라면 `nice -n -20 프로세스` 등 악덕 명령어를 강제 주입하여, 다른 일감을 무시하고 특정 압축 프로세스에게만 최고 우선순위 CPU 지시를 내릴 수 있는 권한을 얻습니다.

## 3. 부팅 시 자동 시작 시스템 (초기화 스크립트)

사용자가 일일이 키보드로 프로세스를 백그라운드에 밀어 넣지 않더라도 웹서버, DB 데몬 등은 시스템 전원이 오르자마자 알아서 뒤에 켜져야 합니다. (Startup Program) 

이러한 부팅 제어 권한은 리눅스의 역사적 판도에 따라 다음 폴더에 위치합니다. 
* **(현재 표준) `/etc/systemd/system/`** : 최신 계열의 리눅스(CentOS 7+, Ubuntu 16+)에서 모든 데몬의 수장인 `systemd`가 읽어 들이는 최적의 병렬 `.service` 선언 구역입니다.
* **(구시대의 유물) `/etc/init.d/`, `/etc/rc.local`** : 과거 System V 초기화 방식 시절 구형 셀 스크립트들이 나열식으로 실행되던 끈적한 구역입니다. 하위 호환을 위해 남아는 있지만 현대 인프라에서는 사용을 폐기해 가고 있습니다.
