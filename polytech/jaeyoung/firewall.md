# 리눅스 방화벽(Firewall)과 내부 네트워크 설계

회사 내부의 데이터베이스와 직원 컴퓨터들을 외부 인터넷 해커들의 위협으로부터 차단하면서도, 직원들은 평화롭게 외부 인터넷을 돌아다닐 수 있도록 만드는 핵심 장치가 바로 **방화벽(Firewall 컴퓨터)**과 **사설망** 개념입니다. 

방화벽은 주로 2개의 랜 카드 장착을 의무화하여, 하나는 외부 인터넷망(공인 IP)을, 또 하나는 우리 직원 내부망(사설 IP)을 바라보게 한 뒤 그 사이를 검문통제하는 출입국관리소 역할을 합니다.

---

## 1. NAT (Network Address Translation) 와 마스커레이딩
모든 직원의 컴퓨터에 공인 IP를 달아주면 해킹의 무방비 타겟이 됩니다. 그래서 내부망 스위치 허브에는 `192.168.x.x` 식의 **사설(가짜) IP**를 뿌립니다.

* **마스커레이딩(Masquerading) 동작 원리:** 
  내부 컴퓨터가 "네이버 띄워줘!"라고 방화벽에게 패킷을 던집니다. 방화벽은 인터넷망으로 패킷을 내보낼 때, 원래 출발지인 사설 IP를 숨겨버리고 당당히 자신의 진짜 **공인 IP**로 위장(가면)시켜서 네이버에 보냅니다. 네이버는 방화벽 장비가 접속한 줄로만 압니다. 이게 곧 공유기의 핵심 역할이며, IP 주소 부족 문제도 완전히 해결해 줍니다. 

## 2. SNAT vs DNAT 개념 (패킷 변조 방향)

사설망 뒤에 웹 서버나 FTP 서버를 구축해 외부에 장사(서비스)를 해야 할 때 트래픽 룰 튜닝법입니다. 리눅스에서는 iptables 설정으로 이를 제어합니다.

### 1) SNAT (Source NAT - 포워딩 전)
패킷의 **출발지 주소(Source)**를 변조하는 기술입니다.
* 외부 인터넷으로 패킷이 나가기 제일 마지막 직전(POSTROUTING)에, 내부 컴퓨터의 사설 아이피를 공용 인터넷 주소로 탈바꿈 시킵니다. 마스커레이딩이 주로 이 범주에 속하되, NAT 테이블이 공인 IP를 '고정적'으로 다룰 때 정교하게 SNAT 지시를 내립니다.

### 2) DNAT (Destination NAT - 포트 포워딩)
패킷의 **도착지 주소(Destination)**를 변조하는 해킹 방어용 서빙 기술입니다.
* 네이버 고객이 우리 집 방화벽의 공인 IP 80번 웹 포트로 접속을 시도했습니다. 하지만 진짜 `index.html` 파일을 서빙하는 리눅스 서버 컴퓨터는 내부망 깊숙한 곳(사설 IP `192.168.0.22`)에 숨어있습니다.
* 방화벽은 들어오는 패킷(PREROUTING)을 뜯어서, 타겟 목적지를 자신의 아이피에서 **내부 사설망 IP 주소로 위조 납치시켜** 패킷을 토스해 줍니다. 흔히 공유기에서 설정하는 '포트 포워딩'이 바로 전형적인 DNAT입니다.

## 3. 방화벽의 진짜 생명은 '보안 정책(Policy)'
수천만 원짜리 장비나, 우분투의 무료 `ufw`, `firewalld` 소프트웨어나 그 자체로는 그냥 깡통입니다. 
관리자가 "들어오는 패킷은 일단 모조리 태워버려라(DROP). 예외적으로 내 IP의 22번(SSH) 포트 노크만 허용(ACCEPT)한다. 나가는 트래픽도 차단한다" 는 식의 **화이트리스트(Whitelist)** 룰과 세밀한 보안 정책을 어떻게 그물망처럼 수립하느냐가 시스템 생존을 좌우합니다.
