# 가상머신 하드디스크 연결 컨트롤러: SATA vs SCSI

서버 환경이나 가상머신(VMWare, VirtualBox)에서 리눅스 인스턴스에 새로운 하드디스크 블록을 달아줄 때, 가상 메인보드와 하드디스크를 어떤 스위치 케이블로 연결할지(인터페이스) 정해야 합니다. 절대적인 양대 산맥인 **SATA**와 **SCSI**의 차이점과 실전 선택 기준을 다룹니다.

---

## 1. SATA (Serial Advanced Technology Attachment)
일반인들이 데스크톱 조립 PC를 맞출 때 SSD나 하드디스크를 꽂는 가장 친숙한 케이블 규격입니다.
* **구조적 장점:** 인터페이스가 직관적이고 매우 저렴하며 호환성이 좋습니다. 별도의 비싼 전용 컨트롤러 카드나 복잡한 설정 없이도 거의 모든 OS 커널에 드라이버가 내장되어 있어 가상머신에서도 즉시 인식됩니다.
* **실무 포지션:** 용량이나 I/O 요청 횟수가 무식하게 크레딧이 요구되지 않는 일반 파일 서버 백업용이나 영세한 규모의 가상머신을 띄울 때 가장 무난하게 채택됩니다.

## 2. SCSI (Small Computer System Interface / 스카시)
개인 PC용이 아니라 오직 고성능 코어 엔터프라이즈 **서버 머신과 데이터 센터를 겨냥해 설계된 병렬 직렬 초고속 규격**입니다.
* **구조적 장점:** CPU의 사이클 명령(인터럽트)을 통하지 않고 스스로 무식한 양의 데이터 블록(I/O per second, IOPS)을 고속으로 퍼다 나르는 독립적 지능형 컨트롤러가 내장되어 있습니다. 디스크를 열댓 개씩 주렁주렁 매달 수 있는 무한한 확장성을 자랑합니다.
* **실무 포지션:** 대규모 유저가 동시에 접속해 쓰기와 읽기(트랜잭션)를 난사하는 오라클 데이터베이스 서버 하드디스크나 1급 주요 가상머신 스토리지(LUN)에 1순위로 채택됩니다. VM에서 하드디스크 용량 증설(Expand)이나 고부하를 견딜 때는 무조건 SCSI(혹은 SAS/가상 NVMe) 류를 기반으로 생성합니다.

---

## 3. 파티션 (Partition) 구조와 마운트 (Mount)

가상 머신에 500GB짜리 하드디스크 쇳덩이를 물리적으로 부착시켰다 해도 OS는 바로 구워 쓰지 못합니다. 

### 1) 파티션 분할 (포매팅)
거대한 500GB 디스크 땅덩어리를 도마질하여, 1번 방(OS 부팅 리눅스 방, `/`), 2번 방(데이터베이스 방, `/var`), 3번 방(가상 메모리 방, `swap`)으로 논리적인 토막을 나누는 행위입니다. 만약 루트 파티션이 꽉 차서 죽어도 다른 로그 데이터 방은 생존하도록 장애 도미노를 차단하는 관리 편의성이 존재합니다.

### 2) 마운트 (합체) 연결
윈도우는 하드를 꽂으면 알아서 `D드라이브` 문자가 생기지만, 리눅스는 디스크 드라이브라는 개념이 아예 없습니다. 리눅스 계통은 모든 자원을 **"디렉터리 폴더"**로 퉁쳐버립니다.
* **마운트의 원리:** 내 리눅스 바탕화면에 빈 깡통 폴더 구멍(`/mnt/data_disk`)을 하나 파놓은 뒤, 뒤늦게 꽂은 하드디스크 조각 덩어리를 "이 깡통 폴더 안으로 쏙 들어가서 합체해라!" 라고 톱니바퀴를 걸쇠에 채우는 융합 행위를 통틀어 마운트(Mount)라고 부릅니다.
