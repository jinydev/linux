# 보안 프로토콜 규약: HTTP vs HTTPS

사용자의 브라우저(크롬) 웹 클라이언트와 리눅스 웹 서버(Nginx, Apache)가 그림 파일과 HTML 소스코드를 무사히 교환하기 위해 정의된 인터넷 언어 전송 규약의 기초를 다룹니다.

---

## 1. HTTP (투명한 엽서 방식)
인터넷에서 하이퍼텍스트 문서를 전송(Transfer)하기 위해 고안된 가장 원시적이고 순수한 통신 프로토콜(TCP 80번 포트)입니다.
* **치명적 약점 (평문 텍스트 통신):** 사용자가 웹쇼핑몰의 아이디 칸에 `admin`, 비밀번호 칸에 `1234`를 입력하고 전송 버튼을 누르면 이 데이터가 순수 평문 텍스트로 네트워크 전선과 무선 와이파이를 타고 둥둥 날아갑니다. 중간에서 해커가 커피숍 공유기만 해킹해 쳐다보고(패킷 스니핑) 있으면, 내용이 모두 까발려지는 무방비 상태의 **투명한 엽서**와도 같습니다.

## 2. HTTPS (철가방 암호금고 방식)
이러한 해킹을 원천 봉쇄하기 위해 HTTP라는 뼈대 위에, 데이터를 금고에 담고 자물쇠를 채우는 **S (Secure Socket Layer, 보안 소켓 계층)** 를 한 겹 더 입힌 방탄복 통신이 바로 HTTPS(TCP 443번 포트)입니다.

* **동작 원리 (SSL/TLS 인증서):**
  클라이언트가 로그인 버튼을 누르면 데이터는 즉시 난수 구조의 더러운 쓰레기 값 암호 코드로 변조됩니다. 이 암호화된 가방은 중간에 해커가 가로채서 갈라 보더라도 절대 해석이 불가능합니다. 오직 목적지 서버만 쥐고 있는 마스터 전용 키(비밀키)를 가져야만 가방 자물쇠를 따고 원본 데이터를 해독(복호화)해 낼 수 있습니다.

---

## 3. 실무 비즈니스에서 반드시 HTTPS를 써야 하는 이유

HTTPS 인증 시스템은 비싼 돈이 들고, 매번 데이터를 넣고 뺄 때마다 암호화 덧셈 뺄셈(CPU 연산 소모)이 걸려 과거엔 금융 사이트만 썼습니다. 하지만 오늘날엔 단순 일기장 블로그조차도 모두 의무화되는 까닭은 다음과 같습니다.

### 1) 고객 데이터 기밀성 유지
쇼핑몰 전자상거래 시스템, 로그인 인증 등 단 1바이트라도 개인정보가 네트워크에 오르락내리락하는 사이트는 그 패킷이 중간 통신사 라우터나 공유기 단말에서 해킹당하는 것을 막아줄 최소 방어선입니다.

### 2) 검색 파워(SEO) 가산점 어드벤티지 
단순 정적 파일 웹사이트조차 HTTPS를 입히는 주 원인입니다. 구글, 네이버 등 글로벌 IT 공룡들은 "보안을 신경 안 쓰는 구닥다리 `http://` 사이트는 악의적 사이트일 확률이 높다"고 판단해 크롬 탭 표기 줄에 <위험함>이라는 빨간 딱지를 붙입니다.
반면 **`https://` 방탄복 인증을 거친 사이트는 검색 엔진 노출 최상단에 우대 가산점(SEO 매트릭스)**을 부여하기 때문에 영업 마케팅 측면에서 절대적인 필수가 되었습니다.
