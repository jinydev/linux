# 마크다운 (Markdown): 개발자의 문서 표준

개발자는 엑셀이나 아래아 한글을 선호하지 않습니다. 마우스를 잡지 않고 키보드 타이핑만으로 제목, 표, 코드 블록을 아름답게 그려낼 수 있는 **텍스트 기반의 경량 마크업 언어(Markdown)**가 전 세계 오픈소스 진영(`GitHub`, `GitLab`)의 사실상 표준(De facto) 문서 포맷이 되었습니다.

---

## 1. 마크다운의 강점과 한계

### [강점]
1. **타이핑 최적화:** 마우스를 만지작거리며 폰트 크기를 늘릴 필요 없이, 글꼴 앞에 `#` 만 달아주면 즉시 본문 제목이 완성됩니다.
2. **이식성과 호환성:** 순수한 `*.md` 텍스트(Text) 파일이므로 용량이 몇 KB에 불과하며, 깃(Git)으로 형상관리 시 수백 줄 중 "어느 한 글자가 바뀌었는지" 완벽하게 시각적 추적이 가능합니다.
3. **HTML 치환성:** 시스템이 빌드될 때 마크다운 문법은 정규화된 순수 HTML 태그(h1, p, table, pre)로 부드럽게 1:1 자동 변환되어 렌더링됩니다.

### [단점]
* W3C 같은 국제 절대 표준 기구가 구심점이 없습니다. (그래서 Git Flavored Markdown (GFM) 등 플랫폼마다 표를 그리는 문법이 미세하게 다를 수 있습니다.)

---

## 2. 실무 필수 마크다운 문법 치트시트

자주 까먹는 핵심 마크다운 기호들을 정리합니다.

### 1) 헤더 (Headers)
글의 제목과 목차 뼈대를 담당합니다. (#의 개수가 많아질수록 글씨가 작아집니다.)
```markdown
# 1. 아키텍처 개요 (h1)
## 1.1 서버 세팅 (h2)
### 1.1.2 리눅스 커널 (h3)
```

### 2) 인용구 (BlockQuotes)
남의 글을 퍼오거나, 주의(Warning) 박스를 칠 때 씁니다. 중첩이 가능합니다.
```markdown
> 이 문장은 인용구입니다.
>> 중첩된 깊은 인용구입니다.
```

### 3) 리스트 (Lists)
숫자가 붙는 순서 리스트와 점으로 찍히는 글머리 리스트가 있습니다.

* **순차 리스트 (Ordered)**
  숫자를 냅다 적고 마침표를 찍습니다. `1. 3. 2.` 처럼 일부러 숫자를 순서 엉터리로 기입해도 화면에 렌더링될 때는 무조건 정렬되어 `1. 2. 3.` 으로 나타납니다.
  ```markdown
  1. 첫 번째 작업
  2. 두 번째 작업
  ```
* **글머리 리스트 (Unordered)**
  대시(`-`)나 별표(`*`)를 앞에 씁니다. 스페이스바를 통해 하위(들여쓰기) 메뉴 구성이 가능합니다.
  ```markdown
  * 최상위 메뉴
    * 서브 메뉴 1
      * 서브 서브 메뉴 2
  ```

### 4) 코드 블록 (Code Blocks)
개발자에게 가장 중요한 기능입니다. 물결표 밑에 있는 억음 부호(Backtick, `` ` ``) 3개를 위아래로 감싸서 코딩 형식을 깔끔하게 보호합니다. 
맨 첫 줄 백틱 옆에 `bash` 나 `python`, `html` 을 적어주면 글자 색상(Syntax Highlighting)까지 예쁘게 입혀줍니다.

````markdown
```bash
# Nginx를 설치합니다.
sudo apt-get install nginx -y
```
````

### 5) 링크와 이미지 (Links & Images)
가장 헷갈리는 문법입니다. 무조건 `[화면출력텍스트](URL주소)` 공식을 지킵니다.
* **일반 텍스트 하이퍼링크:** `[구글 바로가기](https://www.google.com)`
* **이미지 삽입 (사진 띄우기):** 링크 앞에 느낌표(`!`) 하나만 달면 이미지가 렌더링됩니다.
  `![우분투로고](https://cdn.ubuntu.com/logo.png)`
