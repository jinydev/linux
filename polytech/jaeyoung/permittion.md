# 리눅스의 출입통제 시스템: 권한(Permission) 체계

리눅스는 애초에 수백 명의 원격 사용자가 터미널 하나를 나눠 쓰는 멀티 유저 운영체제로 태어났기 때문에, 내 파일과 남의 파일을 엄격하게 통제하는 **'권한(Permission)'과 '소유권(Ownership)'** 개념이 보안의 뿌리입니다.

---

## 1. 퍼미션 8진수 모드 구조 (chmod)

파일에 권한을 주거나 뺏을 때 사용하는 핵심 명령어는 **`chmod` (Change Mode)** 입니다.
`ls -al` 을 치면 왼쪽에 나타나는 10자리 알파벳(예: `-rwxr-xr-x`) 구조를 해독해 냅니다. 첫 글자는 파일 성격(일반 문자 `-`, 디렉터리 문자 `d`)을 뜻하며, 뒤의 9글자를 3개씩 토막 내어 **[소유주] - [그룹] - [나머지 외부인]** 순으로 권한을 매깁니다.

### [권한의 절대 수치 합산 원리]
각각의 권한(읽기, 쓰기, 실행)은 절댓값 포인트를 가집니다.
* **Read (`r`) = 4점:** 볼 수 있는 눈을 줍니다.
* **Write (`w`) = 2점:** 편집하고 지울 수 있는 펜을 줍니다. 
* **eXecute (`x`) = 1점:** 프로그램을 돌리거나(파일), 폴더 속으로 들어갈 발(디렉터리)을 줍니다.

> **실전 예제 (`chmod 755 filename`)**
> * 첫 번째 7 (`4+2+1`): **소유자(나)**는 모든 권한을 가진 절대자.
> * 두 번째 5 (`4+0+1`): **내 그룹(팀원)**은 읽기(4)와 실행(1)만 되고 쓰기 수정은 불가.
> * 세 번째 5 (`4+0+1`): **지나가는 사람**들도 읽기(4)와 실행(1)만 허용.

## 2. 소유권 강제 탈취 (chown, chgrp)

특정 웹서버 폴더는 Nginx가 접근해야 하는데 내가 소유자라 거부당하는 경우, 
파일의 명패(주인) 자체를 다른 사람이나 다른 부서로 양도해 주는 작업이 소유권 변환입니다.
**(이 양도 문서 작업은 오직 신급 권한인 `root`만 인가 도장을 찍어줄 수 있습니다.)**

* **소유자와 그룹 한 방에 바꾸기 (`chown`)**
  ```bash
  # index.html 파일의 주인을 nginx 사용자, 팀도 nginx 그룹으로 통째로 영구 양도합니다.
  sudo chown nginx:nginx index.html
  ```
* **그룹만 살짝 바꾸기 (`chgrp`)**
  주인(내 계정)은 가만히 둔 채, 접근 가능한 팀 간판만 살짝 바꿉니다.

## 3. 권한 대행 및 기본 방패망 (su, sudo, umask)

1. **사용자 신분 위장 (`su` vs `sudo`)**
   * **`su -` (Switch User):** 완전히 철수 계정에 빙의합니다. 빙의하려면 철수의 비밀번호를 알아야 합니다. 아예 껍데기가 철수로 바뀌어 `exit` 칠 때까지 지속됩니다.
   * **`sudo` (SuperUser DO):** 임시로 1초 동안만 대통령 검을 빌려 쓰는 행위입니다. 슈퍼유저 패스워드가 아니라 "내 자신의 로그인 패스워드"를 입력해 검을 빌립니다. 무법천지를 막기 위해, 시스템 관리자가 허락한(`/etc/sudoers`) 사람만 검을 빌릴 수 있습니다.

2. **기본 퍼미션 자르기 (`umask`)**
   운영체제는 처음 파일이 태어날 때 기본적으로 권한 `666`(누구나 읽고 쓰기)이라는 위험한 덩어리를 부여하려고 합니다. 
   보통 리눅스 쉘에 `umask 022` 라는 조각 칼이 숨어있어, `666`에서 `022` 값을 빼앗아 버려(마스킹 조각 내기), 결국 안전한 파일인 **`644` (나만 쓰고 남들은 읽기만 함)** 로 파일이 예쁘게 무결하게 태어나도록 조각해 주는 필터 역할을 합니다.
