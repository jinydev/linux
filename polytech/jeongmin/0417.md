# 리눅스 커널 프로세스와 스레드(Thread) 아키텍처

우리가 코드를 작성하고 돌리는 행위가 운영체제 레벨에서 어떻게 할당되고 실행되는지, 리눅스 인프라 관점에서의 프로그램, 프로세스, 스레드의 계층 구조를 분해합니다.

---

## 1. 정적 상태: 프로그램 (Program)
* **정의:** 하드 디스크(`/usr/bin`)에 고스란히 저장되어 있는, 생명이 없는 '코드와 데이터의 물리적 패키지(실행 파일)'입니다.
* **비유:** 아직 요리사가 꺼내보지 않은, 주방 찬장 속에 들어있는 종이 **레시피 북**입니다.

## 2. 동적 상태: 프로세스 (Process)
* **정의:** 멈춰있던 프로그램 파일이 램(메모리) 위로 적재되고, CPU 자원을 할당받아 심장이 뛰기 시작한 '실행 중인 인스턴스'입니다. 리눅스에서는 고유한 식별 번호(`PID`)를 부여받습니다.
* **구조:** 각각의 프로세스는 남의 것을 침범하지 못하는 완전히 '독립된 메모리 영역 (Code, Data, Heap, Stack)' 블록을 각자 부여받아 보안을 유지합니다. 
* **멀티 프로세스 (Multi-Process)**
  * 장점: 완전히 방화벽이 쳐진 독립 공간이기 때문에, 크롬 탭(프로세스) 하나가 뻗더라도 다른 탭이나 전체 브라우저는 무사히 생존하는 극도의 안정성을 자랑합니다.
  * 단점: 프로세스끼리 서로 대화를 하려면 복잡한 IPC(파이프, 소켓 통신)를 거쳐야 하고, 이 무거운 것들을 들고 CPU가 1초에도 수천 번씩 왔다 갔다 스위칭(Context Switching) 하느라 체력(Overhead) 소모가 막심합니다.

---

## 3. 세부 실행 단위: 스레드 (Thread)
* **정의:** 무거운 프로세스라는 방 안에서 일을 직접 쳐내는 실질적인 '동작 단위(요리사)' 입니다. 모든 프로세스는 최소 1개(메인 스레드) 이상의 스레드를 가집니다.
* **멀티 스레드 (Multi-Thread)**
  * **구조 설계의 혁신:** 스레드들은 프로세스 방해 코드(Code), 데이터(Data), 그리고 동적 메모리 **힙(Heap) 영역을 서로 완벽하게 '공유'**합니다. 오로지 호출 명령을 담는 스택(Stack) 공간만 각자 따로 씁니다.
  * **장점:** 방 안의 물건을 셰어하므로, 멀티 프로세스처럼 무겁게 복사본을 찍어낼 필요 없이 메모리 소모가 적고 속도가 전광석화처럼 빠릅니다. 통신도 그냥 힙 메모리를 통해 주고받으면 끝입니다.
  * **단점:** 서로 같은 힙 변수나 자원을 마구마구 만지기 때문에 **동기화(데드락, 병목 현상)** 조절 설계가 지옥같이 어렵습니다. 가장 치명적인 것은, 멍청한 스레드 하나가 공유 자원에 잘못된 지뢰 메모리를 건드려 터지면 **멀티 스레드는 속해 있는 부모 프로세스 방 전체를 몽땅 붕괴**시키고 동반 자살해 버립니다.
