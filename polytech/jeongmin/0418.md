# 리눅스 프로세스의 4대 메모리(Memory) 구조

하드디스크에 있던 프로그램이 CPU를 만나 진짜 프로세스(Process) 단위를 부여받으면, 운영체제는 이 프로그램이 자유롭게 뛰어놀 수 있도록 가상의 메모리(RAM) 운동장을 던져줍니다. 이 운동장은 섞이는 것을 방지하게 위해 역할별로 철저하게 4구역으로 나뉘어 관리됩니다.

---

## 1. Code (코드/텍스트 영역)
* **역할:** 우리가 키보드로 타이핑한 소스 코드가 기계어(`010100...`)로 번역된 실제 '명령어'들 자체가 통째로 쑤셔 박히는 구역입니다.
* **특징:** 여기서 컴퓨터 CPU가 한 줄씩 명령을 꺼내다 읽기만 해야 하므로, 쓸 수 없는 읽기 전용(Read-Only) 구역으로 락이 걸려있습니다. 

## 2. Data (데이터 영역)
* **역할:** 프로그램의 시작부터 끝까지 죽지 않고 계속 존재해야 하는 **전역 변수(Global)와 정적 변수(Static)** 들이 입주하는 구역입니다.
* **특징:** 프로그램이 실행될 때 처음에 한 번 띡 세팅되고, 프로그램이 완전히 종료(Exit)될 때 비로소 메모리에서 소멸합니다. 

---

## 3. Heap (힙 영역 - 사용자 통제구역)
* **역할:** 개발자인 내가 원할 때 필요한 만큼 떼서 쓰고 버릴 수 있는 **동적 할당(Dynamic Allocation)** 메모리 운동장입니다. (C언어의 `malloc`, 자바의 `new` 객체들이 사는 곳)
* **특징:** 메모리의 아랫바닥(낮은 주소)에서부터 위를 향해 데이터를 차곡차곡 쌓아 올립니다. 가장 먼저 들어온 놈들이 먼저 나가는 선입선출(FIFO)의 구조를 지닙니다. 이 힙에 데이터 객체를 쌓기만 하고 지워주지 않으면, 프로그램의 덩치가 터져버리는 '메모리 누수(Memory Leak)' 대참사 버그가 발생합니다.

## 4. Stack (스택 영역 - 커널 자동구역)
* **역할:** 함수를 호출할 때 잠깐 썼단 버릴 임시 메모장입니다. **지역 변수(Local)와 매개 변수(Parameter)** 들이 머무는 곳입니다.
* **특징:** 함수가 호출되면 할당되었다가, 함수 루틴이 무사히 끝나고 리턴되는 즉시 번개처럼 사라집니다. 밑바닥부터 쌓는 힙과 반대로, 천장(높은 주소)에서부터 허공 아래로 거꾸로 자라납니다. 제일 늦게 들어온 함수 변수가 가장 먼저 빠져나가는 후입선출(LIFO) 원리를 따릅니다. 무한 재귀 함수를 돌려 스택이 뻗어나가다 못해 선을 넘으면 발생하는 에러가 바로 무서운 `Stack Overflow` 입니다.

> **💡 Heap vs Stack 영토 분쟁**
> 
> 같은 메모리 하우스 안에서, **Heap은 밑에서 위로, Stack은 위에서 아래로** 서로 마주 보며 자라납니다. 고정되어 있지 않고 가변적으로 유연하게 쓰다가 둘의 영토가 부딪혀 공간이 부족하면 어플리케이션은 뻗어버립니다. 이를 물리적으로 중재하는 것이 커널 가상 메모리의 힘입니다.
