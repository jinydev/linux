# 루트 권한 취득: su 와 sudo 의 아키텍처적 차이

리눅스는 애초에 멀티 유저 시스템이므로 누군가 시스템 핵심 설정 파일을 작정하고 부수지 못하게, 시스템 절대관리자인 `root` 계정과 `일반 시스템 유저` 계정이 완벽히 물리적으로 단절되어 있습니다. 

터미널 작업 중 이 막대한 root 권한의 검을 얻어내는 3가지 방식의 차이점을 파악합니다.

---

## 1. su (Switch User) : 남의 옷만 빌려 입기
가장 원초적으로 다른 사람(또는 root)의 아이디로 갈아탈 때 쓰는 로그아웃/로그인 전환 단축키입니다.
* **동작:** `su root` (혹은 뒤에 계정 이름 생략 시 무조건 root로 간주)
* **특징:** 대상 사용자로 전환은 되지만, 기존 내 원래 계정이 머물던 폴더 위치(`/home/user1`)나 환경 변수 값들은 단 하나도 바뀌지 않고 원래의 껍데기를 그대로 뒤집어쓴 채 옷만 바꿔 입는 형태입니다.
* **요구사항:** 무조건 타겟 대상자(위 예시에선 `root`)의 진짜 패스워드를 알아야만 뚫을 수 있습니다.

## 2. su - (Switch User Login) : 몸통까지 완벽 빙의하기
단순히 `su` 뒤에 짝대기(-) 하이픈 표기 하나를 더한 것이지만, 리눅스 관리에서 완전히 하늘과 땅 차이입니다.
* **동작:** `su - root` 또는 `su -`
* **특징:** 단순히 옷만 갈아입는 수준이 아니라, 전환하려는 그 대상 계정에게 할당된 순정 홈 디렉터리(`/root`)로 워프하며, 프로파일 변수들까지 그 계정의 초기 세팅 값으로 **완벽하게 영혼 빙의급 재로그인 접속(Login Shell)**을 이끌어 냅니다.
* 실무에서는 시스템 꼬임을 방지하기 위해 무조건 하이픈(-)을 붙여서 `su -`를 치는 것이 엔지니어들의 암묵적 룰입니다. 

---

## 3. sudo (SuperUser DO) : 일시적 권한 대행
수십 명의 개발자에게 진짜 root의 패스워드를 함부로 가르쳐 줄 수는 없습니다. 그래서 발명된 것이 대리 권한 수여 체계인 `sudo` 입니다.

* **동작:** `sudo mkdir /sys_folder` 처럼 제한 폴더에 명령어 1개를 실행할 때 앞에 수식어로 붙입니다.
* **특징:** `su`처럼 껍데기를 통째로 root로 갈아타는 것이 아니라, **내 원래 계정 신분을 그대로 유지한 채 단 1회에 한해 관리자 행세를 허락해 주는 프리패스 쿠폰**입니다.
* **요구사항:** root의 비밀번호를 알려달라고 묻지 않습니다. "너 정말 본인 맞아?" 라며 **자기 자신(현재 유저)의 허접한 로그인 패스워드**를 물어봅니다.
* **보안 통제:** 아무나 자기 패스워드를 쳤다고 권한을 주진 않으며 사전에 시스템 관리자가 `/etc/sudoers` 파일 명단에 이 직원의 이름을 V.I.P로 등록해 둔 경우만 동작합니다. 

### [부록: 권한이탈 명령어 시트]
```bash
# 내가 허황된 권한 위장에 취해 현재 내 정체성(ID)이 대체 뭔지 헷갈릴 때 칩니다
$ whoami 

# 남의 계정으로 su를 타거나 접속한 곳에서 원래 세계로 빠져나갈 때 칩니다
$ exit
# 또는
$ logout
```
