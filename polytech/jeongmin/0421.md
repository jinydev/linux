# 서버의 출입문: 포트 (Port Number) 식별 체계

네트워크 통신에서 상대방 서버 기계에 무사히 닿기 위해 치고 들어가는 `IP 주소` 가 건물의 주소, 혹은 '동·호수' 라면, 도달한 그 집 현관문 안에서 **"어떤 방(애플리케이션 프로그램) 문을 열고 이야기할 것인가?"**를 결정짓는 고유 방 번호가 바로 **포트(Port)** 입니다.

동일한 웹 서버라도 웹 화면을 뿌리는 80번 포트 프로그램과 해커가 침투하기 위한 22번 뒷문 포트 프로그램은 물리적으로 완벽히 구분되어 실행됩니다.

---

## 1. 포트 번호의 할당량 체계

컴퓨터 안에서 사용할 수 있는 가상의 방(문)은 `0번` 부터 최대 `65535번` 까지 도합 6만 개 이상의 엄청난 번지수를 자랑합니다. 하지만 번호 충돌과 무법천지를 막기 위해, 전 세계 IANA 기구에서 앞쪽의 황금 번호대를 강제 규격화하여 선점해 두었는데 이를 **잘 알려진 포트 (Well-Known Ports)** 라고 부릅니다. 

### 🌟 절대 암기해야 할 Well-Known Port (0 ~ 1023번)
이 번호대는 시스템이 예약 독점하고 있기 때문에 개인이나 해커가 임의로 게임 서버를 띄울 일이 있을 때는 절대로 끌어다 쓰지 못하며, 건드리기 위해선 `root` 권한이 무조건 필요합니다.

| 분류 서비스 | 방 번호 (Port) | 통신 역할 (암기 필수) |
| :-- | :-- | :-- |
| **FTP** | `21` | 큰 파일, 소스코드 타일 등을 서버와 주고받기 위한 통로 포트 |
| **SSH** | `22` | 관리자가 텔넷 수준을 넘어 강력한 암호화 프로토콜로 원격 터미널에서 제어하는 포트 |
| **HTTP** | `80` | 가장 친숙한 일반 평문 웹사이트 브라우저 통신 포트 (`https`는 443번) |

이후 `1024번 ~ 49151번` 대역은 마리아DB(3306)나 톰캣(8080) 같은 범용 기업체 솔루션들이 선점하는 구역으로 쓰이며, 남은 끄트머리 `49152번 ~ 65535번` 대역은 우리 운영체제가 남몰래 자동으로 뒷구멍 연결 통신을 할 때 소진하고 폐기하는 랜덤 다이나믹 포트로 활용됩니다.

## 2. 포트 충돌 대참사와 프로세스(PID) 색출 기법

톰캣을 돌리는데 오류콘솔에 `Address already in use: bind` 라며 포트가 튕겨 나가는 현상이 흔히 발생합니다.
"우리가 사용할 8080번 방을, 이미 다른 누군가(좀비 프로그램 등)가 독점하고 열쇠를 잠근 채 쓰고 있어서 나에게 방을 내어주지 못하겠다"라는 포트 충돌의 전형적 증상입니다.
이때는 윈도우나 리눅스 터미널 가릴 것 없이 **어떤 놈이 이 포트 방을 쓰고 있는지 지문 검색을 해야 합니다.**

### [문제 해결 추적 커맨드: netstat]
```bash
# 현재 시스템에 열려있는 무수히 많은 전 포트 리스트와, 그 포트를 선점하고 알박기하는 
# 범인 프로그램의 번호(PID)를 투명하게 모두 출력시켜 관찰합니다.
$ netstat -ano

# (리눅스 심화) 수천 줄 중 8080번 방을 장악 중인 범인의 흔적만 핀셋으로 짜내기
$ netstat -anp | grep 8080
```
출력 결과에서 맨 오른쪽의 **PID (Process ID)** 숫자를 확보한 뒤, 리눅스에서 `kill -9 [PID]` 를 날려 해당 프로세스의 동아줄을 강제로 끊어 죽여버리면 굳게 닫혀있던 포트가 스르륵 풀려나 자유로워집니다.
