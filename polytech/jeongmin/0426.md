# 도메인 정보 추적 및 네임서버 질의: nslookup

`nslookup (Name Server Lookup)` 은 브라우저나 시스템이 백그라운드에서 아무도 모르게 수행하는 'DNS 주소록 번역기 질의(Domain to IP)' 과정을, 엔지니어가 직접 쉘 상에서 추적하며 수동으로 IP를 캐묻고 설정이 제대로 탔는지 감시할 수 있는 디버깅 유틸리티입니다.

*(현대 리눅스에서는 살짝 구형 취급을 받아 이 명령어 대신 `dig` 커맨드를 선호하는 추세이기도 합니다.)*

---

## 1. 기본 도메인 질의 IP 추출 (A 레코드)

가장 흔한 방식입니다. 도메인을 주면 연결된 진짜 숫자(서버 IP)를 까발려 줍니다. 

```bash
# 구글 도메인의 A레코드(웹서버 아이피 주소)를 내놓으라고 질의합니다.
$ nslookup www.google.com

Server:		168.126.63.1      # 친절하게 번역해 준 내 통신사 DNS(KT) 주소 
Address:	168.126.63.1#53

Non-authoritative answer:
Name:	www.google.com
Address: 142.250.76.100     # 이 번호가 찾아낸 구글의 진짜 IP 주소입니다.
```

---

## 2. 심화 DNS 레코드 (RR Type) 분해 분석

도메인을 산다고 끝이 아닙니다. 이 도메인 주소록(존 파일) 안에는 "서버는 1번지로, 메일오면 2번지로"라는 세부 규칙이 존재하며 이를 **RR (Resource Record)** 이라 부릅니다. `nslookup`의 대화형 모드나 파라미터를 통해 이 규칙들을 샅샅이 캐물을 수 있습니다.

| 질의 타입 종류 | 엔지니어 해석 (질문의 의도) |
| :-- | :-- |
| **A (A-Record)** | "이 도메인의 진짜 본서버 IP 번호 좀 알려줘" (기본값) |
| **CNAME** | "혹시 이거 가짜 별칭 도메인 아냐? 진짜 원본 이름이 뭔지 가리켜봐" |
| **MX** | "누가 이 도메인 네임으로 이메일을 쏘면, 메일을 받아먹을 Exchange 수신 서버 IP가 어딘지 알려줘" |
| **NS** | "이 도메인 주소록 전체를 관리하는 총 네임서버 책임자 대빵이 누구야?" |
| **TXT** | "이 사이트 스팸 방지 검증이나, 소유권 인증하라고 구글이 꽂아둔 비밀 암호문 덱스트 좀 꺼내봐" |

### [실전 옵션 응용법]
이 도메인의 메일 수신 서버(MX)가 누구인지 핀셋 추적할 때 `-type=mx` 설정을 때려 넣습니다.
```bash
# 네이버의 이메일 수신 담당 서버(MX) 내역만 털어보기
$ nslookup -type=mx naver.com
```
