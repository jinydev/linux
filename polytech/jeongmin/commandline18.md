# 압축(Compression)과 아카이빙(Archiving) 유틸리티 제어

리눅스 서버의 방대한 로그 파일들은 며칠만 지나면 디스크를 꽉 채워버립니다. 파일 시스템 부하와 용량 폭탄을 막기 위해 덩치를 줄이는 '압축 프로그램'과, 폴더 단위로 짐가방을 한통에 묶어내는 '아카이브 도구'를 숙지해야 합니다. 

---

## 1. 순수 덩치 줄이기 (단일 압축)
리눅스의 오리지널 압축 도구들은 한 번에 여러 파일을 묶지 못하고 단 하나의 파일 덩치만을 줄이는 데 특화되어 있습니다. 원본 파일이 사라지고 꼬리가 붙는 특징이 있습니다. 

* **`gzip` (.gz)**
  가장 유서 깊은 표준 압축 방식. 빠르며 압축률이 평이합니다.
  ```bash
  $ gzip server_log.txt        # server_log.txt.gz 로 바뀌고 원본 소멸
  $ gunzip server_log.txt.gz   # 압축 풀고 원본 복구
  ```
* **`bzip2` (.bz2)**
  시간은 더 거북이처럼 오래 걸리지만 텍스트 파일을 쥐어짜는 고효율 알고리즘 덕에 용량 다이어트 효과가 탁월합니다. 

## 2. 짐가방 캐리어 묶기 도구 (tar 아카이빙)
수천 개의 파일과 디렉터리를 가진 소스 코드 폴더는 `gzip`으로 압축조차 안 됩니다.
**수천 개의 짐을 테이프 칭칭 감아 하나의 거대한 쇳덩이 가방으로 묶어버리는 도구가 바로 `tar` (Tape Archive) 입니다.**
자체로는 압축 기능(용량 줄이기)이 없으나 압축 도구 옵션을 빌려 함께 결합해 사용합니다 (실무 절대 표준).

### [tar 실전 커맨드: c(생성), x(풀기), v(과정보여주기)]
```bash
# 1. 묶기 + 압축 (가장 중요한 cvfz 옵션 결합, gzip의 z를 빌려 씀)
# my_source 폴더를 묶고 압축해서 release_v1.tar.gz 캡슐로 만들어 냅니다.
$ tar -cvfz release_v1.tar.gz /home/user/my_source/

# 2. 풀기 + 압축해제 (xvfz 혼합 옵션)
# 묶인 캡슐 가방을 현재 디렉터리 바닥에 확 풀어 헤칩니다.
$ tar -xvfz release_v1.tar.gz
```
*(참고: 윈도우와 호환용으로 쓰이는 `zip` 과 `unzip` 도 리눅스에서 널리 지원됩니다.)*

## 3. 원격지 폭격 동기화 (rsync 무손실 복사)

내가 서버 A에서 어제저녁에 서버 B로 소스 폴더 100GB를 복사(백업)했습니다. 그런데 오늘 아침 폴더에서 딱 한 줄의 10KB짜리 파일 1개만 바꿨는데 이걸 동기화하려고 또 `cp`나 `tar`를 써서 100GB 거대 폴더를 통째로 쏟아부어야 할까요?

* **동작 원리:** **`rsync` (Remote Sync)**는 통신할 때 파일들의 수정 시간 해시 목록을 미친 듯이 스캔 차이를 떠버린 다음, **"변경된 부분(10KB 한 줄 조각)만 아주 구두쇠처럼 전송해 덧씌우는"** 궁극의 네트워크 대역폭 다이어트 백업 유틸리티입니다.
* 새벽에 크론(Cron) 스케줄러를 걸어두고, 웹 서버 A와 대피용 서버 B를 똑같은 거울 모드로 무손실 동기화 백업 칠 때 무조건 0순위로 쓰이는 최강의 명령어입니다.
