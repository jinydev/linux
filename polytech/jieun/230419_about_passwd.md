# UID 등급과 패스워드 비밀번호 만료 정책 (passwd & chage)

리눅스는 서버 한 대에 수천 명의 직원이 동시 접속하는 운영체제이므로, 직급별 통제 시스템인 다중 계정 체계와, 보안 감사를 위한 패스워드 강제 변경 주기를 엔지니어가 컨트롤해야 합니다.

---

## 1. 리눅스 계정의 3대 철저 계급 (UID)

리눅스 커널은 사람이 입력하는 `hojin`, `admin` 같은 영어 이름을 해석하지 않습니다. 운영체제는 회원 가입 시 찍혀 나오는 **`UID (User ID)` 라는 숫자로 계층을 차별화합니다.**

* **UID 0 번계급 (Root / 슈퍼유저):**
  리눅스 시스템 생태계의 절대 창조주. 신급 번호인 `0`번을 배정받습니다. 시스템 폴더를 통째로 지워버리든 권한을 뺏든 그 어떤 제한도 받지 않는 무적 계정입니다.
* **UID 1 ~ 999 번계급 (시스템 데몬 계정):**
  사람(직원)이 로그인할 때 쓰는 계정이 아닙니다. `bin`, `mail`, `apache`, `mysql` 등 백그라운드 프로그램들이 자신들의 프로그램 실행 권한 방어막을 치고 소유권을 들고 있기 위해 내부적으로 돌아가는 숨겨진 소프트웨어 계정들입니다. 로그인이 차단되어 있습니다.
* **UID 1000 번계급 이상 (일반 평민 유저):**
  신규 입사자가 들어와서 내주거나, 개발자들이 FTP 접속 시 할당받는 가장 일반적인 계층입니다. 자신의 `/home/아이디` 우물 안에서만 뛰어놀 수 있으며, 상위 폴더나 남의 파일을 보려면 권한 결핍에 가로막힙니다.

## 2. 비밀번호 즉시 수정 명령어 (`passwd`)

자신의 비밀번호를 바꿀 때는 그냥 치고, 해고된 직원의 계정을 잠그거나 비번을 강제로 초기화할 때는 root 권한이 필요합니다.

```bash
# 본인의 패스워드 셀프 입력 및 변경
$ passwd 

# 관리자가 'testuser' 직원의 비밀번호를 강제 세팅해 줌
$ sudo passwd testuser
```

### [passwd 보안 락킹 옵션 매뉴얼]
* `-l` (Lock): 사고 친 사원의 패스워드 앞에 잠금 기호를 달아, **아예 로그인을 막아 시스템에서 튕겨내버립니다.**
* `-u` (Unlock): 잠금을 풀어 사면해 줍니다.
* `-d` (Delete): 비밀번호 해시 암호를 삭제시켜, 비번 입력 란을 그냥 엔터만 쳐도 뚫려 들어가게 만듭니다 (실무 사용 금지).

## 3. 기업 보안 감사: 비밀번호 만료 주기 설정 (`chage`)

금융권이나 IT 기업 인프라 보안 감사(Compliance)에서는 "모든 사원은 30일에 한 번씩 강제로 패스워드를 바꾸게 만들어야 한다"는 룰이 필수입니다. 이 수명 주기를 제어하는 명령어가 CHange AGE, 즉 **`chage`** 입니다.

```bash
# 1. 특정 유저(test)의 남은 패스워드 수명 기간 상태표를 조회
$ sudo chage -l test

# 2. 강력한 실무 옵션 콤보 튜닝 (보안 규정 적용)
# -M 90: 비밀번호를 바꾸면 90일 동안만 그 비밀번호의 수명이 보장됨 (90일 지나면 강제 변경창 뜸)
# -W 7 : 만료일이 다가오기 7일 전부터 로그인할 때마다 "비번 바꿔라" 경고창을 띄움
# -m 3 : 한 번 비밀번호를 바꾸고 나면, 최소 3일이 지나기 전에는 새 비밀번호로 또 바꿀 수 없음 (방어막)
$ sudo chage -M 90 -W 7 -m 3 test
```

> **📌 도움말 백과사전 메뉴얼 (`man`) 호출**
> 막막한 명령어나 옵션이 기억 안 날 때 구글링 대신 리눅스 내부 지침서를 읽는 방법입니다.
> * `$ man passwd` (명령어 사용법 텍스트 폭포수 호출)
> * 빠져나올 때는 `q`(Quit)를 치고, 스페이스바를 누르면 한 장씩 아래로 술술 넘어갑니다.
