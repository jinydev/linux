# 파일 퍼올리기: FTP (File Transfer Protocol) 아키텍처

원격 서버에 내가 로컬에서 짠 웹소스(.html)를 수천장 복사해 올려야 할 때 쓰이는, 유서 깊은 '무자비한 파일 덤프트럭' 전송 규약입니다. 

---

## 1. 두 개의 분리된 차선 통신 포트

일반적인 HTTP 웹 접속은 80번 포트 하나만 뚫어도 요청과 응답을 다 처리하지만, FTP는 무거운 대용량 파츠(파일)을 나르기 위해 아예 지시를 내리는 무전기 채널과 덤프트럭이 다니는 화물 채널 두 가지를 찢어서 분리 통과시킵니다.

* **명령 채널 (Command / 21번 포트):** 클라이언트가 서버에 "나 로그인할게", "자료 목록 좀 보여줘", "a.txt 다운받을게" 등을 타이핑 쳐서 서로 대화하는 제어 파이프입니다.
* **데이터 채널 (Data / 20번 포트 등):** 실제 무거운 파일 조각이 무식하게 쏟아져 들어오거나 나가는 화물 고속도로입니다.

## 2. FTP 연결 모드: 능동(Active) vs 수동(Passive) 

클라이언트 방화벽 때문에 화물 채널(Data)을 뚫는 기법이 갈렸습니다. 요즘은 거의 능동 모드가 버려집니다. 

### 능동 모드 (Active Mode)
* **논리:** 클라이언트가 "나 5000번 포트 열어놨으니 네가 파일 싸들고 이리로 들어와라!" 하고 서버한테 지시합니다.
* **치명적 문제:** 요즘 사무실 공유기(NAT)나 윈도우 방화벽은 외부에서 남이 내 컴퓨터를 다이렉트로 치고 들어오는 걸 절대 용납하지 않습니다. 당연히 서버가 파일 들고 오다가 내 방화벽에 막혀 죽고 에러를 뿜습니다.

### 수동 모드 (Passive Mode - 현대 표준)
* **논리:** 능동 모드의 개살구를 극복했습니다. 클라이언트가 "내가 접속해 들어갈 테니, 서버 네가 여유 있는 랜덤 포트 하나를 쫙 열고 거기다 파일 담아놔!" 라고 응수합니다. 방화벽 구조상 내가 밖으로 뚫고 나가는 통신은 허용되므로, 이 방식으로만 에러 없이 대규모 다운로드가 가능합니다.

---

## 3. 보안 약점 구조 탈피 (SFTP의 시대)

과거 순수 FTP의 치명적인 단점은, 명령 채널에서 내가 입력하는 "비밀번호 1234" 라는 패스워드가 **아무런 암호화 없이 투명한 평문 유리 상자 상태로 인터넷망을 날아다닌다는 것**이었습니다. 카페 와이파이에서 해커가 패킷만 가로채면 회사의 서버 비밀번호가 1초 만에 털립니다.

현재 실무 인프라 엔지니어링에서는 이를 모조리 단종시키고, SSH의 무적 터널링 암호를 둘둘 말아 씌운 **SFTP (22번 포트)** 를 전면 표준으로 강제하고 있으며, `FileZilla` 같은 클라이언트도 이를 주력으로 지원합니다.
