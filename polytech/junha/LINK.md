# 파일 주소의 영혼 관리: 아이노드(i-node)와 하드/소프트 링크 분신술

리눅스는 파일 이름 자체를 진짜 그 파일 덩어리로 생각하지 않습니다. 내부적으로는 숫자로 된 **아이노드(i-node)** 라는 꼬리표를 핵심 데이터로 관리합니다. 우리는 이 신기한 아이노드 철학을 이용해 분신술(링크)을 만들어 낼 수 있습니다.

---

## 1. 아이노드 (i-node) 란?
파일 시스템의 고유한 영혼 식별 번호이자 호적 등본입니다. 사람으로 치면 '주민등록번호'입니다. 
우리가 `report.txt` 라는 파일을 만들면, 이름표와 용량, 권한 정보 등은 아이노드(예: `158392`번) 방명록에 등록되고 실제 알맹이 데이터는 하드디스크 어딘가에 투척됩니다.

---

## 2. 하드 링크 (Hard Link) : 거울 분신 만들기
원래 있던 원본 하나에, 이름표만 하나 더 복사해서 갖다 붙이는 완전한 직통 거울 연결 방식입니다.

* **동작 명령:** `ln 원본파일 새로만들분신이름`
* **아키텍처:** 하드 링크를 걸면 원본 파일과 새로 만든 링크 파일이 **아예 똑같은 주민번호(아이노드 번호)를 공유**하게 됩니다. 두 이름 중 아무거나 붙잡고 글을 수정하면 결국 하드디스크의 똑같은 핵 데이터를 수정하게 됩니다. 
* **불사조 특징 (용량 절약):** `ls -l` 로 보면 파일 두 개가 각각 10MB 인 것처럼 보이지만, 아이노드를 셰어하므로 실제 하드 용량은 10MB 하나만 차지합니다 (`cp` 복사와 완전 다름). 게다가 원본 쪽 파일(이름표)을 `rm`으로 불태워 삭제해 버려도 데이터는 삭제되지 않으며 남은 하드링크 분신을 통해 무사히 읽을 수 있는 무적 구조입니다. 모든 이름표 끈이 끊어져야 비로소 데이터가 죽습니다.

---

## 3. 소프트 링크 (심볼릭 링크) : 바탕화면 바로가기
윈도우의 '바탕화면 바로가기 아이콘'과 100% 동일한 개념입니다. 원본 데이터 아이노드를 바라보는 게 아니라, 껍데기 길바닥 주소 텍스트 문자열만 쥐고 있는 허수아비입니다. 실무에서 압도적으로 많이 쓰입니다. (맨 앞 권한 기호가 `l` 로 뜹니다.)

* **동작 명령:** `ln -s 원본파일 바로가기이름` (옵션 s 삽입)
* **아키텍처:** 원본이 주민등록번호 158392번을 가졌다면, 이 심볼릭 링크 분신은 331121 이라는 아예 남남인 자기만의 독립된 주민등록번호를 발급받습니다. 그리고 그 속에는 원본 파일의 텍스트 경로명(예: `/home/user/app.log`)만 덜렁 적어놓고 언제든 거기로 워프시켜주는 안내판 노릇만 합니다.
* **치명적 단점 (단절 고아):** 만약 원본 파일이 폴더를 이사 가버리거나 삭제되어 버리면, 심볼릭 링크 분신은 허공을 가리키는 고아(Broken Link)가 되어 눌렀을 때 `No such file or directory` 에러를 시뻘겋게 뿜으며 사망합니다.

### [실무에서의 심볼릭 링크 활용기 (버전 스위칭)]
자바 스프링 배포 폴더가 `/app/release_1.0` 이었다가 내일 `/app/release_2.0` 으로 바뀌었을 때, 시스템 환경 변수에 폴더명을 일일이 수정하면 서버가 죽습니다. 대신 `/app/current` 라는 심볼릭 링크 간판을 세팅해 두고, 구버전을 가리키던 간판을 부수고 새버전 폴더로 향하게 링크만 찰칵 결착해주면 1초 만에 무중단 무정지 시스템 버전 점프업 배포가 끝이 납니다.
