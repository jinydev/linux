# 인터넷 프로토콜 스택: TCP/IP 아키텍처

택배 배송 시스템처럼, 내 노트북의 카카오톡 메시지가 지구 반대편의 친구 핸드폰 화면에 100% 무사하게 도착하도록 설계된 전 세계 공통의 네트워크 배달 규약입니다. 

---

## 1. 전송 계층의 쌍두마차 (L4 Layer)
물리적인 랜선을 타고 데이터가 찾아갈 때, 3계층(IP)이 '집 주소'를 찾아준다면, **4계층(L4)**은 '수신자가 택배를 받을 상태인지, 파손되진 않았는지'를 책임집니다.

### 🛡️ TCP (Transmission Control Protocol) - 등기 우편
* **철학:** 신뢰성 100% 보장. 메시지가 중간에 유실되거나 순서가 뒤섞이면 끝까지 추적해서 기어코 완벽하게 맞춰냅니다.
* **비용:** 까다로운 검수 작업 탓에 속도가 느리고 무겁습니다. 웹 브라우저(HTTP), 파일 전송, 내부 망 접속 등 누락이 절대 용납되지 않는 서비스에 쓰입니다.

### 💨 UDP (User Datagram Protocol) - 전단지 살포
* **철학:** 확인 안 함, 무조건 최고 속도 폭격. 수신자가 받든 말든 패킷을 미친 듯이 뿌립니다.
* **비용:** 중간에 몇 개 유실되어 화면이 깨지거나 음질이 끊겨도 상관없이 실시간 전광석화 속도를 뽑아내야 하는 유튜브 실시간 스트리밍, 온라인 게임 FPS 반응속도, 화상회의에 쓰입니다.

---

## 2. TCP의 핵심 철학: 3-Way Handshake (3단계 악수)

TCP는 다짜고짜 데이터를 던지지 않습니다. 통신을 시작하기 전, 상대방 서버가 살아있는지 반드시 3번의 타진을 통해 전용 통신 파이프라인(세션)을 수립합니다.

1. **내 노트북 ➡️ 서버 (SYN):** "똑똑, 카카오 서버님. 나 데이터 보낼 건데 통신 가능하냐? (Sync)"
2. **서버 ➡️ 내 노트북 (SYN/ACK):** "오냐 노트북아, 난 준비됐으니 너도 준비해라! (Sync + Acknowledge)"
3. **내 노트북 ➡️ 서버 (ACK):** "네 알겠습니다. 지금부터 바로 데이터 쏩니다! (Acknowledge)"

> 💡 해커들은 이 3-Way Handshake 의 허점을 파고들어, 1번(SYN)만 수백만 번 던져서 서버가 2번 응답을 하느라 힘이 다 빠져 죽게 만드는 **DDos 공격(SYN Flooding)**을 자행합니다.

---

## 3. TCP의 통제 메커니즘 (흐름 제어와 혼잡 제어)

TCP는 단순히 확실하게 보내는 것을 넘어, 네트워크 망이 뻗지 않게 교통정리까지 자처합니다.

* **흐름 제어 (슬라이딩 윈도우):** 내 노트북 최신형인데, 상대방 서버가 구형 똥컴일 때 내가 데이터를 1GB씩 쏟아부으면 서버가 감당 못 하고 터집니다. 수신자가 "나 한 번에 10MB밖에 못 받아!"라고 **Window 크기**를 조절해 주어 데이터의 분사 속도를 최적화합니다.
* **혼잡 제어 (Slow Start):** 고속도로에 차가 꽉 막혔는데 패킷을 쏟아부으면 인터넷망이 다 같이 마비됩니다. TCP는 처음에 패킷 1개를 슬쩍 보내 간을 봅니다. 차가 안 막힌다 싶으면 2개, 그다음 4개, 8개씩 지수 함수로 살살 속도를 올려(Slow Start) 전체 인터넷 트래픽망의 평화를 유지합니다.
