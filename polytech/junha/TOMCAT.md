# 인프라 아키텍처의 분업: 웹 서버(Apache)와 WAS(Tomcat)

자바(Java) 웹 개발자가 회사에 취업하면, 서버 인프라에 가장 먼저 세팅하게 될 핵심 콤비인 `Apache(아파치)` 와 `Tomcat(톰캣)`의 아키텍처 역할 분담론입니다. 흔히 합쳐서 '아파치 톰캣(Apache Tomcat)' 이라고 묶어 부르지만, 인프라의 관점에서는 완전히 다른 역할의 두 심장입니다.

---

## 1. 개념과 롤(Role)의 분리

### 정적 데이터 배달부: Web Server (Apache)
이미지 파일(`logo.png`), 디자인 파일(`.css`), 껍데기 HTML 등 **답이 딱 정해져 있는 파일(정적 컨텐츠)**을 하드디스크 창고에서 찾아서 재빠르게 고객에게 배달하는 트럭입니다.
머리를 쓰는 계산(DB 검색, 로그인 체크)은 불가능하지만, 전방에서 수만 명의 트래픽을 빠르게 쳐내는 엄청난 수비력을 자랑합니다.

### 동적 비즈니스 연산기: WAS (Tomcat)
요청을 받을 때마다 회원의 등급에 따라 가격을 할인해 주거나, 데이터베이스(DB)에서 포인트 잔고를 깎는 등 **"복잡한 자바 비즈니스 로직(JSP/Servlet)"** 을 즉석에서 연산해 만들어내는 두뇌 서버입니다.
* 톰캣은 가장 무겁고 복잡한 연산을 짊어지는 핵심 엔진(서블릿 컨테이너)이므로 트래픽을 정통으로 맞으면 뻗어버리기 십상입니다.

---

## 2. 왜 실무에서는 Apache와 Tomcat을 꼭 융합(연동)하여 쓸까?

톰캣(WAS) 단독으로도 서버를 띄울 수 있고, 내부에 자체적으로 허접한 웹 서버 기능이 있긴 합니다. 하지만 기업형 무정지 아키텍처에서는 앞단에 아파치를 자물쇠처럼 꼭 세워두고 **`Apache + Tomcat`** 의 2-Tier 구조를 구축합니다.

### 분업 콤비의 장점 (Tomcat만 썼을 때의 절망)

1. **최 정예 요원의 연산 집중 (부하 분산):** 
   무거운 DB 수술을 하느라 바쁜 천재 외과의사(Tomcat)에게, 지나가는 사람이 "병원 로고 그림 파일 하나만 주세요" 라고 요청할 때 그거 갖다 주느라 수술 흐름을 끊으면 안 됩니다. 
   앞단에 아파치(간호사)를 두어 허접한 그림 파일 요청은 자기가 다 처리해 버리고, 진짜 어려운 자바 로직만 톰캣으로 던져주어 톰캣의 CPU를 100% 비즈니스 로직에만 쏟게 만듭니다.
   
2. **소프트웨어 로드 밸런싱 (무한 확장):**
   장사가 너무 잘되면, 앞단의 아파치 1대 뒤에 톰캣 5대를 거미줄처럼 병렬로 엮어버립니다. 아파치가 교통경찰이 되어, "1번 톰캣아 너 힘드냐? 그럼 이번 결제 요청은 2번 톰캣 네가 처리해라!" 라며 작업을 지능적으로 분배해 서버가 터지는 걸 막습니다.

3. **해킹 방벽 (물리적 망분리):**
   해커의 브라우저는 최전방 아파치까지만 도달할 수 있습니다. 진짜 소스코드와 DB 연결 비밀번호를 쥐고 있는 톰캣은 아파치 등 뒤의 완전 폐쇄된 사설 방화벽 내부망 고립 지대에 깊숙이 숨겨둘 수 있는 치명적 장점이 발생합니다.
