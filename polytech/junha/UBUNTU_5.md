# 리눅스 파일 시스템의 구조와 생태계 (ext4, 마운트)

우리가 1GB짜리 영화 파일을 하드디스크에 저장할 때, 운영체제는 이것을 단순히 쑤셔 넣는 것이 아니라 거대한 바둑판(블록) 칸에 쪼개어 체계적으로 주소를 매겨 저장합니다. 이렇게 하드디스크의 텅 빈 대지를 조각하고 관리하는 헌법 기구이자 조직망을 **파일 시스템(File System)** 이라고 부릅니다. 

---

## 1. 운영체제별 파일 시스템의 대격돌

리눅스와 윈도우가 서로의 하드디스크를 꽂았을 때 포맷이 안 맞는다며 파일을 못 읽는 이유는, 이 '바둑판을 긋는 규칙' 채택이 아예 다르기 때문입니다. 

### 1) Windows 계열 포맷
* **FAT32 / exFAT:** 옛날 플로피디스크 시절부터 쓰던 구형 포맷입니다. 구조가 멍청하고 보안이랄 게 없지만, 윈도우/맥/리눅스 모든 기계에서 찰떡같이 인식이 되기 때문에 호환성이 100%인 'USB 메모리 전용 포맷'으로 쓰입니다.
* **NTFS:** 현대 윈도우(C드라이브)의 절대 지배자입니다. 정전이 나면 꼬인 파일을 역산술로 복구하는 '저널링' 기술이 탑재되어 안전합니다.

### 2) Linux 계열 포맷 (ext4 최강 천하)
* 리눅스는 `ext2`, `ext3`를 거쳐 궁극의 최신 진화형인 **`ext4`** 를 기본 표준 포맷으로 채택합니다. 
* 16TB 단위의 초대형 괴물 파일도 쪼개지지 않고 관리되며, 속도를 극대화하는 지연 할당 기법이 들어있어 엄청난 빅데이터 서버 베이스먼트로 쓰입니다.

---

## 2. 빙의의 마술: 마운트 (Mount)

윈도우는 USB를 꽂으면 내 PC에 `D드라이브` 나 `E드라이브` 처럼 문자열을 새로 파서 독립시켜 보여줍니다. 하지만 리눅스는 무조건 세계수 뿌리(루트 `/`) 하나에서 뻗어 나가는 잔가지(단일 파일 시스템) 통치 규칙을 고집합니다.

이를 해결하기 위해 밖에서 새로 들어온 이방인 USB나 추가 하드디스크(예: `/dev/sdb1`)를, 기존 리눅스 세계수 트리의 텅 빈 특정 나뭇가지 폴더(예: `/mnt/usb 폴더`)에 귀신처럼 찰싹 빙의시켜 버리는 작업을 **마운트(Mount)** 라고 부릅니다.
* 마운트가 성공하면 기존 폴더 속 내용은 가려지고, USB 안에 있던 영화 파일들이 `/mnt/usb/` 폴더 안으로 쏟아져 들어오며 접근이 가능해집니다.

## 3. 디스크 조각남 현상 (Fragmentation) 과 무결성 점검

하드디스크 바둑판에 파일을 저장하고 지우고를 몇 년간 반복하다 보면, 바둑판 중간중간 이빨이 빠진 빈 공간 조각들이 지저분하게 흩어집니다. 새로 10GB 영화를 받으면 이 흩어진 조각 공간들을 찾아서 땜빵식으로 갈기갈기 찢어서 저장해야 하므로, 옛날 윈도우즈는 하드 읽는 속도가 극악으로 느려지고 시스템이 정지(흔히 '디스크 조각 모음'이 필요했던 이유)되곤 했습니다.

* **최신 ext4 파워:** 리눅스 `ext4` 파일 시스템은 애초에 저장할 때부터 "미래에 파일 덩치가 커질지도 모르겠다" 싶으면 바둑판 주변 공간을 강제로 텅텅 비워두고 호위무사처럼 예약 선점하는 천재적인 알고리즘으로 설계되었습니다. 즉, 아무리 파일을 깔았다 지워도 리눅스 서버는 디스크 단편화가 거의 발생하지 않아 10년 넘게 포맷 없이 제 속도를 뽑아냅니다.

> **💡 하드디스크 외과 수술 3대 유틸리티**
> * **`fsck` (무결성 체크):** 정전으로 갑자기 서버가 뒤지면 하드 공간이 꼬입니다. 부팅될 때 이 명령어가 자동으로 돌면서, 퍼즐이 꼬인 부분을 스스로 잘라내어 봉합 수술을 합니다. (마운트가 해제된 쌩 하드에서 돌려야 안전)
> * **`badblocks` (시한부 검사):** 하드디스크의 자성 자체가 긁혀서 물리적으로 사망한 '배드섹터'가 있는지 싹 돌려보고 격리(블랙리스트) 처리합니다.
> * **`df -h` 와 `du -sh`:** 현재 남은 하드 전체 용량 볼 땐 `df`, 이 특정 폴더가 용량 얼마나 꿀꺽했는지 범인 색출할 땐 `du`를 씁니다.
