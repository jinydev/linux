# 인프라 확장 아키텍처: Web Server 와 WAS 

사용자의 브라우저(크롬)에서 날아온 HTTP 요청을 목적에 따라 분업하여 앞단과 뒷단에서 나누어 쳐내는 엔터프라이즈 환경 3-Tier 아키텍처의 필수 개념입니다.

---

## 1. 전방 수비대: Web Server (정적 배달기)
해커든 일반 고객이든 가리지 않고 최전선 80포트, 443(https) 포트에서 무차별적으로 날아오는 트래픽 폭격을 온몸으로 흡수해 주는 방패막입니다.

* **핵심 역할:** 변하지 않는 사진(.jpg), 화면 디자인(.css), 단순 대문 페이지(.html) 등 **'정적(Static) 컨텐츠'** 를 하드디스크에서 꺼내 고객의 얼굴에 재빨리 던져줍니다.
* **제품군:** 전 세계 웹 서버 시장의 군림자 `Nginx(엔진엑스)`, 고전의 명가 `Apache(아파치)`

## 2. 두뇌 연산반: WAS (동적 비즈니스 센터)
`WAS (Web Application Server)`는 DB와 접속해서 돈을 출금하거나, 자바(Java) 로직을 돌려서 오늘 로그인한 유저의 맞춤 쿠폰 스토리를 즉석에서 **'생성해 내는(Dynamic)'** 특수 미들웨어 특공대입니다.

* **동작 파이프라인:** 
  고객이 "내 계좌잔액 보여줘" 라고 누르면 ➡ 앞단의 `Web Server`가 "이건 연산이 필요하네?" 판단하고 ➡ 뒷단의 `WAS`로 토스 ➡ WAS가 DB 접속해서 잔고 10억 조립 ➡ HTML로 이쁘게 꾸며서 다시 Web Server로 반환 ➡ 고객 도착.
* **제품군:** 자바 진영의 영원한 친구 `Tomcat(톰캣)`, 기업형 상용 서버 `JEUS(제우스)`, `WebLogic`.
* **스프링 부트(Spring Boot) 시대:** 요즘은 자바 스프링으로 개발할 때 거대한 톰캣을 서버에 따로 안 깔아도, 그냥 `.jar` 실행 파일 배꼽에 마이크로 톰캣 내장이 탑재되어 딸려 올라갑니다.

---

## 3. Web Server 와 WAS 를 왜 2개로 물리적 격리를 시킬까?

초보 개발자들은 톰캣(WAS) 혼자서도 사진 파일 다 잘 주니까 서버 하나로 퉁치려 하지만 실무에서는 반드시 둘을 쪼개서 서버를 2단으로 세웁니다.

1. **과부하 폭발 방지 (정적/동적 부하 분산):** 
   무거운 DB 조회를 하고 있는 천재 외과 의사 WAS한테, 갑자기 유튜브 썸네일 수만 장을 열어달라고 요청하면 WAS 메인 CPU가 터집니다. 썸네일 같은 단순 노가다 작업은 앞단의 Nginx 병사들이 알아서 쳐내고 통과하게 만듭니다.
2. **소프트웨어 로드밸런싱 확장:** 
   이벤트 날 접속자가 터져나가면, 앞단에 Nginx 하나를 두고 뒷단에 복사된 톰캣 WAS를 5개, 10개씩 클러스터로 병렬 증식시켜서 트래픽 분산 스위칭(L4 라우팅처럼)을 해냅니다.
3. **해킹 방패막 망분리 구축:** 
   진짜 비즈니스 로직(돈, 유저 정보)을 가진 코드가 탑재된 WAS는 인터넷이 끊긴 사내 내부 가상망 깊은 곳에 꽁꽁 숨겨두고, 오직 최전방 웹 서버하고만 대화하게 만들면 해커의 다이렉트 침투가 100% 원천 봉쇄됩니다.
