# 프로그래밍 언어의 런타임 번역기: 컴파일(Compile) vs 인터프리터

인간이 영단어로 타이핑한 `if (num == 1) print("hello")` 라는 소스코드를, 0과 1밖에 모르는 멍청한 CPU의 전선에 전기로 지져 넣기 위해 '기계어'로 바꾸는 양대 번역 아키텍처 전쟁입니다.

---

## 1. 컴파일 철학 (번역가 - C, C++, Java, Go)

코드 1,000만 줄을 개발자가 다 짠 뒤, 빌드(Build) 버튼을 한 번 빡 누르면 **'컴파일러(Compiler)'** 라는 프로그램이 파일 전체 문법을 처음부터 끝까지 정밀 스캔하고 검사한 다음, 컴퓨터 전용의 완벽한 `.exe` 나 기계어 덩어리 캐리어를 한방에 뽑아내 버립니다. 

* **압도적 장점 (미친 속도):** 이미 번역과 검열이 100% 끝나서 만들어진 실행 파일 공구 상자이므로, 서버에서 무지성으로 실행만 하면 C/C++처럼 리눅스 시스템 위에서 빛의 속도로 돕니다. 연산 집약적인 서버의 심장, 게임 엔진 등에 쓰입니다.
* **단점 (오랜 빌드 시간):** 코드 딱 한 줄을 고쳤는데, 확인하려면 수 분에 걸쳐 전체 1,000만 줄을 다시 통째로 컴파일로 말아내야 합니다.

### [컴파일 파이프라인]
1. **전처리 (Preprocessing):** 소스에서 `#include` 매크로나 복붙할 부속 파일들을 하나로 쭉 합칩니다.
2. **구문/의미 분석 (Syntax/Semantic Analysis):** 변수명이 맞는지, if문 괄호가 안 닫혔는지 컴파일러 빨간 줄 에러를 철저하게 색출합니다. (이때 에러 나면 빌드가 폭파됩니다.)
3. **최적화 및 코드 생성:** "이 for문은 불필요하니까 쳐버리자" 스스로 코드를 정제한 후 어셈블리어와 최종 기계어(Target Code)를 생산합니다. 

---

## 2. 인터프리터 철학 (동시통역사 - Python, JS, Ruby)

전체를 다 번역해서 하나의 완성본 책으로 만드는 컴파일과 달리, **'인터프리터 엔진'** 이 켜져서 1번 줄 읽어 기계한테 명령 내리고, 2번 줄 읽어 명령 내리는 식의 즉각적인 '한 줄 번역 통역사' 기법입니다.

* **압도적 장점 (초고속 피드백):** 빌드/컴파일 과정이라는 게 아예 존재하지 않습니다. 파이썬 `.py` 텍스트 수정하고 `F5` 누르면 0.1초 만에 바로 돌아가서 결과를 확인합니다. 코딩과 테스트 사이의 피드백이 전광석화입니다. 
* **치명적 단점 (느려터진 속도):** 실행 중에 CPU한테 갈 때마다 매번 한 줄 한 줄 영어 단어를 기계어로 번역하며 돌아가야 하므로, 태생적으로 C언어(컴파일) 같은 속도를 감히 넘보지 못합니다. 런타임에 에러가 뻥뻥 터지기도 쉽습니다.

---

## 3. 혼합형 JIT (Just-In-Time) 의 등장

자바(Java)나 최신 자바스크립트 엔진(V8 브라우저 엔진)은 이 두 방식을 교묘히 합쳤습니다. 1차적으로 전체 코드를 바이트코드라는 중간 단계로 번역(컴파일)해 두고, 실행하는 순간에 필요한 놈만 기계어로 초스피드로 통역(인터프리트)해 캐싱해두어 번역 시간과 실행 속도를 동시에 사냥한 괴물 같은 기술입니다.
