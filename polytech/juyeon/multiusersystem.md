# 리눅스 다중 사용자 아키텍처 (Multi-User System)

윈도우(Windows)는 철저하게 마우스를 쥔 한 사람의 개인 단말기(Personal Computer) 철학으로 만들어졌지만, 리눅스는 태생부터 **거대한 하나의 메인프레임 서버에 전 세계 1,000명의 엔지니어가 동시에 접속해 각자의 방에서 작업하는 '다중 사용자(Multi-User)' 철학**으로 탄생했습니다.

---

## 1. 다중 사용자의 존재 이유 (서버 자원의 쉐어링)

서버용 CPU와 RAM은 천문학적으로 비쌉니다. 엔지니어 100명이 각자 깡통 PC로 컴파일을 시도하면 하루 종일 걸리지만, 1대의 초대형 슈퍼컴퓨터(리눅스)에 100개의 계정으로 접속해서 SSH 터미널 창만 띄워 통신하면 엄청난 컴퓨팅 파워를 나눠먹으며(Time-Sharing) 초고속으로 결과를 얻어냅니다. 

* **강력한 격리와 보안 (Sandboxing):** A라는 유저가 코드를 짜다가 서버 메모리를 터뜨려도, 자신의 할당 권한 안에서만 에러가 날 뿐, 옆 방에서 접속 중인 B유저의 작업이나 서버 전체가 죽어버리는 현상(블루스크린)을 원천 차단합니다. 

---

## 2. 권한의 계급구조 (유저 타이어)

수백 명이 한 서버를 공유하므로 철저한 신분 계급 통제가 필요합니다.

### 1) 신 (Root / UID 0)
모든 권한의 정점입니다. 다른 사람의 비밀번호를 없애버리거나, 시스템의 숨통을 끊는 자폭 명령어까지 단 1%의 제재 없이 먹혀들어 가는 무소불위의 계정입니다.

### 2) 서비스 시스템 데몬 계정 (UID 1 ~ 999)
아파치(`apache`)나 데이터베이스(`mysql`) 같은 프로그램들이 로그인할 때 쓰는 '가짜 투명 인간' 계정입니다. 보안을 위해 사람이 쉘(Shell)을 통해 접속하지 못하게 로그인 기능이 거세되어 있으며, 오직 백그라운드 프로그램이 권한을 빌려 쓸 때만 작동합니다.

### 3) 평민 계정 (Normal User / UID 1000 이상)
우리가 `adduser` 로 수동 생성하는 일반 개발자 계정입니다. 오직 자기 자신의 방(`/home/donghak`) 안에서만 제왕일 뿐, 옆 사람의 방을 들여다보거나 서버의 엔진 설정 폴더(`/etc`)를 고칠 권한은 아예 막혀있습니다. 

> **💡 sudo (슈퍼맨 변신망토)**
> 일반 평민이 잠깐 마우스 드라이버를 깔아야 할 때 root 비밀번호를 공유해 주면 회사가 망합니다. 그래서 특정 평민에게 `"네가 네 자신의 비밀번호를 한 번 더 치면, 앞으로 5분 동안만 root의 힘을 1회성으로 빙의시켜 줄게"` 라고 권한을 빌려주는 것이 바로 `sudo` 시스템입니다.
