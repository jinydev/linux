# 날것의 요리법: 타르볼(Tarball) 빌드와 소스 컴파일 구조

`apt-get install nginx` 처럼 잘 포장된 남의 리눅스 배포판 설치 파일(RPM, DEB)을 쓰는 시대지만, 특수한 서버 환경이나 최신 버전의 극단적인 버그 픽스를 위해 해커들처럼 **원시 소스코드 문자열 파일을 그대로 다운받아 내 리눅스 서버 기계어로 직접 구워버리는 '소스 컴파일 빌드'** 공정 아키텍처입니다.

---

## 1. 재료 다듬기 시스템: configure 

오픈소스 타르볼 파일(`nginx.tar.gz`)을 다운받아 압축을 풀면 폴더 안에 `configure` 라는 실행 녹색 파일이 우두커니 들어있습니다.

* **동작 (견적 내기):** `./configure` 를 치는 순간, 내 리눅스 서버의 환경(C++ 컴파일러가 깔려있는지, 운영체제가 우분투인지, 메모리 주소 체계가 몇 비트인지)을 쫙 스캔합니다. 만약 부품이나 라이브러리가 하나라도 없으면 여기서 빨간 에러를 뿜으며 빌드 견적 내기를 중단합니다. 
* **결과물 (`Makefile` 생성):** 스캔이 성공적으로 끝나면, 내 컴퓨터 환경에 아주 딱 맞춤복으로 재단된 레시피 지시서인 `Makefile` 을 생성해 줍니다. 

---

## 2. 끓이기 (Compile) 와 플레이팅 (Install)

견적서가 나왔으니 본격적으로 CPU를 100% 혹사시켜 기계어로 번역기를 돌립니다.

### `make` (단조 공정 / 컴파일과 링킹)
* 아까 만들어진 `Makefile` 레시피 지시서를 읽으면서, 실제 C언어 소스코드 텍스트 파일들을 미친 듯이 0과 1의 기계어 바이너리 파츠(Object 파일)로 통과 구워냅니다.
* **링킹(Linking):** 다 구워진 작은 부품 파일들을, 윈도우의 DLL이나 리눅스 커널의 공통 부품(라이브러리 공간)들과 전선으로 매듭묶어 연결해 하나의 온전한 초거대 실행 무기로 결합합니다.
* 엄청난 시간이 걸리는 작업이며, 끝났다고 시스템에 설치된 것은 아닙니다. 현재 폴더에 실행 파일이 덩그러니 구워진 상태입니다.

### `make install` (배치 작업)
* 갓 구워진 따끈따끈한 `nginx` 싱싱한 새 실행 파일과 관련 매뉴얼 문서 조각들을, 리눅스 시스템의 진짜 핵심 코어 디렉토리 파츠(예: `/usr/local/bin`, `/etc`) 등 제자리에 복사해서 강제 쑤셔 박아버립니다. 
* 이 순간부터 터미널 어디에서나 `nginx` 명령어가 시스템 풀파워로 동작하게 됩니다.

---

> **💡 인터프리터 언어(Python, JS)의 시대엔?**
> 이런 구시대의 살인적인 컴파일 지옥(configure -> make -> install)이 너무 피곤해서, 파이썬같이 컴파일(망치질) 없이 코드를 치자마자 0.1초 만에 실행(인터프리터)되는 언어가 대폭발 혁명을 일으켰습니다. 하지만 극강의 CPU 한계 돌파를 다루는 운영체제 커널 코어나 C언어 기반 엔진 코어들은 아직도 이 무식한 타르볼 원시 빌드법을 피할 수 없습니다.
