# 가상머신 망분리 아키텍처: 호스트 전용 어댑터 (Host-Only)

기업망 보안이나 로컬 웹 서버 환경 구성을 위해 가장 많이 쓰는 안전 네트워크 구축법입니다. Guest(버추얼박스 리눅스)가 밖의 진짜 외부 인터넷으로 나가는 길을 물리적으로 아예 끊어버리고, 오직 **Host(내 윈도우 본체) 와 Guest(가상 리눅스) 끼리만 통신**하게 묶어버리는 철저한 로컬 폐쇄망 세팅입니다.

---

## 1. 아키텍처 사상 (1:1 내부 통신망)

* **작동 구조:** Host(내 윈도우) 와 Guest(우분투) 사이에 투명한 가상 랜선 1가닥을 꼽아 직결 연결합니다.
* **네트워크 규칙:**
  * Guest -> Host (본체 PC로 접근) : **O (가능)**
  * Guest <- Host (본체 PC에서 가상머신 SSH 찌르기) : **O (가능)**
  * Guest <-> Guest (가상머신끼리 통신) : **O (가능)**
  * Guest <-> 인터넷 (태평양 외부 구글망) : **X (절대 뚫고 나갈 수 없음)**
* **장점:** VirtualBox 자체가 이 닫힌 망 안에서 소형 DHCP(IP 분배기) 라우터 역할을 해주어, 외부 망의 복잡한 간섭 없이 독립적인 데이터베이스 서버와 웹 서버 클러스터를 한 PC 세트장 안에 우아하게 구축할 수 있습니다.

---

## 2. 실전 트러블슈팅 (어댑터가 증발했을 때)

종종 버추얼박스에서 *'Failed to open/create the internal Network'* 에러를 뿜으며 호스트 전용망 세팅 자체가 먹통이 되는 경우가 자자합니다. 이때의 복구 엔지니어링 매뉴얼입니다.

### [증상 A: VBox 네트워크 드라이버의 체크 해제]
* 윈도우 방화벽이나 백신이 설치하며 드라이버를 무시한 경우입니다.
* 윈도우 `네트워크 연결(ncpa.cpl)` 제어판을 열어 가상의 VBox Host-Only Ethernet Adapter 우클릭 -> 속성에 들어갑니다.
* **Virtualbox NDIS6 Bridged Network Driver** 항목의 체크 박스가 해제되어 있으면 강제로 클릭하여 바인딩을 복원합니다.

### [증상 B: VirtualBox 네트워크 브릿지 파일 자체가 삭제된 경우]
* 가장 빈번한 치명타 에러입니다. 어댑터 추가 리스트에서 VBox 탭 자체가 날아간 현상입니다.
* **1차 복구:** `관리자 권한` 으로 VirtualBox를 재설치해서 시스템 어댑터를 다시 삽입시킵니다. 기존 가상머신 볼륨들(.vdi)은 포맷되지 않고 그대로 생존해 연동됩니다.
* **2차 복구 (수동 드라이버 강제 주입):**
  1. 윈도우 네트워크 어댑터 설정 창을 띄웁니다.
  2. [설치] 버튼 -> [서비스] 탭에서 [추가]를 클릭한 후, [디스크 있음]을 선택합니다.
  3. 찾아보기로 **`C:\Program Files\Oracle\VirtualBox\drivers\network\netlwf\`** 깊숙한 폴더로 잠입해 **`VBoxNetLwf.inf`** 커널 정보 파일을 직접 강제 캐치하여 오픈합니다.
  4. 재부팅하면 어댑터가 기적처럼 부활하며, VirtualBox 메뉴 내에서 `DHCP 서버 사용` 을 켜주면 복구가 완료됩니다.
