# 무중단 원격 제어 터미널: Telnet에서 SSH로 

데이터 센터 백색 소음이 울리는 추운 방 안으로 직접 걸어 들어가 리눅스 서버 키보드를 두드리는 엔지니어는 더 이상 없습니다. 내 따뜻한 거실 노트북에서, 저 멀리 랙에 꽂힌 리눅스 깡통 서버에 투명한 널빤지를 쏴서 터미널 제어권을 가로채는 '원격 접속 프로토콜' 디자인 아키텍처입니다.

---

## 1. 퇴출당한 고대 유물: Telnet (명령어 평문 탈취)

* **작동 구조 (포트 23):** 인터넷 초창기 원격 접속의 근본 프로토콜입니다. 
* **치명적 폐기 이유 (평문 공격):** 텔넷의 가장 강력한 지옥은, 내가 치는 `root` 아이디와 비밀번호 타이핑이 **'100% 생날것의 평문 텍스트'** 로 인터넷 허공을 날아간다는 점입니다. 해커가 중간에서 랜선을 스니핑(엿듣기) 툴로 잡아채면 내 서버 최고관리자 패스워드를 1초 만에 훔쳐냅니다. 이 참혹한 보안 취약점 때문에 현재 Telnet은 실무 망에서 100% 멸종당했습니다.

---

## 2. 철벽의 보안 터널: SSH (Secure Shell) 

텔넷 시대의 허술함을 박살 내고, 오늘날 전 세계 리눅스 엔지니어들이 서버를 지배하는 유일신이자 완벽한 산업 표준 원격 터미널 통신 프로토콜입니다. (Putty, Xshell 같은 클라이언트 프로그램으로 진입 시 사용)

* **작동 구조 (포트 22):** 
  가장 극강의 핵심은 **초강력 암호화 알고리즘** 입니다. 서버(리눅스)와 클라이언트(내 노트북)가 통과를 하기 전, 수학적으로 증명된 비대칭 키(개인키/공개키) 퍼즐을 서로 맞춰보는 Handshake 무결성 검증을 거칩니다. 검증이 성공하면 둘 사이에 터널이 영원히 폭파되지 않는 이상 오가는 모든 키보드 타자 데이터가 복원 불가능한 쓰레기 암호화 덩어리 해시로 송출됩니다. 해커가 통신을 낚아채도 해독이 불가능한 구조입니다.

### [실무 SSH 세팅 가이드 (Ubuntu)]
원격 아이피를 허용해 주려면 우분투 서버가 문을 열고 `sshd` 데몬 리스너가 잠복해야 합니다.
```bash
# 1. 문지기 오픈소스 SSH 서버 코어 설치
sudo apt-get -y install openssh-server

# 2. 문지기 서비스 가동 및 무한 부팅 자동화 설정 
sudo systemctl restart ssh
sudo systemctl enable ssh

# 3. 방화벽(UFW) 장벽에 22번 포트 특수 직결 구멍 폭파
sudo ufw allow 22/tcp
```

## 3. 원격 통신의 생존 네비게이터: Port Forwarding

내가 멀리 떨어진 회사 리눅스 서버에 SSH(22번 포트)로 접속하려 시도할 때, 무조건 회사 사무실 앞단에 있는 '공유기(라우터)' 문지기 장벽에 1차로 부딪혀 폭사당합니다. 이 공유기에게 '이건 해커가 아니라 합법적 직원이니까 포트 뒷구멍으로 바로 패스시켜 줘' 라고 룰을 세팅하는 것이 **포트 포워딩(Port Forwarding)** 아키텍처입니다.

* **동작 원리:** 공유기는 6만 개의 포트 구멍을 들고 있습니다. "회사의 외부 공유기 대표 IP의 **방 번호(Port)** 로 접속이 찔리면, 묻지도 따지지도 말고 저 구석에 있는 내 가상머신 우분투 서버 내부 IP의 특정 **포트 번호** 로 토스해 줘" 라며 물리적 맵핑을 걸어주는 네트워크 조작 나침반 기술입니다.
