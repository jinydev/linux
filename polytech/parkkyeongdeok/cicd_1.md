# 소프트웨어 공장 조립 라인: CI/CD (지속적 통합/배포)

개발자가 코드를 짜서 Git에 올리면, 그 코드가 사람이 전혀 개입하지 않는 컨베이어 벨트를 타고 자동으로 서버로 끌려가 불순물(버그)을 테스트당하고, 도커 이미지로 구워진 다음 프로덕션 서버로 자동 방출되어 고객 스마트폰에 접속되기까지의 전 과정을 자동화한 **DevOps 인프라 엔지니어링의 심장**입니다.

---

## 1. CI (Continuous Integration): 지속적인 코드 통합 투입

여러 명의 개발자들이 짜낸 파편화된 소스 코드들이 Git 마스터 브랜치에 합쳐질 때마다 핏줄처럼 엮여서 폭발(충돌)하지 않는지 기계가 자동으로 검증하는 단계입니다.

* **동작 파이프라인 트리거:** 개발자가 깃허브(GitHub)에 코드를 `git push` 로 던지는 순간, 센서가 코드를 가로채서 젠킨스(Jenkins) 등의 무인 공장 CI 서버로 즉시 끌고 들어갑니다.
* **자동 빌드 & 린트 & 테스트:** 
  사람이 직접 로컬 PC에서 버튼을 눌러 테스트해 보던 과거와 다릅니다. CI 서버가 코드를 즉석에서 가상 환경으로 컴파일(Build)로 조립하고, 문법 악취가 나는지 스캐닝(Lint)하며, 내가 짜놓은 수천 개의 단위 테스트(Unit Test)를 1초 만에 돌려 모조리 합격해야만 코드를 "안전 자산" 으로 판정합니다.
* **에러 알림:** 만약 테스트가 단 하나라도 실패하면 즉시 슬랙(Slack)으로 에러 알람을 쏴서 그 쓰레기 코드가 메인 서버에 섞이는 걸 방어막 쳐 내버립니다.

---

## 2. CD (Continuous Deployment): 지속적인 강제 배포 

CI 컨베이어 벨트 심사를 통과해 "이 코드는 무결함이 인증됨" 도장이 찍힌 결과물을, 실제 전 세계인이 접속 중인 살아있는 AWS 상용 서버에 무중단으로 강제 꽂아 넣어버리는 투척 파이프라인입니다.

* **배포 자동화의 마법:** 과거엔 밤 12시에 서비스를 닫고 인프라 운영자가 FTP로 서버에 파일을 복사해서 서버를 재부팅시켰습니다. CD 파이프라인은 CI 로 조립된 깨끗한 `.jar` 빌드 팩이나 Docker 이미지를 낚아채서, **AWS CodeDeploy**나 **Kubernetes** 클러스터에 롤링(Rolling) 또는 블루/그린(Blue/Green) 방식으로 알아서 무중단 스무스 교체 배포를 때려 넣습니다.

---

## 3. DevOps의 파괴적 혁신: CI/CD 적용 전과 후

* **적용 전 (야성의 시대):** 개발자가 코드를 로컬에서 짠다 -> Git에 올린다 -> 운영팀에 "배포해 주세요" 메일을 보낸다 -> 운영팀이 서버에 직접 다운받아서 수동으로 데몬을 껐다 킨다 -> 서버가 에러를 뿜으며 뒤진다 (개발자 PC에선 됐었는데요?) -> 밤새도록 롤백 대참사가 일어난다.
* **적용 후 (초자동화 시대):** 개발자가 코드를 `Push` 한다 -> 집으로 퇴근한다 -> 그 사이 클라우드 중앙 CI/CD 봇 서버가 코드를 빼앗아 공장 기계를 돌려 10만 개의 테스트를 통과시킨 후 AWS 라이브 서버에 자동으로 교체 배포를 끝마쳐 버린다. 에러가 나면 봇이 자동으로 `Push`를 드랍시켜버리므로 절대 메인 서버가 죽지 않는다.
