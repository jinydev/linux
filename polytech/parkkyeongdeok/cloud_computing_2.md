# 클라우드의 권한 분할 3계층 아키텍처: IaaS - PaaS - SaaS

AWS나 Google Cloud를 쓸 때, 내가 아마존에게 "깡통 기계 부품만 빌릴 것인가" 아니면 "코딩할 판(Platform)까지 빌릴 것인가", 아니면 아예 "완성된 엑셀/워드 프로그램을 빌릴 것인가"를 선택하는 클라우드 서비스 공급 티어(Tier) 모형입니다.

---

## 1. IaaS (Infrastructure as a Service): 깡통 뼈대 렌탈

* **지원 영역:** 서버 껍데기 기계(CPU, RAM, HDD 하드), 가상 네트워크 랜선만 빌려줍니다.
* **사용자 권한 (매운맛):** AWS EC2 인스턴스가 대표적입니다. 아마존이 검은색 터미널 창(Linux 깡통)만 덜렁 던져주면, 내가 직접 그 안에 Java도 깔고, 방화벽도 설정하고, DB도 얹어서 바닥부터 싹 다 구워내야 합니다.
* **장점:** 내 마음대로 자유로운 OS/서버 통제가 가능하나 인프라 관리 고통이 큽니다.

---

## 2. PaaS (Platform as a Service): 코딩판 제공

* **지원 영역:** 깡통 기계 위에 **'운영체제(OS) + 미들웨어(Java, Python) + 데이터베이스(DB 엔드포인트)'** 까지 전부 다 미리 설치해 놓은 세팅 완료된 깔끔한 도마를 렌탈해 줍니다.
* **사용자 권한 (순한맛):** 대표적인 예로 AWS Elastic Beanstalk이나 Heroku가 있습니다. 나는 오직 내가 짠 소스코드(Source Code *.jar 파일) 데이터만 휙 집어 던지면, PaaS가 그걸 덥석 물고 알아서 컴파일해서 사이트를 띄워줍니다. 
* **장점:** "나는 서버 세팅은 모르겠고, 프로그래밍에만 집중할래!" 하는 모던 백엔드 개발 팀에 최적입니다.

---

## 3. SaaS (Software as a Service): 완성품 임대

* **지원 영역:** 소프트웨어의 **모든 것**을 완성해서 브라우저로 쏴줍니다.
* **사용자 권한 (초보자맛):** 구글 닥스(Google Docs), 넷플릭스, 슬랙, 네이버 메일 등. 개발 코딩이 1도 없고 돈 내고 아이디/비번 치고 들어가서 버튼만 클릭해 사용하면 끝입니다.

---

## 4. 클라우드 구축 전선: 4대 배치 모델 (Deployment Model)

이 클라우드 구름을 **누구 소유로 어디에 띄울 것인가?** 에 대한 거대 기업들의 지정학적 아키텍처 전장입니다.

* **Public Cloud (공용 클라우드):** AWS, Azure 처럼 거대한 남의 집(아마존 데이터센터) 아파트에 들어가 월세를 내고 전 세계 남들과 같이 부대끼며 살아가는 렌탈 클라우드입니다. 
* **Private Cloud (프라이빗 클라우드 - 온프레미스 연계):** 금융권이나 정부 기관처럼 보안이 목숨보다 중요해 퍼블릭 아파트로 들어갈 수 없을 때 씁니다. 회사 내부 지하 서버실에 폐쇄망을 깔고 '우리 회사 직원만 접속 가능한' 사내 전용 강력한 우물 안 클라우드 뼈대를 직접 구축하는 것(또는 전용 호스팅)입니다.
* **Hybrid Cloud (하이브리드 클라우드 - 돌연변이):** 가장 고도화된 실무 아키텍처입니다. **고객 평문 스토리지(Public)** 는 AWS에 띄워 놓고, **초강력 결제/보안 DB 센터(Private)** 는 우리 회사 건물 내부에 띄워서, 두 개를 보안 전용선 물리 랜선 경로로 강제로 연결해 버리는 하프 앤 하프(반인반수) 혼종 결합 구성입니다.
