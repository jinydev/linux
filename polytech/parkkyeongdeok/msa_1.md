# 레거시의 해체와 독립: MSA (마이크로서비스 아키텍처)

거대한 쇼핑몰 서버를 운영할 때, 모든 기능(게시판, 결제, 회원가입)을 하나의 거대한 건물 안에 통째로 쑤셔 박아 넣고 컴파일해버리는 과거의 '모놀리식(Monolithic)' 개발 방식의 무거움을 부숴버리고, **각 기능들을 1~2명이 관리할 수 있는 손톱만 한 마이크로 단위의 미니 서버들로 수십 개 쪼개서 각각 띄워놓는(MSA)** 현대 클라우드 설계 패러다임입니다.

---

## 1. 거인의 죽음: Monolithic Architecture의 한계

하나의 코드로 모든 기능이 단일 패키징(예: 하나의 거대한 `.war` 파일)되어 묶여있는 전통적인 구조입니다. 코드가 천만 줄이 넘어가기 시작하면 시스템은 지옥의 스파게티로 돌변합니다.

* **동반 폭사 (치명적 결속):** 게시판 조회수 카운트 코드를 수정하다가 생긴 버그 하나 때문에, 프로그램에 연결된 회원가입과 결제 로직까지 전체 서버가 블루스크린을 띄우며 동시에 터져버립니다.
* **배포의 공포 (시간 급증):** 오타 한 줄을 고쳐서 서비스에 반영하려 해도, 이 묶여있는 거대한 코드를 다시 빌드하고 껐다 켜는 데 30분이 걸립니다. 
* **스케일 아웃의 낭비:** 블랙 프라이데이에 '결제' 트래픽만 폭발할 때, 결제 모듈만 메모리를 늘려 띄울 수가 없어서 무거운 전체 쇼핑몰 프로그램 자체를 복제해야 하는 자원 낭비가 극에 달합니다.

---

## 2. 서비스 세포 분열: MSA (MicroService Architecture)

모놀리식의 끔찍한 결합도를 찢어버리기 위해 도래한 사상입니다. 기능별(회원 서버, 결제 서버, 게시판 서버 등등)로 도커(Docker) 컨테이너 안에 개별적인 미니 깡통 서버를 하나씩 배정해 완전히 찢어버립니다.

* **독립된 바벨탑 (API 통신):** 각 서버들은 내부 로직을 절대 공유하지 않습니다. 자바 서버든 파이썬 서버든 각자의 DB를 따로 갖고 생존합니다. 회원 서버가 결제 서버의 정보가 필요하면 오직 **REST API 호출** 이나 **Kafka Message Stream(메시지 큐)** 라는 네트워크 우편을 통해서만 정중하게 데이터를 요청해야 합니다.

### [MSA가 가져다준 개발 공장의 파괴적 혁신]
1. **버그 격리 (무적의 부분 방탄):** 결제 서버에 메모리 누수가 발생해 터져서 죽어버리더라도, 결제만 안 될 뿐 게시판 서버와 로그인 서버는 전혀 다른 물리 깡통 서버이므로 아무 일 없다는 듯이 쾌적하게 돌아갑니다.
2. **이질적 기술의 융합 (Polyglot):** 하나의 프로젝트 안에서, 뷰가 잦은 컨텐츠 서버는 가벼운 Node.js로, 중요한 금융 로직이 담긴 결제 서버는 견고한 Spring Boot(JAVA) 로, AI 분석 서버는 Python으로 각 팀이 마음대로 언어와 DB 포맷을 입맛대로 바꿔 개발해도 전혀 문제가 없습니다. API 언어만 맞추면 되기 때문입니다.
3. **극한의 ス케일 아웃 (민첩성):** 이벤트가 터져 '결제' 시스템만 불타오를 때, 결제 서버 깡통만 100개로 무한 클론 생성(오토 스케일링)하여 막아내고, 이벤트가 끝나면 다시 1개로 확 줄이는 클라우드 원형 인프라에 가장 최적화되어 있습니다.

---

## 3. MSA 도입의 핏빛 딜레마 (Trade-off)

넷플릭스, 아마존처럼 우아해 보이지만 인프라 엔지니어가 겪어야 할 지옥의 난이도가 도사리고 있습니다.

* **통신의 악몽 (Latency):** 모놀리식처럼 함수 호출 한방(0.001초)에 끝나던 로직이, MSA는 물리적 인터넷 랜선을 타고 다른 서버로 API HTTP 통신을 날려 응답을 받아와야 하므로 필연적인 네트워크 딜레이 트래픽 비용이 작렬합니다.
* **글로벌 트랜잭션의 파탄:** 결제는 성공했는데, 배송 서버에 API를 찌르는 중간에 네트워크가 끊겨버리면 데이터 정합성(DB 일치)이 박살 납니다. 이 분산 서버들끼리의 이중 복구(Saga Pattern 등)를 구현하는 설계 난이도는 끔찍하게 높습니다.
* **디버깅 헬 (에러 추적 불가):** 에러가 났을 때, 원인을 찾기 위해 A 서버, B 서버, C 서버의 로그 수만 줄을 지도를 그려가며 추적(Trace)해야 하는 막연한 고통이 수반됩니다.
