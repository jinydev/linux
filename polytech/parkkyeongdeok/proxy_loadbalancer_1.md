# 인프라 앞단 방패 아키텍처: 프록시(Proxy)와 로드밸런서(LB)

외부에서 집요하게 날아오는 트래픽(해커 공격포함)이 내부 결제 서버를 직접 때리게 놔두는 짓은 서버를 파괴해 달라고 비는 것과 같습니다. 인터넷 망과 내 서버 깡통들 정중앙(목구멍)에 방패를 깔아두고, **'내가 대신 너의 요청을 받아서 (대리-Proxy)' 뿌려주거나 찢어주는(분산-Balance)** 최전방 인프라 방파제 컴포넌트입니다.

---

## 1. 포워드 프록시 (Forward Proxy) : 우리 부서를 가려주는 외벽

일반적으로 기업망 사무실 내부에서 외부 인터넷으로 빠져나갈 때, 즉 **사내망 클라이언트 앞단** 에 깔아놓는 캐싱용 대리 문지기입니다.

* **동작 원리 (숨기기):** 우리 회사 직원 컴퓨터 수만 대가 바깥 구글 서버에 접속 시, 인터넷 선에서 구글이 이 IP들을 분석하면 '아! A직원은 이 사이트를 봤고 B직원은 이걸 봤구나' 라고 역추적 식별이 됩니다.
  이를 방어하기 위해 직원 브라우저 설정에 '프록시 IP'를 먹여두면, 직원의 IP는 완전히 가려진 채 모든 네트워크가 **'포워드 프록시' 라는 대표자 단 1명의 IP로만 둔갑하여 밖으로 튀어나갑니다.** 구글 서버는 오직 프록시의 접속만 관측합니다 (익명성 및 우회 VPN 특성 원리).
* **캐시 증폭(Caching):** 동일한 부서 직원 100명이 네이버 메인 뉴스에 접속할 때마다 바깥으로 나가는 건 트래픽 바보짓입니다. 포워드 프록시가 메인 페이지 그림을 자기 배 안에 적재(Cache)해 놓고, 두 번째 직원이 네이버를 부르면 밖으로 나가지 않고 자기 배 안에서 0.001초 만에 뱉어나 화면에 쏴줍니다.

---

## 2. 리버스 프록시 (Reverse Proxy) : 우리 서버를 감싸는 금고

클라우드 백엔드 환경에서 반드시 Nginx(엔진엑스)라는 방어막이 달고 사는 포지션입니다. **나의 소중한 서비스 운영 서버(결제망 등 DB) 가장 최앞단** 에 세우는 수문장입니다.

* **동작 원리 (서버 IP 은닉):** 클라이언트가 내 서비스를 해킹하기 위해 직접 내부 톰캣 WAS 서버 IP나 스프링 부트 포트를 찌르려고 해도 불가능합니다. 클라이언트의 렌더링 찌르기는 무조건 문지기 리버스 프록시 IP 1대에서 막혀버리며, 그 프록시가 적폐/악성 코드를 필터링한 후, **지들만 아는 지하실 암호 네트워크로 은밀하게 뒷단 톰캣에 다리를 넘겨 응답을 훔쳐와서 돌려줍니다.** 실제 백엔드 서버의 민낯은 인터넷 세상 어디에서도 영원히 조회되지 않는 완벽한 방탄유리가 생성됩니다.

---

## 3. 부하 분할의 마법: 로드밸런서 (Load Balancer)

하나의 서버에 천만 명의 이벤트 트래픽이 쏟아지면 메모리가 터져 폭사합니다. 이를 방어하기 위해, 서버 1개의 CPU/RAM 쇳덩어리를 늘리는 하드 코어 짓(Scale-Up)을 포기하고, 그저 똑같이 가벼운 깡통 인스턴스 서버 100대를 복제(Scale-Out)해 놓은 뒤 **로드밸런서(LB)** 라는 분배/교도관을 가장 최전방 교차로에 대기시킵니다. 
"1번 고객은 A 서버로, 2번 고객은 B 서버로" 트래픽 물줄기를 공평하게 칼같이 찢어버립니다. (이를 무분별하게 퍼붓는 라운드 로빈 등 다양한 알고리즘 기법이 있습니다.)

### [L4 로드밸런서 (무식한 고속 택배 기사)]
* 인터넷 규약 4계층(Transport)인 **TCP/UDP, IP 주소, 포트 번호** 만을 보고 트래픽을 나눠줍니다.
* 택배 상자의 내용물(데이터)은 볼 줄 모르고, 박스 겉표지의 '포장지 라벨 아이피' 만 보고 미친 듯이 A/B/C 서버 창고로 던져 나릅니다. 연산을 깊게 안 하므로 트래픽 처리 속도가 광속에 가깝게 폭발적입니다.

### [L7 로드밸런서 (디테일한 통관 검사원)]
* 가장 상위인 7계층(Application)인 **HTTP 헤더, URL 주소, 쿠키, JSON 페이로드 내용물** 속살까지 완전히 다 까보고 나서 서버를 나눠 꽂아주는 문지기입니다.
* `site.com/image/*` 를 불렀어? 너는 '이미지 전용 서버' 로 가! `site.com/video/*` 를 불렀네? 너는 '스트리밍 무거운 전용 서버' 로 가! 라며 컨텐츠 성격에 맞게 길을 미세 분할해 찢어주거나, 이 안에 든 악성 해킹 코드 패턴을 검열해 단칼에 차단(WAF 방화벽 연계 등)할 수 있는 압도적인 디테일 유연성을 제공합니다. (당연히 택배를 일일이 상자 까서 봐야 하므로 연산 비용이 더 듭니다.)
