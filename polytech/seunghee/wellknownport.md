# L4 계층의 트래픽 라우팅 목적지: 포트(Port) 번호 아키텍처

IP(인터넷 프로토콜)가 수백 킬로미터 밖의 무작위 '건물(컴퓨터/서버)' 주소까지 무사히 도착하게 만들어 준다면, **포트(Port)** 넘버는 그 아파트 안의 수천 개 '호실(방 번호)' 중 정확히 어디로 배달할지를 찾아 들어가는 네트워크 계층(L4 Transport Layer)의 핵심 논리적 종단점 개념입니다.

IP 주소를 치고 우분투 서버 1개에 들어왔을 뿐인데, 그 안에는 `웹서버(Nginx)`와 `데이터베이스(MySQL)`와 `원격제어(SSH)` 등 수천 개의 데몬 서비스 애플리케이션 뇌파들이 돌아가고 있습니다. 이 혼란스러운 멀티태스킹 프로세스 교통량을 교통 체증 없이 정확히 찢어 분리 배송(Bind)해 주는 것이 포트의 임무입니다.

## 1. Well-Known Ports: 전 우주적 공인 약속 번호 (0~1023번)

포트 번호는 0번부터 대략 65535번까지 존재하지만, 이 중에서 **가장 앞단의 0~1023번까지** 는 이미 IT 렌더링 개척자들이 "이 번호들은 전 세계 공통의 특정 통신 규약으로만 고정해서 몰빵 쓰자!" 라고 약속해 버린, 시스템 루트 레벨 예약 성역 구역입니다.

URL 주소를 브라우저에 칠 때 포트 번호를 입력하지 않아도 자동으로 접속되는 이유는, 웹은 암묵적으로 80(HTTP)번과 443(HTTPS)번을 향해 돌진하도록 프로그래밍되어 있기 때문입니다.

### [엔지니어 필수 암기 7대 포트 병기]
1. **`21 (FTP)`:** 옛날 보안 개나 준 단순 파일 업로드 전송 채널 (잘 안 씀).
2. **`22 (SSH)`:** 내가 서버를 씹고 뜯고 조종하기 위해 진입하는 절대 무결성 해킹 터널. 서버 보안의 성지.
3. **`25 (SMTP)`:** 구글 / 네이버 메일을 날려 보낼 때 쓰는 이메일 우체국 채널. 
4. **`53 (DNS)`:** `naver.com` 문자 주소를 숫자인 IP 주소로 물어보고 변환받는 IP 룩업 상담소 채널.
5. **`80 (HTTP)`:** 암호화되지 않은 투명한 해킹 위험 평문 세계(WWW 사이트). 브라우저의 기본 문.
6. **`443 (HTTPS)`:** 무적 방패 보안 인증서(SSL/TLS)가 발라져서 모든 패킷이 꼬여 날아가는 안전한 브라우저 사이트 문.
7. **`3389 (RDP)`:** 윈도우 원격 데스크톱을 띄울 때 쳐들어가는 화면 공유 GUI 문열림 구역.

## 2. Registered & Dynamic Ports: 데몬과 스프링의 전쟁터

### [데이터베이스와 데몬의 고정 영토 구역 (1024~49151번 이상)]
시스템 급의 절대 권위 포트(1023) 뒷자리 번호들은 대표적으로 톰캣이나 오라클, MySQL 같은 미들웨어나 데이터베이스들이 포진해서 선점 싸움을 하는 번호 구역입니다. (충돌 시 에러를 뿜으며 실행 거부 - "Port Already In Use")

* **`1521 (Oracle DB)` / `3306 (MySQL)` / `5432 (PostgreSQL)`:** 
 백엔드 서버가 DB 심장부에 쿼리를 꽂아 넣기 위해 질주하는 메인 데이터베이스 수문.
* **`8080 (Tomcat / Spring / 비공식 Web)`:** 
 앞단에 살아있는 진짜 웹 80 포트를 점령시키기는 부담스러우니, 그 뒤에 몰래 테스트용이나 WAS 백엔드 내부 통신용으로 개발자들이 사랑해 마지않는 굴뚝 구역. 리버스 프록시(Nginx)가 80으로 다 맞은 뒤 암흑 통로로 8080으로 우회 연결해 줍니다.
