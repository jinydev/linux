# 협업의 끔찍한 충돌 방어막: 원격 동기화 (Fetch vs Pull)

내가 컴퓨터(Local)에서 코딩을 하고 있을 때, 동료 개발자가 나 몰래 우리 공용 깃허브 서버(Remote - origin/master)에 자기가 짠 코드를 먼저 `push`로 밀어 넣어버렸습니다.
이 사실을 모른 채 내가 내 코드를 서버로 `push` 하려 하면, 서버는 "니 코드 구버전이야. 최신 내역부터 다운받아!" 라며 튕겨냅니다. 이때 외부의 코드를 내 컴퓨터로 강제로 당겨오는 생존 명령어 두루마리입니다.

---

## 1. 소극적 염탐(조회): `git fetch`

원격 저장소(GitHub)에 있는 동료의 최신 업데이트 코드를 내 컴퓨터로 몰래 **가져오기만** 하고, 내 작업물(Local)에는 절대 섞지 않는(반영하지 않는) 굉장히 방어적인 명령어입니다. 

* **작동 렌더링:** `git fetch origin` 을 치면 동료의 코드가 다운로드는 되지만 랩핑되어 대기합니다.
* **실무 활용 (안전한 리뷰):** 만약 동료의 코드가 쓰레기라서 내 코드까지 망칠까 두려울 때 씁니다. 일단 `fetch` 로 가져온 뒤, `git diff HEAD origin/master` 로 동료가 짠 코드를 내 코드와 비교(염탐)해 봅니다. 코드가 안전하다고 확신이 들었을 때 그제야 수동으로 `git merge` 를 때려서 섞습니다.

---

## 2. 극단적 밀어붙이기(병합): `git pull`

개발자들이 가장 많이 쓰면서도 방심하면 코드를 터뜨려버리는 무자비한 명령어입니다. 원격 저장소의 최신 내역을 내 컴퓨터로 다운받는 즉시, **내 작업 공간의 코드와 강제로 퓨전(Merge)시켜 버립니다.**

* **아키텍처 로직:** `git pull` = `git fetch (염탐)` + `git merge (강제 결합)` 이 한방에 연사로 날아가는 매크로 명령어입니다.
* **치명적 위험성 (충돌 / Conflict):** 만약 나와 동료가 **똑같은 파일의 똑같은 15번 줄** 을 서로 다른 코드로 수정해 놓았다면? `git pull` 을 당기는 순간 Git 시스템이 "둘 중에 누구 코드로 합칠지 나도 몰라!" 라며 파업을 일으키는 무시무시한 **Merge Conflict (충돌 지옥)** 에 빠지게 됩니다. (결국 개발자가 직접 텍스트를 열어 손으로 합쳐야 함)
