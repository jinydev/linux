# 인프라 전송의 모달 GUI: FTP 프로토콜과 FileZilla

리눅스 터미널의 시꺼먼 화면에서 `scp` 나 `rsync` 같은 텍스트 코드 명령어만 쳐서 AWS 서버로 수백 개의 파일과 10기가짜리 폴더 덩어리를 밀어 넣는 것은 개발자에게도 지옥 같은 작업입니다. 이를 마우스 드래그 앤 드롭(Drag & Drop)으로 렌더링 맵핑해주는 것이 21게이트(FTP 통신) 클라이언트 기술입니다.

---

## 1. FTP (파일 전송 프로토콜)의 민낯
단순 브라우저를 띄우는 80번(HTTP 웹) 포트와 달리, 목적 자체가 '파일 송수신' 에 특화된 대용량 트럭 수송 포트입니다. 

* 네트워크 인프라에서 서버-클라이언트 아키텍처로 구현되어 작동하며, 리눅스 서버 쪽에 `vsftpd` 같은 데몬 서비스 백그라운드가 돌고 있어야 내 윈도우(Client)에서 빨대로 꽂아 자료를 던져 넣을 수 있습니다.
* **치명적 결함:** 텔넷 급의 날것의 평문 텍스트 통신을 주로 베이스로 쓰기 때문에, 최근의 인프라 서버는 FTP를 봉쇄하고 RSA 암호가 발라진 SFTP(SSH 파일 전송 터널) 루트만 제한적으로 열리도록 강제하는 추세입니다.

---

## 2. 파일질라(FileZilla) 클라이언트 아키텍처
전 세계 1위의 점유율을 장악하고 있는 무료 오픈소스 시각화 FTP 접속 툴입니다. (MS 윈도우, mac, 리눅스 모두 호환). 

### 코어 활용 매커니즘 렌더링
파일질라는 단순 파일 복사를 넘어서, 엔지니어들이 대용량 백엔드 트래픽 이관 시 마주하는 병목(Error)과 커넥션 끊어짐 방어를 완벽하게 서포트하는 멀티스레드 괴물 클라이언트입니다. 

1. **이어받기(Resume) 뼈대:** 밤새 50GB 패치 파일을 리눅스로 전송하다가 랜선이 살짝 뽑혀 뻑이 나도 파일질라는 죽지 않습니다. 처음부터 다시 업로드하지 않고 끊어진 비트 단위 그 지점부터 연결을 재수립하여 밀어붙이는 무결성 방어 회로를 갖춥니다.
2. **동시 다발 커넥터 처리:** 파일 1만 개를 올릴 때 1개씩이 아니라, 서버 통로를 10번씩 다중으로 문어발로 따내어 동시에 병렬 프로세싱을 조지는 트래픽 부하 최적화 스펙을 지원합니다.
3. **분할 인터페이스 구조:** 
   *(파일질라 콘솔에 IP, 아이디, 비밀번호(192.168.10.x / root) 를 호스트 타겟에 박고 22번 포트(SFTP)로 Connect 승인 트리거를 누르면 아래 GUI 모델이 펼쳐집니다)*
   - **왼쪽 컴포넌트:** 내 윈도우 본체 PC의 폴더 디렉토리 (보내는 곳).
   - **오른쪽 컴포넌트:** 지구 반대편의 AWS 리눅스 서버 디렉토리 (받는 곳).
   - 마우스로 잡고 오른쪽으로 던지거나 긁어오면 끝입니다.
