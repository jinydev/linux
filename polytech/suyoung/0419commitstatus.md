# 인프라 코드의 생존 여부 검사기: Git Status 의 심층 해부

`git status`는 내 로컬 폴더(Working Copy)와 깃허브가 서로 얼마나 어긋나고 변위가 일어났는지 시각적으로 콘솔에 쏴주는 렌더링 나침반입니다.

특히 개발을 하다 보면 내가 어제 짰던 파일들이 `빨간색` 으로 나타났다가 `초록색` 으로 변하고 결재(Commit)를 기다리는 치명적인 3계층 생태계 뷰를 확인할 수 있습니다.

---

## 1. 3대 저장 컴포넌트의 위상 대립 교차

Git이 내 터미널 환경에 `클린(Clean / nothing to commit)` 하다고 백기를 드는 절대 평화 조건은, 아래의 3개 레이어 구역 내부 코드가 1바이트의 오차도 없이 100% 똑같이 동기화 맵핑되었을 때뿐입니다.

1. **Working Directory (로컬 본체):** 실제 내 윈도우에 깔려있는 생생한 파일 소스코드.
2. **Index (Staging Area 중간층):** `git add` 장부를 통해 다음에 깃허브에 날아갈 대기 표를 끊어둔 파일들의 버퍼링 구역.
3. **HEAD (Repository 최신 커밋):** 가장 최후에 확정 결재가 떨어져 저장소 객체에 굳어버린 과거 시점의 화석 코드.

---

## 2. 붉은색의 경고 (Modified & Untracked) 상태

아키텍처의 평화가 깨지고, 로컬 텍스트(1번)가 변경되어 깃의 동기화 장부(2/3번) 간에 불일치(Mismatch)가 발생해 붉은색 에러가 튀는 상태입니다.

* **`Untracked files` (미행 금지 유령 파일):**
  로컬 폴더(1번)에 처음 보는 생소한 코드 파일을 만들었지만, Git의 눈(Index 장부)에는 아예 존재 자체가 부정된 추적망 밖의 아웃사이더 깡통 구역입니다. 
* **`Changes not staged for commit` (추적 중인 반란 파일):**
  예전에 `add` 도 하고 `commit` 도 잘하던 파일인데, 내가 오늘 그 코드를 5줄 정도 무단으로 삭제 조작해 버린 상태입니다 (Modified). 로컬(1)과 최신 버퍼링 장부(2) 간의 코드가 충돌하여 불일치가 터져 빨간 경고를 내뿜습니다.

---

## 3. 초록색의 승인 대기열 (Staged) 상태

위의 붉은 반란군 코드들을 진압하기 위해 우리가 `$ git add` 를 때리면 일어나는 변위 매커니즘 렌더링입니다.

* **`Changes to be committed` (결재 대기열 승급):**
  로컬(1번)에서 수만 줄을 고쳤던 간에, `add` 명령을 통해 그 수정본을 모조리 Index 버퍼(2번)에 욱여넣어 장부 갱신을 끝마친 녹색 평화 상태입니다. 
  다시 말해 (1번 == 2번) 코드는 똑같아졌지만, 아직 최종 화석 코드 격인 (3번 HEAD) 보다는 진보해 있는 상태이므로, "빨리 최종 서명 명령(`git commit`)을 때려서 서버 장부에 박제시켜라!" 라고 알림을 쏴주는 결재 대기 워크플로우 큐(Queue)를 나타냅니다.
