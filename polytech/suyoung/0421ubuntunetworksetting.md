# 가상의 인프라 랜선을 잘라라: 하이퍼바이저 (VirtualBox) 네트워크론

로컬 윈도우(Host) 안에 여러 대의 우분투 가상머신 서버(Guest)를 올렸을 때, 이 가짜 서버들이 바깥 구글 인터넷망과 통신하게 뚫어줄 건지, 아니면 완전 독립된 밀폐망(보안 구역)에 가둘 건지를 세팅하는 가짜 랜선 스위치 렌더링 아키텍처입니다.

---

## 1. 4대 가상 랜선 맵핑 어댑터 구조

### [NAT (Network Address Translation - 신분 세탁 기생망)]
* **디폴트 렌더링:** 우분투 안에서는 `10.0.2.15` 라는 사설망 찌끄래기 IP를 받지만, 바깥 인터넷(구글)으로 패킷이 나갈 때는 내 윈도우 PC(Host)의 IP로 신분을 세탁(변환)시켜서 탈출해 기생합니다 (Outbound 정상 작동).
* **치명적 폐쇄성:** 바깥 세계의 해커나 심지어 내 윈도우 본체 PC의 Putty 프로그램조차, `10.0.x.x` 로 구성된 가상머신 내부(Inbound)를 찔러 들어갈 길이 없습니다. 보안은 좋지면 원격제어가 원천 차단됩니다 (이걸 뚫으려면 '포트포워딩' 수술이 필요).

### [Bridged Adapter (어댑터에 브리지 - 외부망 평행 복제)]
* 가장 편하고 개방된 랜선 결속법입니다. 내 윈도우 PC가 쓰는 진짜 공유기 랜선에 우분투를 나란히 물려버립니다.
* 만약 공유기망이 `192.168.0.x` 면, 윈도우는 `0.3` / 우분투는 `0.4` 로 평행한 외부 IP를 따냅니다. 이렇게 되면 바깥 스마트폰이나 노트북 어디서든 우분투 서버로 투명하게 양방향 SSH 접속 타격이 가능해집니다.

### [Internal Network (내부 은폐망 - 랜선 절단기)]
* 윈도우 본체와의 연결부조차 가위로 잘라버리는 극단의 폐쇄 보안망. 외부 인터넷망으로 나갈 수 없습니다. 오직 동등한 VirtualBox 안에 깔려있는 "우분투 쌍둥이 군단들끼리만" 랜선으로 엮여서 끼리끼리 패킷을 던질 수 있는 데이터베이스 격리 벙커용 아키텍처입니다.

### [Host-Only (호스트 전용망 - 다이렉트 케이블)]
* 바깥 인터넷 나가는 선은 잘려 있지만(구글 핑 안 나감), **내 윈도우 본체(Host)와 -> 가상머신(Guest) 단절 구역 간에만 1:1 직통 비밀 랜선** 을 연결하는 통제구역입니다. 윈도우에서 안전하게 우분투로 SSH 접속 터널은 열되, 바깥 해커는 절대 우분투를 건드리지 못하게 하는 투트랙(NAT+HostOnly 결합 등) 설계의 기본 뼈대가 됩니다.

## 2. Inbound 통제 우회: SSH 데몬과 포트 방화벽

리눅스 서버 인프라를 올린 뒤 윈도우에서 콘솔(Putty, Mac 터미널)로 원격 터미널 통제를 잡아채려면(22번 TCP 포트 결속), 데몬과 방화벽이라는 이중 심문관을 뚫어야 합니다.

1. **`openssh-server` 데몬의 탑재:** 리눅스 안에 24시간 동안 문 열고 기다리는 리스닝(Listening/Bind) 백그라운드 유령 프로그램 서버(ssh)를 패키지 매니저로 쑤셔 박아 설치합니다.
2. **`UFW (Uncomplicated Firewall)` 방화벽 천공:** 우분투 커널 앞단에서 돌고 있는 무시무시한 방화벽 방패에, 내가 들어갈 22번 구멍 통로를 파열시키는 강제 포트 오픈 명령을 때립니다.

```bash
# 22번 포트 규격으로 날아오는 TCP 패킷에 한해, 방화벽(ufw) 요격 시스템을 허용(allow) 렌더링한다
$ sudo ufw allow 22/tcp
```
이 세팅이 완료되어야, 비로소 외부망(Host-윈도우)에서 우분투 내부로 타격해 들어오는 Inbound 쉘 권한 터널이 확정 성립합니다.
