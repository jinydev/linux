# 차단벽 뚫기 렌더링: Inbound 터널링과 포트포워딩(Port Forwarding)

우리가 내 노트북(Host PC) 안에 가상머신 리눅스(Guest VM)를 깔고 NAT(사설망 은폐) 스위치 환경에 물어놨을 때 봉착하는 가장 큰 문제는 **"바깥쪽(구글이나 내 로컬 윈도우)에서 안쪽(리눅스망)으로 파고들 수 없다(Inbound 불가)"** 는 절대 봉쇄망 단절 현상입니다.
이 방어막에 구멍을 뚫고 터널을 맵핑 시켜주는 기법이 포트포워딩 수술입니다.

---

## 1. 두 세계의 포트(L4 Port) 관점 충돌

* **Host Port (로컬 윈도우 본체의 개방 창구):** 
  내 실제 노트북이나 윈도우 PC(192.168.0.x 등)가 바깥세상을 향해 열어두고 켜놓은 문(Port 번호)입니다. 다른 누군가가 내 노트북 환경으로 찌르고 들어오는 바깥쪽 인터페이스입니다.
* **Guest Port (격리된 가상망 리눅스의 수신단):**
  가상머신(VirtualBox)의 폐쇄된 NAT 망 내부(`10.0.x.x` 구역)에 갇혀있는 리눅스가 자신만의 세계 안에서 열어둔 서버 포트입니다 (SSH 22번, 웹 80번 등). 바깥에서는 애초에 이 번호를 찔러볼 IP 주소 자체가 먹히질 않습니다.

---

## 2. 도관 렌더링의 이음새 (포트 포워딩 맵핑)

바깥의 누군가(또는 내 윈도우 안의 Putty 프로그램)가 가상 리눅스 안의 분리된 SSH(22번)로 들어가고 싶을 때, 강제로 두 세계의 다리를 연결하는 패치 코드 세팅입니다.

* **동작 아키텍처 규칙:** `[나의 윈도우 껍데기 IP : 외부 노출 Host 포트] ===> [가상머신 숨은 IP : 종단 Guest 포트]`
* **실무 세팅 예시:** VirtualBox의 설정 창(포트포워딩 규칙)에, `Host Port: 2222` / `Guest Port: 22` 로 쌍(Pair)을 묶어 렌더링 인젝션을 박습니다.
* **통신 침투 룩업:** 이제 바깥 컴퓨터에서 내 윈도우 본체 IP 주소의 극단적인 `2222번` 포트로 SSH 억지 타격을 날립니다. 그러면 내 윈도우가 "아? 2222번으로 들어왔어? 이 패킷은 내가 받을 게 아니라 지하에 갇힌 가상머신 `22번` 방으로 던져주는 택배 포트포워딩 택배구나!" 라고 해석하여, Inbound 패킷을 그대로 리눅스 격리망 안쪽까지 직행 통과시켜 버립니다.
