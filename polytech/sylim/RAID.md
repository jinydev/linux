# 하드디스크 묶기 (RAID) 및 LVM 볼륨 관리

## 1. 하드디스크 관리 (RAID)

### 1-1. RAID의 정의
**RAID(Redundant Array of Independent Disks)**는 물리적인 여러 개의 하드디스크를 논리적으로 묶어 "마치 하나의 거대한 파티션"처럼 사용하는 기술입니다. 디스크의 입출력 속도를 높이거나, 장애가 발생했을 때 데이터 소실을 막기 위해(백업) 사용합니다.

* **하드웨어 RAID:** 메인보드나 슬롯에 꽂는 전문 RAID 컨트롤러 칩셋(물리 장비)이 연산을 처리합니다. 성능과 안정성이 가장 뛰어나며 실무 엔터프라이즈 환경에서 필수적으로 사용됩니다. (주로 RAID 1, 5, 1+0 방식을 사용)
* **소프트웨어 RAID:** 별도의 물리 장비 없이, 운영체제(Linux 커널 등)의 CPU 연산을 빌려 소프트웨어적으로 흉내내는 방식입니다. 비용이 들지 않으나 CPU 부하가 발생하며, 디스크가 통째로 망가졌을 때 OS 부팅이 불가능해질 위험이 있습니다.

### 1-2. RAID 레벨의 이해 (환각 교정)

리눅스 및 실무 환경에서 구축하는 RAID의 기초 레벨은 다음과 같습니다. *(기존 리포트에 기록된 RAID 1+6 등은 현업에서 쓰이지 않는 심각한 오개념입니다.)*

* **RAID 0 (Striping):** 데이터 속도 극대화. 2개의 디스크에 데이터를 반반씩 나누어 동시에 씁니다. 단, 디스크 둘 중 하나라도 고장 나면 파편화된 데이터가 섞여 전체 데이터가 날아갑니다. 방어력 제로.
* **RAID 1 (Mirroring):** 데이터 안정성 극대화. 2개의 디스크에 완전히 똑같은 데이터를 쌍둥이처럼 기록합니다. 하나가 깨져도 다른 디스크에 복사본이 있으므로 복구 가능합니다. 단, 디스크 2개 비용으로 1개 용량밖에 쓰지 못합니다.
* **RAID 5:** 디스크 3개 이상 필요. 데이터를 저장할 때 고장을 복구할 수 있는 '패리티(Parity) 정보'를 각 디스크에 나누어 저장합니다. 속도와 안정성을 일정 수준 타협하여 실무에서 비용 대비 효율로 가장 많이 쓰입니다. 1개가 고장 나도 복구가 가능합니다.
* **RAID 6:** RAID 5에서 패리티 정보를 두 개로 늘려, 동시에 **디스크 2개**가 고장 나더라도 안전하게 복구할 수 있게 만든 극보안 모델입니다. 디스크 4개 이상이 필요합니다.
* **RAID 10 (1+0):** RAID 1의 거울(안정성)과 RAID 0의 스트라이핑(속도)을 결합한 하이브리드. 최소 디스크 4개가 필요하며, 현대 DB 서버의 표준 구성입니다.

## 2. LVM (Logical Volume Manager)

### 2-1. LVM의 개념
서버 운영 중 C드라이브(루트 파티션)의 용량이 꽉 차면, 전통적인 파티션 방식에서는 디스크를 다 비우고 새 디스크로 이사해야 하는 끔찍한 작업이 필요합니다. 

**LVM(논리적 볼륨 매니저)**을 사용하면, 언제든 컴퓨터 전원을 끄지 않고 여분의 물리 디스크를 꽂아서 기존 용량을 고무줄처럼 늘리거나 줄일 수 있습니다. (CentOS 등 최신 배포판들은 설치 시 기본적으로 LVM으로 포맷됩니다.)

* **물리 볼륨 (PV - Physical Volume):** 파티션(/dev/sda1 등) 자체를 LVM이 인식할 수 있게 변환한 블록.
* **볼륨 그룹 (VG - Volume Group):** 여러 개의 PV를 합쳐 만든 거대한 찰흙 덩어리(가상 창고).
* **논리 볼륨 (LV - Logical Volume):** 거대한 VG 창고에서 사용자가 원하는 만큼 떼어 내어 실제로 포맷(ext4, xfs)하고 사용하는 가상의 드라이브 파티션.

## 3. 사용자별 디스크 공간 할당 제어 (Quota)

* 리눅스는 여러 명이 동시 접속해 하나의 디스크 창고 폴더(`/home` 등)를 공유합니다. 
* 특정 사용자가 동영상 파일 등을 꽉 채워 디스크 용량이 100%에 도달하면, 리눅스 자체의 구동(로그 기록 등)을 막아버려 시스템 데드락(다운)을 유발합니다.
* **쿼터(Quota):** 각 사용자(User)나 그룹(Group)이 하드디스크의 용량을 "최대 몇 GB까지만 쓸 수 있는지", 또 "문서 파일을 최대 몇 개까지만 만들 수 있는지" 용량과 개수를 제한하는 파일시스템 고급 관리 기법입니다.
