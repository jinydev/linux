# 웹 서버의 종류: Apache, Nginx, IIS

사용자가 브라우저를 켜고 도메인을 입력하여 엔터를 눌렀을 때, 목적지 서버에서 그 요청(HTTP Protocol)을 건네받아 html, 이미지, 동영상 파일 등을 화면에 '서빙'해주는 문지기 역할을 바로 웹 서버(Web Server)가 합니다. 이 시장을 주름잡는 3대 웹 서버의 특징을 간결하게 정리합니다.

## 1. 아파치 (Apache HTTP Server)
오랜 역사를 지닌 전 세계 점유율 1위의 영원한 오픈 소스 웹 서버 표준입니다. 

* **강력한 확장성:** 수많은 외부 호환 모듈을 블록 조립하듯 끼워 넣어, 거의 모든 OS와 프로그래밍 환경에 구애받지 않고 연동되는 등 범용성이 가장 우수합니다. 
* **요청당 프로세스 할당(MPM Prefork):** 브라우저에서 사용자가 접속할 때마다 '자식 프로세스'를 하나씩 할당하여 처리합니다. 이는 매우 안정적이나, 사용자가 1만 명 단위로 한꺼번에 몰리는 이른바 'C10K 문제' 발생 시 램 메모리가 폭발하며 서버가 죽어버리는 아키텍처적 한계가 존재합니다.
* **가상 호스팅(Virtual Hosting):** 물리적인 리눅스 컴퓨터 장비 하나에 `naver.com`, `daum.net` 처럼 전혀 다른 10개의 도메인을 연결해도, 내부적으로는 각각 독립된 웹 서버 공간처럼 분리 서비스를 띄워주는 고효율 가상 호스팅을 지원합니다.

## 2. 엔진엑스 (Nginx)
과거 아파치 서버가 동접자 폭주의 C10K 문제를 견디지 못하고 뻗어버리던 시절, 속도와 경량화에 모든 것을 쏟아부어 개발된 러시아발 '이벤트 기반(Event-Driven)' 웹 서버 혁명입니다.

* **압도적인 성능과 가벼움:** 프로세스를 하나씩 생성하지 않고 비동기식 이벤트 큐 방식으로 트래픽 짐을 쳐내므로 아파치보다 **월등히 적은 메모리로, 말도 안 되게 높은 동시 접속자 수**를 버텨냅니다.
* **리버스 프록시 (Reverse Proxy):** 엔진엑스 자신이 직접 무언가를 처리하지 않고, 뒤에서 구동 중인 JAVA WAS(Tomcat, Spring)나 백엔드 Node.js 서버에게 사용자의 트래픽을 토스하고 로드 밸런싱(부하 분산) 해주는 '대리자' 역할이 아주 탁월합니다. 
* (과거 학생 보고서 오류 정정: Nginx는 동적 처리를 스스로 못하는 단점이 존재한다고 했으나, 애초에 웹 서버의 목적은 html 등 '정적 파일' 서빙이며, 동적 처리는 백엔드 미들웨어(WAS)에게 전가하는 것이 현대 마이크로서비스 인프라의 절대 표준 원칙이기에 이는 단점이 아니라 의도된 장점입니다.)

## 3. Microsoft IIS (Internet Information Services)
오픈 소스인 위 제품들과 달리, 오로지 마이크로소프트의 윈도우(Windows Server) 제품군 내에서만 제공되고 구동되는 독점 유료 웹 서버입니다.

* 윈도우 OS의 그래픽 유저 인터페이스(GUI)를 통해 마우스 클릭만으로 웹 서버 관리가 가능해 텍스트 입력이 부담스러운 관리자들에게 진입 장벽이 현저히 낮습니다.
* MS 생태계의 C#, ASP.NET 프로그래밍 환경 개발자들과 철저히 긴밀하게 통합되어 작동할 때 최고의 성능 시너지를 냅니다.
* (다만 라이선스 비용이 청구되고, 도커(Docker) 컨테이너 친화력이 우분투 환경의 Nginx류 보다 심각하게 떨어져 모던 클라우드 시장에서는 점유율을 내어주고 있습니다.)
