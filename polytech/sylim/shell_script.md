# 자동화의 꽃: 쉘 스크립트(Shell Script) 이해

## 1. 쉘 스크립트란?
관리자가 터미널 창에 일일이 타이핑하여 내리던 백업, 로그 삭제, 서버 모니터링 같은 일련의 명령어들을 텍스트 파일(메모장) 하나에 쭉 이어 적어놓은 일괄 처리 프로그램 파일입니다. 리눅스 쉘(Bash 등)이 이 파일을 위에서 아래로 읽으며 순차적으로 모두 실행해 줍니다. 프로그래밍의 기초인 변수, 제어문(if, for 등)을 전부 지원합니다.

### 문법 작성 예시 (환각 수정)
*(과거 제출물에 기록된 if 문법 구문의 심각한 bash 에러(`if [$1 = "yes"]`)를 실무 문법 띄어쓰기 규격에 맞춰 교정했습니다.)*

```bash
#!/bin/bash
# 첫 규칙: 최상단 시스템에게 이 스크립트를 Bash 엔진으로 번역해달라고 지시 (Shebang)

# Bash에서 if 조건식의 대괄호 양옆은 "반드시" 띄어쓰기를 해야 하며 문자열은 쌍따옴표로 감싸는 것이 보안상 안전합니다.
if [ "$1" = "yes" ]; then
    echo "당신의 첫 번째 입력값 인자는 yes 입니다."
else
    echo "yes가 아닙니다."
fi
```

## 2. 권한 부여 및 쉘 스크립트 실행 방법론

쉘 스크립트를 작성(`vim runfile.sh`) 한 후, 이를 내 터미널 환경에서 실행시키는 방식은 크게 두 가지로 분류됩니다.

### 방식 A. 서브 쉘 (Sub Shell)에서 실행 시스템 파생하기
원본 터미널이 직접 명령어를 실행하지 않고, 자기 밑에 "새끼 터미널 프로세스(자식 쉘)"를 하나 더 띄워서 그 창에서 백그라운드처럼 로직을 돌리고 결과만 부모에게 반환하는 방식입니다. 일반적인 방식입니다. 파일을 '프로그램'처럼 인식시켜야 하므로 실행(`x`) 권한 부여가 필요합니다.
```bash
# 1. 파일에 유저들이 실행(eXecute)할 수 있는 +x 권한을 끼워넣어 줍니다.
$ chmod 755 runfile.sh

# 2. 현재 디렉토리 경로에 있는 녀석이라고 명시하며 쉘을 던집니다.
$ ./runfile.sh
```

### 방식 B. 현재 쉘 (Current Shell) 위에서 강제 직접 실행하기
자식 프로세스를 낳지 않고, 현재 내가 보고 있는 터미널 부모 창 위에서 위에서부터 아래로 텍스트를 고대로 복사+붙여넣기 한 것처럼 직속 실행하는 방식입니다. 스크립트 안에서 `cd` 명령어 등으로 폴더를 이동했다면, 실행 종료 후 내 실제 작업 경로도 이동된 채로 남아있게 됩니다. (권한 부여 불필요)
```bash
# source 연산자 사용하기
$ source runfile.sh

# 위 source 명령과 완벽하게 동일한 기능을 하는 예약 점(.) 사용
$ . runfile.sh
```
