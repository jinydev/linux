# 시스템 제어의 중심: systemctl 명령어

## 1. systemd의 등장
- **systemd**란 시스템 부팅 단계부터 각종 서비스 데몬, 네트워크, 로그 등 리눅스 전반을 총괄하는 **통합 초기화(Init) 및 프로세스 관리 시스템**입니다.
- 운영체제가 전원을 켜고 커널을 로드한 뒤, 가장 먼저 실행되어 PID 1번을 부여받으며, 시스템이 정상 작동하도록 모든 백그라운드 환경과 설정(Service Unit)들을 메모리에 띄워주는 핵심 역할을 수행합니다.
- 이 거대한 `systemd` 엔진에게 사용자가 명령을 내리고 제어하기 위해 사용하는 인터페이스(도구)가 바로 **`systemctl`** 명령어입니다.

## 2. 서비스 제어 명령어 (Service Control)
웹 서버, DB 서버 등 데몬 서비스를 운영할 때 가장 많이 쓰이는 명령어 패턴입니다. 관리자(root) 권한이 필요합니다.

* **목록 확인**
  ```bash
  systemctl list-unit-files    # 시스템 내 설치된 모든 서비스 유닛 목록과 부팅 시 구동 상태 출력
  ```
* **서비스 시작 및 종료**
  ```bash
  sudo systemctl start [서비스명]    # 즉시 서비스 가동
  sudo systemctl stop [서비스명]     # 즉시 서비스 중지
  sudo systemctl restart [서비스명]  # 서비스가 정지된 후 다시 시작됨 (설정 파일 적용용)
  ```
* **서비스 부팅 등록 (중요)**
  ```bash
  sudo systemctl enable [서비스명]   # 서버 재부팅 시에도 해당 서비스가 자동으로 시작되게 설정
  sudo systemctl disable [서비스명]  # 자동 시작 해제
  ```
* **무중단 설정 갱신**
  ```bash
  sudo systemctl reload [서비스명]   # 프로세스를 죽이지 않고, 연결을 유지한 채 설정 파일 내용만 다시 덮어씌움
  ```

## 3. 시스템 전원 제어 명령어
시스템 전체 상태를 제어할 때 사용합니다. 구형 명령어(`halt`, `reboot`)도 결국 내부적으로는 `systemctl`의 명령을 거쳐 수행됩니다.

* `sudo systemctl halt` : 시스템의 모든 프로세스를 안전하게 종료하지만, **전원(파워) 자체를 차단하지는 않고 시스템을 멈춤 상태(Halt)**로 둡니다. (ACPI 제어가 없던 서버 시절 방식)
* `sudo systemctl poweroff` : 시스템 프로세스를 종료하고, 메인보드에 신호를 보내 **물리적인 전원까지 완전히 차단**합니다. 현대 서버 종료의 표준입니다.
* `sudo systemctl reboot` : 파일 시스템을 안전히 동기화하고 캐시를 저장한 뒤, **시스템을 재기동(Restart)** 합니다.
