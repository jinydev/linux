# 인프라 보안의 시작점: 계정 권한(User Permission) 분리

윈도우 시스템이 "모두가 평등한 관리자(Administrator)" 이념으로 편의성에 몰빵하다 해킹에 박살 나는 것과 대조적으로, 리눅스 시스템은 파일을 만든 자(User)와 그 팀원(Group), 그리고 알지도 못하는 외부인(Others)의 파일 접근 권한을 3단계로 엄격하게 칼질하여 찢어놓는 철저한 다중 사용자 보안 렌더링 아키텍처를 가집니다.

---

## 1. 3대 권력 계층망

* **절대 신 `root` (SuperUser):** OS의 뇌파(커널)마저 지하시키고 덮어쓸 수 있는 유일한 계정. 파일에 아무런 권한이 없어도 모든 잠금을 무시하고 강제 삭제, 열람이 가능합니다. 이 계정이 털리면 서버는 즉시 폭파됩니다. 
* **일반 깡통 계정:** 쉘을 통해 명령어(`ls`, `cd`)는 칠 수 있지만, 시스템 코어 설정 파일(`/etc`)을 건드리거나 80번 웹 서버 포트를 개방하는 등의 주요 인프라 통제권이 원천 차단된 노예 계정입니다.
* **시스템 데몬 계정 (`nologin`):** `www-data`, `mysql` 등 백그라운드 프로그램들이 빙의해서 구동될 때만 쓰는 특수 계정입니다. (사람이 이 계정으로 터미널 쉘 로그인을 시도하면 권한 방패에 튕겨 나갑니다.)

### [일반 계정의 반란: `sudo`]
권한이 없는 일반 계정이 Nginx 웹 서버를 껐다 켜는 등 치명적 명령어를 내려야 할 때, 일시적으로 `root` 신의 권력을 5분 동안만 훔쳐 와서 타격하는 대리 결재(SuperUser DO) 권한 위임 레이어입니다.

## 2. 파일 접근 통제 매트릭스 (rwx 렌더링)

리눅스의 모든 문서 파일과 폴더는 생성되는 순간, 아래와 같은 10자리의 철창(Permission) 권한표가 덧씌워집니다.

**`-rw-r--r-- 1 ubuntu admin 4096 config.txt`**

1. **맨 앞 1자리 (`-` 또는 `d`):** 파일인지(`-`), 폴더방인지(`d`) 식별해 주는 렌더링 인디케이터.
2. **세 토막 권한 분리 (`rw-` / `r--` / `r--`):**
   * **소유자(User: ubuntu):** `rw-` (읽고 쓸 수 있음)
   * **그룹(Group: admin):** `r--` (수정은 못 하고 눈으로 읽기만 가능)
   * **제3자(Others):** `r--` (지나가는 행인도 읽기만 가능)

### [권한 부여의 8진수 핫패치 조작 (`chmod`)]
이 권한을 `r, w, x` 타이핑치기 너무 귀찮아서 엔지니어들은 이 권한의 유무를 이진수 비트(Bit) 렌더링으로 치환해 버렸습니다.
* `r(Read)` = 4
* `w(Write)` = 2
* `x(eXecute - 실행불/폴더진입)` = 1

```bash
# 777: 4+2+1 등급을 소유자, 그룹, 남에게 모두 뿌림 
# -> 전 우주의 누구나 이 파일을 지우고 마음대로 조작 가능. 치명적 보안 참사 (절대 금지).
$ chmod 777 config.txt

# 600: 나만 읽고 쓰고(4+2=6), 그룹과 남들은 아무 권한(0) 없음
# -> SSH 비밀 열쇠(pem 키) 파일의 통제 시퀀스 필수 권한.
$ chmod 600 key.pem
```

## 3. 소유권 박탈과 증여 매커니즘 (`chown` / `chgrp`)

권한 표지판이 아니라 아예 파일의 "주인 명의"를 통째로 등기 이전 시켜버리는 소유권 장악 명령어입니다. (원 주인조차 튕겨 나가게 만듭니다.)

```bash
# config.txt의 주인을 무관한 user1로, 소속 팀을 web_group으로 강제 소유권 위임 인젝션
$ chown user1:web_group config.txt
```
