# 시스템 자원 할당의 스케일 렌더링: 프로세스와 스레드

운영체제 커널의 최우선 임무는 CPU 코어와 한정된 RAM 메모리판 위에서, 미친 듯이 실행 버튼을 눌러대는 수백 개의 프로그램들(크롬 창 10개, 디스코드, 게임 등)이 서로 충돌하지 않게 시간을 쪼개 격리시키는 고도의 스케줄링 렌더 로직입니다.

---

## 1. 불가침의 거대 요새: 프로세스 (Process)

단순 방치된 `.exe` 쇳덩어리 파일을 더블클릭하면, 그 파일이 메모리 위로 붕 떠올라 피와 살이 도는 활성 생명체로 구동되는 상태를 프로세스라 부릅니다. 
운영체제는 프로세스들에게 철저하게 독립된 메모리 땅덩어리 요새(독거실)를 배분하여 **어느 한 놈이 에러로 자폭 폭파해도 다른 놈이 죽지 않게(격리 방어망)** 아키텍처를 짭니다.

### [프로세스 할당 4대 메모리 데이터 렌더 구역]
* **`Code` (명령 구역):** "1+1을 더해라" 같은 순수 소스코드 명령문이 바이너리로 박혀있는 고정 읽기 전용 구역.
* **`Data` (정적 저장소):** 프로그램이 시작부터 켜둘 때 확보되는 전역 상수 값 장부.
* **`Heap` (메모리 블랙홀 동적 팽창):** 코더들이 `malloc` 이나 객체 생성을 남발할 때마다 프로그램 용량이 짐승처럼 팽창하며 자라나는 런타임 메모리 할당 렌더러 지대. (여기서 개발자가 자원을 안 치우면 램이 꽉 차는 메모리 누수-OOM 폭사가 터집니다.)
* **`Stack` (함수 처형장):** `A()` 함수가 끝나면 임시 변수 찌꺼기들(`int i`)을 펑펑 터뜨려 날려버리는, 생성/소멸이 광속으로 돌아가는 LIFO 파이프라인.

---

## 2. 요새 단절망을 뚫는 핫라인 통신 체계: IPC

멀티 프로세싱 환경에서, 프로세스 요새끼리는 서로의 메모리에 절대 직접 침투 불가합니다. 방벽을 우회해 데이터를 패싱해 주기 위한 통신 데몬 규약이 `IPC (Inter-Process Communication)` 레벨 브릿지입니다.
* **파이프(Pipe) / 소켓(Socket):** 네트워크 망을 쏴서 서로 소통하거나(소켓), 운영체제가 뚫어놓은 단방향/양방향 텍스트 파이프라인 전송 터널.
* **공유 메모리 (Shared Memory):** 두 프로세스 중간에 중립 구역(메모리 웅덩이)을 파서, 서로 데이터 장부를 끄적이고 바꿔 읽을 수 있게 하는 가장 빠른 무접점 통신. (단, 둘이 동시에 쓰다 데이터가 씹히는 동기화-데드락 경합 버그의 주범).

---

## 3. 요새 내부의 기동 분대: 스레드 (Thread) 스케일링

웹브라우저 하나를 띄워놓고 (프로세스 1개), 그 안에서 음악을 들으며 동시에 파일 다운로드를 돌린다? 이처럼 한 요소 안에서 독립된 여러 개의 분신을 파생시켜 코일을 쪼개는 아키텍처가 쓰레드(Thread)입니다.

### [멀티 스레드 트레이드오프 매커니즘 렌더링]
* **극강의 자원 가성비:** 스레드 분신들은 미련하게 `Code, Data, Heap` 자원을 복제 복사하지 않고 본체의 거실을 냅다 공유합니다. 자기가 혼자 쓸 `Stack` 메모리 쪼가리만 각자 들고나가서 병렬 분신 파이프라인을 굴립니다. (생각 속도, 컨텍스트 스위칭 속도 극강)
* **공멸의 연쇄 폭발:** 거실(메모리)을 공유하기 때문에, 스레드 1번이 거실에 잘못된 에러 버그 폭탄을 엎어버리면, 옆에서 일하던 스레드 2, 3번 뿐만 아니라 프로세스 본체 전체가 우르르 동반 침몰 폭사하는 치명적 도미노 아키텍처 리스크를 동반합니다.
