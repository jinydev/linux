# 인프라 종단 주소록 포맷팅: IP와 서브넷 렌더링 아키텍처

우리가 네이버 서버나 우분투 가상머신에 접근하기 위해서는 MAC 주소라는 물리 기계 번호를 감싸서 논리적인 표지판 경로로 매핑시켜 주는 OSI 3계층 (L3)의 지휘관 프로토콜 주소 체계인 **IP(Internet Protocol)** 아키텍처가 핵심 패킷을 주도합니다.

---

## 1. 32비트 지번 분리 렌더링 (Net ID vs Host ID)

IP 공간(`192.168.0.1` 같은 IPv4, 32비트 덩어리)은 무식하게 한 줄의 단순 번호가 아닙니다. **"이 IP가 어느 동네(소속 대역) 네트워크인가?"** 를 판별하는 `Network ID`와, 그 동네 라우터 안에 들어가서 **"정확히 몇 동 몇 호의 컴퓨터 놈(단말기)인가?"** 를 저격하는 `Host ID` 의 모듈 조립 조합으로 파생됩니다.

### [구시대의 망 국경선: IP Class 체계]
초창기에는 맨 앞 숫자의 크기만 보고 강제로 할당 동네 크기(Class)를 도끼질해 나눠버리는 무식한 깡통 스케일 분류법을 썼습니다.
* **A Class (`1.x.x.x ~ 126.x.x.x`):** 전면 8비트만 동네 이름, 뒤의 24비트 전체가 남는 빈방. (네트워크 하나당 1600만 대 컴퓨터 수용 가능, 국가/초거대 망 독점)
* **B Class (`128.x ~ 191.x`):** 중간 규모 라우터망 포지션 (네트워크당 6만 5천 대 수용).
* **C Class (`192.x ~ 223.x`):** 앞 24비트(192.168.0)가 동네 이름이고 조그만 8비트 구역(최대 254대 기기)만 내 건물에 배당해 주는 소규모 공유기/로컬망 전폭 지지 클래스.

---

## 2. 대규모 낭비 타파 아키텍처: 서브넷 (Subnetting) 분할

만약 대학교에 B 클래스를 하나 던져주면 그 안에 부서별로 6만 개의 IP를 우겨 넣게 됩니다. 하지만 부서 간 통신을 막기 위해 망을 분할해야 하는데 고작 100대씩 쓰는 방들에 클래스를 나눠주면 IP가 수십만 개씩 쓰레기통에 처박혀 낭비(IP 고갈)되는 참사가 터집니다.
* **서브넷팅 지형 칼질:** 거대한 덩어리 네트워크(Host ID) 비트를 커널 엔지니어가 쪼개서 네트워크 그룹으로 편입(Subnet) 시켜버리는 논리적 네트워크망 폭파 파티셔닝 기술입니다. 이로써 사내 인사팀, 개발팀, 기획팀이 하나의 망 안에서 라우터 대역을 단절시키며 통신 렌더링 블로킹의 효과를 맛봅니다.

---

## 3. 동네 분할 도끼질 기준점: 서브넷 마스크 (Subnet Mask & CIDR)

"도대체 어디까지가 동네 번호(Network ID)고, 어디서부터가 방 번호(Host)인데?" 이 칼자루 분할 선의 기준을 CPU 라우터 파서에게 짚어주는 판별 표지판이 **서브넷 마스크(Subnet Mask)** 렌더링 필터입니다.

* IP 주소와 1:1로 비트를 겹치며, **비트가 `1` (`255`)로 도배된 구역은 소속 Network ID로 막아 잠그고, `0` 으로 비워진 구역은 호스트 IP에 재량권을 주는 마스킹 오버헤드 메커니즘** 입니다.
* 만약 C 클래스 세팅이라면 마스크는 강제로 `255.255.255.0` (앞 3자리는 꼼짝 말고 동네 번호 공유망 고정) 이 세팅됩니다.

### [모던 엔지니어의 프리픽스(CIDR Prefix) 표기법 축약]
요즘 AWS 에서는 귀찮게 `255.255.255.0` 4덩어리를 치지 않습니다. 
이 255를 이진수로 돌리면 앞쪽부터 `1`이 24개 등장하므로, 무자비하게 IP 뒤쪽에 슬래시 패치 꼬리표를 달아버려 **`192.168.0.1/24`** 와 같이 단 3글자로 서브넷 분할 스케일 렌더링을 완전히 종결 요약 조립해 버립니다.
