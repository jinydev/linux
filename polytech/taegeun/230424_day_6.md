# 문자열 엔드포인트 번역망: DNS (Domain Name System)

우리가 웹 브라우저에 `google.com` 이라는 영단어를 치면 컴퓨터는 절대 알아듣지 못합니다. 3계층 네트워크 통신을 위해서는 무조건 숫자로 된 `142.250.206.14` 같은 진짜 IP 좌표 체계가 필요한데, 이 '인간 친화적 영단어' 와 '기계 친화적 숫자 IP' 를 1:1로 장부 조립 세팅해 놓고 초광속으로 매핑 번역해 주는 전 세계 규모의 데이터베이스 시스템이 DNS입니다.

---

## 1. 3단 계층 파싱 레이어 (도메인 네임 스페이스)

`.com` 이나 `.kr` 같은 도메인에는 명확한 권력 서열과 계급이 존재하며, 오른쪽에서 왼쪽으로 렌더링 파싱이 들어갑니다.

1. **Root DNS 서버:** 지구상에 13대뿐인, 도메인 번역의 출발점이자 최고 존엄 뿌리 기지입니다.
2. **TLD (Top-Level Domain):** `.com`, `.net`, `.org`, `.kr` 같은 우주 대규모 구역을 담당하는 서버 그룹입니다.
3. **Authoritative (권한 위임 네임서버):** `google.com`, `naver.com` 처럼 여러분이 돈을 내고 산 실제 상표 호스트 이름을 통제하는 세부 실무 서버 망입니다.

---

## 2. 클라이언트 대행자: 리졸버 (Resolver 데몬)

사용자의 구글 크롬 브라우저가 전 세계 DNS 서버 계층망을 상대로 직접 일일이 질의를 때리고 다니는 건 미친 짓(비효율)입니다. 대신 이 귀찮은 심부름 작업을 OS 단에서 대행해 주는 놈이 **리졸버(Resolver)** 입니다. 

* **Resolver 통신 렌더 모달:** 여러분의 윈도우 PC(클라이언트)가 `google.com` 의 IP가 뭐냐고 통신사(KT, SKT)의 막강한 리졸버 기계(Local DNS)에게 던지면. 이 리졸버 깡패가 Root -> TLD -> Authoritative 순으로 전 세계를 훑어 발품을 판 뒤 최종 숫자 IP를 구해다 다시 여러분의 윈도우로 배달해 줍니다. 
* **캐싱 핫패치 방어:** 만약 어제 가져온 주소를 오늘 또 물어보면 굳이 태평양 건너 DNS를 또 조회하지 않고 자기(Local DNS) 메모리에 임시 기억해 둔 캐시 데이터본을 광속으로 반환 맵핑 시킵니다.

---

## 3. 웹사이트 호출 파이프라인 시퀀스

우리가 브라우저 엔터를 치는 순간 수천 킬로미터 밖에서 일어나는 DNS 쿼리의 재귀적(Recursive) 심문 과정입니다.

1. 개발자의 브라우저가 **Local DNS (KT/SKT 리졸버)** 에게 `www.example.com` 번역을 요구 발사합니다.
2. 리졸버가 캐시 장부를 뒤져보고 없으면, 지구 최상단 전지전능한 **Root DNS** 에게 묻습니다. 
3. Root DNS는 *"나도 세부 IP는 모르는데, 대신 저 밑에 `.com` 관리하는 **TLD 서버** 좌표 알려줄 테니 걔한테 가봐라"* 라며 튕겨냅니다.
4. 리졸버가 다시 TLD 서버로 쳐들어가 묻자 TLD는 *"아 `example.com` 관리하는 **권한(Authoritative) 네임서버** 놈 주소가 여기다 걔한테 가봐라"* 라며 또 튕겨냅니다.
5. 마지막으로 권한 네임서버에게 물어보면 *"맞다! 우리 건물 웹 서버 진짜 IP (Host) 는 `10.23.xx.xx` 다!"* 라고 최종 응답을 뱉습니다.
6. 이 IP를 받아낸 통신사 리졸버가 내 윈도우 PC 브라우저로 렌더링 토스하며, 비로소 브라우저가 랜선을 타고 웹 문서를 끌어옵니다.
