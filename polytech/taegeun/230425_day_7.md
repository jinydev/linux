# C/S 통신 규약의 코어 렌더링: HTTP와 HTTPS 

우리가 주소창에 `www` 를 칠 때 맨 앞에 보이지 않게 생략되어 있는 `http://` 의 정체는, 글로벌 전 세계의 클라이언트(내 컴퓨터)와 서버 웹 엔진 프로그램이 서로 ' HTML 텍스트 문서' 를 쿵짝거리며 주고받기 위해 만든 텍스트 데이터 포맷 전송 법(Protocol) 통신 규약입니다. 

---

## 1. 망각의 늪: HTTP의 Stateless (무상태성) 아키텍처

쇼핑몰 서버가 동시 접속자 100만 명을 지탱하며 뻗지 않는 극한의 스케일링 비밀이 바로 HTTP의 본질인 **'기억 상실(Stateless)'** 구조입니다.

* **메모리 절단 폐기:** 클라이언트가 서버에 "나 로그인했어, 화면 줘(Request)" 라고 던지면. 서버는 응답 HTML 렌더링 화면(Response)을 뱉어주자마자, 즉시 방금 통신했던 너라는 존재의 상태 기억 메모리를 가차 없이 절단해 폭파 삭제해 버립니다.
* **스케일 아웃의 미학:** 이렇게 기억을 1초 만에 초기화하니까 서버 메모리(RAM)가 절대 터지지 않고 수십만 명의 접속을 미친 속도로 무한 트랜잭션 수용할 수 있습니다. 

### [망각을 우회하는 편법: 쿠키(Cookie)와 세션(Session)]
HTTP가 너를 바로 망각해 버리니. 게시판 페이지를 넘어갈 때마다 다시 로그인이 풀려버리는 미친 참사가 발생합니다. 이를 땜빵하기 위한 우회 메모리 렌더링 기법이 `쿠키/세션` 입니다.
* **쿠키(Cookie):** "내가 너 누군지 기억 안 부를 테니까, 내가 도장(Session ID) 찍어준 쪽지 니 브라우저 본체 하드디스크에 저장해 놔라. 다음번에 올 때 또 무조건 그 쪽지 같이 제출(Header 포함)해라!" 라며 클라이언트에게 신분망 증명을 떠넘기는 방식입니다.
* **세션(Session):** 가짜 쿠키 제출 범죄를 막기 위해, 진짜 중요 데이터 정보는 서버 백엔드 메모리에 고이 박아놓고 해시 포인터 주소(세션 ID)만 맵핑해서 내려주는 서버-사이드 검증 기법입니다.

## 2. 평문의 학살을 방어하라: HTTPS 프로토콜

일반 `HTTP (80번 포트)` 는 당신이 서버로 전송하는 `비밀번호: 1234` 데이터를 순수한 글자 그대로 랜선 바다에 뿌립니다. 와이파이 해커 장비(WireShark 패킷 스니퍼 등)가 중간에 1초만 낚아채서 열어보면 모든 개인 정보가 실시간 파싱 유출 탈취당합니다.

### [SSL/TLS 양방향 터널링 무결성 방벽]
이 구시대의 평문 학살을 막기 위해 튀어나온 것이 `S (Secure)` 가 붙은 암호화 장갑차 **HTTPS(443번 포트)** 인젝션입니다.
* **SSL(보안 소켓 계층) / TLS (전송 계층 보안):** 
  클라이언트와 서버가 서로 악수를 할 때(Handshake), 상대방이 해커가 아닌 오리지널 진짜 네이버 서버인지 신분증(인증서)을 까서 검증하고 단둘만 비대칭키 구조로 수십 자리의 난수로 암호 복호화 껍데기(터널) 시스템을 구축합니다.
* 해커가 중간에서 당신의 443번 통신 랜선을 탈취가 잘라 먹어도, 열어보면 우주 외계어 암호문만 가득 덤프 되어 절대 해석이 불가능한 무결성 아키텍처로 렌더링 방어됩니다.
