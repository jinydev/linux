# 인프라 서버의 트래픽 폭격 방어벽: 로드 밸런싱(Load Balancing)

카카오톡이 새해 자정이나 대국민 이벤트 당일 날, 5천만 명의 유저가 스마트폰에서 동시에 수백만 건의 접속 요청(Request)을 때릴 때 뒷단의 웹 서버 단 한 대가 이 물리적 부하 트래픽(Load)을 모두 혼자 쳐맞는다면 5초 안에 램이 가득 차 OOM 커널 패닉으로 폭발합니다. 
진격하는 어마어마한 트래픽 레이저를 앞에서 대신 쳐맞아 여과하고, 뒤에 숨어있는 **'쌍둥이 서버군 수백 대'에게 사이좋게 1/N 씩 패킷을 찢어서 분산 토스해 주는(Balancing) 절대적 중계 지휘관 아키텍처**입니다.

---

## 1. 인프라 생존 철학의 양대 매커니즘 (물리 스케일링)

한 대의 서버가 버티지 못할 때 엔지니어가 취할 수 있는 두 개의 증설(Scale) 아키텍처 맵핑 방식입니다.

* **스케일 업(Scale-Up / 깡패 만들기):** 서버 컴퓨터 케이스 뚜껑을 열어제끼고 미친 듯이 64기가 램과 32코어 CPU를 추가로 쑤셔 박아 돌연변이 괴물급 단일 서버 한 대를 렌더링시킵니다. 데이터베이스(DB) 한계 봉착 시 주로 쓰는데 부품값 확장 한계선 타격이 옵니다.
* **스케일 아웃(Scale-Out / 쌍둥이 분신술 렌더링):** 윈도우 싼 컴퓨터 머리를 여러 대 옆으로 계속 증식 파싱 결합(Clone) 시킵니다. 똑같은 우분투 리눅스를 돌리는 서버를 3대, 10대 무한 양산해서 옆구리에 붙입니다. AWS 클라우드가 뻗어나갈 수 있는 무한대의 오토 스케일링 유연성 기반 기술입니다 (단, 이 수십 대의 분신들을 앞에서 통제할 **'로드밸런서 문지기'** 가 반드시 필요합니다).

---

## 2. 분산 토스 전략 렌더링 (균등 스케줄링 알고리즘)

부하 하중을 똑같이 뒤로 쪼개기 위한 로드밸런서 엔진의 분할 샷 로직입니다.
1. **순서 교대 (Round Robin):** 앞뒤 생각 안 하고 뒤에 있는 1번, 2번, 3번 서버에게 사이좋게 순서대로 공정한 핑퐁(패킷 던지기) 1회씩 배분합니다. 
2. **가중치 인젝션 (Weighted):** 1번 서버가 최고급 기종이면 걔한테 트래픽 비중을 2배 더 많이 쏠리게 세팅해 병목을 통제합니다.
3. **최소 응답/최소 연결 (Least Connection):** 가장 놀고 있거나 연결 파이프 지연(Ping Time)이 없는 쾌적한 비어있는 서버를 귀신같이 찾아 글로 밀어 넣어 하중을 스케일 다운시킵니다.
4. **IP 해싱 (무조건 락인):** 특정 사용자의 스마트폰 IP 접속자는 어떤 일이 있어도 자기가 한 번 뚫었던 그 해당 배정 서버 1번으로만 꽂히게 고정(Sticky Session)시켜 로그인 세션 증발이 끊기지 않는 쿠키 유지 통제를 수반합니다.

---

## 3. 심도를 가르는 계층 분할 스위치 (L4 vs L7)

네트워크 OSI 계층에서 어디까지 파고들어 껍데기(Header) 봉투 내용을 해독해 분산시킬 건지에 대한 권력망 파이프라인 차이입니다.

* **L4 (4계층 - 패킷 포트 렌더러):** 
  트래픽 봉투 내용물이 무엇이든 아예 보지도 않습니다. 오직 'IP 나한테 왔네? TCP 포트번호 80번이네?' 라는 주소 표지판만 광속으로 읽어서 곧바로 던져버리는 미친 속도의 전송 스위칭 처리를 갖습니다. (트래픽 분산과 방어 그 자체에 초점)
* **L7 (7계층 - 애플리케이션 스니핑 파서 파괴자):**
  도착한 HTTP 통신 봉투를 완전 개봉하여, 사용자의 스마트폰 브라우저 주소 URL 경로 세부 내용(`/image/` 냐 `/video/` 냐)이나 헤더, 세션 심지어 페이로드 찌꺼기까지 모조리 파싱 분석합니다 "이미지 요청이네? 뒤에 웹서버 말고 이미지 전용 이미지 캐시 스토리지 자판기 서버로 우회 던지기 렌더링 시켜줘!" 와 같이 극한의 맞춤형 마이크로 아키텍처 분배 타격 스케일링이 가능한 앱 계층 포렌식 스위쳐입니다.
