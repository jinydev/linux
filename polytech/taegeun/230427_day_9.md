# 영속성 아키텍처의 패권 전쟁: 데이터베이스(DBMS) 변천사

게임 캐릭터 레벨이나 은행 잔고를 구동 중인 메모리(RAM)에만 박아두었다가 전원이 꺼지면 모든 렌더링 정보가 공중 증발 폭파당합니다. 데이터를 절대 삭제/유실 되지 않는 디스크 쇳덩어리에 체계적인 장부 로직(무결성/일관성 보존)으로 파싱해 영구 보관 격리 저장해 주는 마스터 코어 서버 프로그램이 데이터베이스(DB)입니다.

---

## 1. 20년 백엔드를 지배한 패왕: RDBMS (관계형 데이터베이스)

엑셀의 무식한 테이블 셀판때기(Row & Column) 시트를 수백 장 겹겹이 찍어내고, 테이블과 테이블 사이의 **관계(Relation) 링크 ID 연결 고리 설계망**을 구축해 데이터의 지독한 중복을 박살 내고 타임 파이프라인 무결성을 보존하는 극한의 체계화 철학입니다.

* **작동 렌더링:** 회원 정보용 테이블(주민번호), 결제 이력 테이블을 철저하게 분리 보관하다가. 사용자가 요청하면 `SQL (Structured Query Language)` 구조화된 쿼리 질의 조인 규격 포맷을 통해 실시간 메모리 런타임 위로 정보를 융합 합체(Join) 렌더링시킵니다.
* **장/단점:** "은행에서 돈 천만 원이 빠져나갔으면 저쪽 놈 계좌에 백 퍼센트 플러스 천만 원이 들어가야만 동작이 확정된다"는 트랜잭션 록킹 절대 원칙(ACID 강제)으로 신뢰도 100%의 절대 무결성을 가집니다. 단, 칼같이 짠 스키마(표의 칼럼 뼈대 포맷 라인)를 조금이라도 벗어나는 데이터 파스는 절대 보관이 거절되며, 다중 서버 병렬 스케일 아웃 확장에 태생적으로 무너지는 파이프라인 병목이 존재합니다.
* **코어 제품:** `Oracle DB(엔터프라이즈 철통망)`, `MySQL`, `MariaDB`, `PostgreSQL(최강 오픈소스 진영)`

## 2. 규격 뼈대의 파괴 아키텍처: NoSQL (비관계형 분산 저장소)

빅데이터 폭풍과 페이스북 1억 명 트래픽 동시 다발 시대가 터지자, 이 "반드시 이 줄 눈금 엑셀 칸을 지키고 줄 서서 연결 관계를 확인해라!" 라는 RDBMS의 깐깐한 문법 속도 병목(Join 지옥) 때문에 데이터 서버가 폭발하기 시작합니다. 관계형 뼈대를 과감히 버리고 수평선으로 클러스터링(Scale-Out) 증식 확장 폭발에 몰빵한 NoSQL 진영이 튀어나옵니다.

1. **Document 포맷 유연성 렌더링 (MongoDB):** 
   엑셀 표처럼 쪼개놓지 않고, `JSON(중괄호 쌍)` 규격이라는 자유로운 파일 문서 통짜 한 덩어리에 모든 데이터를 욱여넣어 그대로 디스크에 쑤셔 박거나 뱉어내는 극강의 읽기 속도 지향 모델입니다. 칼럼(뼈대 틀 스키마)이 자유자재라서 동적 파싱 데이터 덤프에 압도적으로 쓰입니다. 
2. **Key-Value 인메모리 폭주형 (Redis):** 
   딱 '이름 = 정수영' 같이 단순 무식한 1:1 매칭 해시 포워딩 데이터만 취급합니다. 그 대신 RAM 메모리에 이 데이터를 올려버려, RDBMS보다 수백 배 빠른 초광속 응답 통신 캐싱 조회로 트래픽 렌더 스파이크 방어벽을 구축합니다.
3. **Graph 구조화 지형:** 
   SNS에서 "이 놈이랑 이 놈이 친구고 걔 친구의 친구가 나다" 와 같은 극단적 다중 연결망 노드와 엣지망(Edge) 관계를 시각적으로 추적 탐색 저장하는 데 특화된 알고리즘 아키텍처입니다 (`ArangoDB`).

### [여담: 구시대의 전유물 계층형(IMS)]
폴더 트리나 뿌리(Root) 구조처럼 데이터가 무조건 조상-손자 계급 구조로 박힌 구시대 모델입니다 (IBM 메인프레임 통치 시대). 부모가 삭제되면 그 자식 데이터 군락 트리 지점 전체를 폭파/단절해야만 하는 살인적인 유지보수 폐단이 작렬합니다.
