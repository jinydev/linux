# 컴퓨터와 소통하는 3가지 인터페이스 (Interface)

**인터페이스(Interface)**란, 두 주체(사용자와 컴퓨터, 또는 컴퓨터와 컴퓨터)가 서로 상호작용하고 데이터를 주고받기 위해 합의한 '경계면'이나 '통신 규약'을 뜻합니다.

시스템을 조작하는 방식에 따라 크게 3가지로 나뉩니다: **CLI**, **GUI**, 그리고 **API**.

---

## 1. CLI (Command Line Interface)
마우스 없이 오직 **키보드의 텍스트(명령어)만으로** 컴퓨터와 대화하는 방식입니다.

* **특징:** 배경이 검은 터미널 창에 `ls`, `mkdir` 등의 텍스트를 치면 컴퓨터가 텍스트로 응답합니다.
* **장점:** 그래픽을 그릴 필요가 없어 컴퓨터 자원(CPU, 메모리) 소모가 극단적으로 적고 처리가 매우 빠릅니다. 여러 명령어를 조합하는 쉘 스크립트(자동화) 작성이 용이합니다.
* **단점:** 명령어를 다 외워야 하므로 초보자에게 진입장벽이 높습니다.

## 2. GUI (Graphical User Interface)
화면에 그려진 그래픽 요소(아이콘, 창, 버튼)를 **마우스나 터치스크린으로 클릭하여** 조작하는 방식입니다.

* **특징:** 윈도우(Windows), 맥(macOS) 등 우리가 일상적으로 쓰는 데스크톱 환경입니다.
* **장점:** 시각적이고 직관적이어서 누구나 매뉴얼 없이 쉽게 배울 수 있습니다.
* **단점:** 그래픽을 그리는 데 그래픽 카드(GPU)와 메모리가 많이 소모되어 서버 환경에서는 비효율적입니다. (명령어를 연속 클릭으로 대신해야 하므로 자동화가 어렵습니다.)

---

## 3. API (Application Programming Interface)
사용자(사람)가 아닌, **'소프트웨어(프로그램)와 소프트웨어 간'의 대화**를 위한 소통 창구입니다.

### API의 비유: 식당의 점원과 메뉴판
* **손님(Client 프로그램):** 요리를 직접 주방에서 만들지 않고, 점원에게 메뉴판을 보고 주문합니다.
* **점원(API):** 손님의 요구(주문)를 주방 규약에 맞게 전달하고, 완성된 요리를 다시 손님에게 내어주는 창구 역할을 합니다.
* **주방(Server 프로그램/DB):** 실제 데이터를 가공하고 요리하는 내부 로직입니다.

### API 활용 예시 (REST API)
웹 브라우저(클라이언트)가 날씨 서버(백엔드)에게 "오늘 서울 날씨 데이터 줘!" 라고 할 때, 컴퓨터끼리 알아들을 수 있는 정확한 규격으로 데이터를 주거나 받습니다. 과거 보고서에 인용된 유튜브 캡쳐본 대신, 실제 백엔드 개발 표준 포맷을 살펴봅시다.

```json
// 클라이언트가 GET /api/weather/seoul 로 API 요청을 보내면,
// 서버의 API가 아래와 같은 순수 데이터(JSON)로 응답합니다.

{
  "location": "Seoul",
  "temperature": 18.5,
  "condition": "Cloudy"
}
```

### API의 장단점
* **장점:** 프론트엔드 개발자(화면)와 백엔드 개발자(DB)가 각자의 내부 코드를 몰라도, API 명세서(메뉴판)만 있으면 협업하여 거대한 시스템을 모듈화해 구축할 수 있습니다.
* **단점:** API를 연동하려면 프로그래밍 지식이 필수적이며, 한 번 배포된 핵심 API의 규격을 바꾸면 연동된 모든 앱들이 통신 장애를 겪을 수 있어 설계 관리가 까다롭습니다.
