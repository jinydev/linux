# 데몬(Daemon)과 서비스(Service)

리눅스 서버에 접속하면 화면에는 아무것도 보이지 않지만, 뒤에서 묵묵히 밤을 새우며 웹 사이트를 띄워주는 아파치(Apache), 원격 접속을 받아주는 SSH 등 수많은 프로그램이 살아 숨 쉬고 있습니다. 눈에 보이지 않고 백그라운드에서 실행되는 이 유령 같은 응용 프로그램들을 부르는 용어가 바로 **데몬(Daemon)**과 **서비스(Service)**입니다.

## 1. 두 용어의 뉘앙스 차이

* **데몬 (Daemon):** 유닉스/리눅스 생태계의 아주 전통적인 용어입니다. 시스템이 부팅될 때 자동으로 깨어나 아무런 사용자 인터페이스 없이 시스템의 백그라운드 작업을 조용히 처리하는 유령(Daemon) 같은 녀석들입니다. 보통 실행 파일 끝에 `d`가 붙습니다. (예: `sshd`, `httpd`, `mysqld`)
* **서비스 (Service):** 주로 윈도우 생태계에서 불리거나 현대 IT 시스템 관리 측면에서 기능 덩어리를 묶어 부르는 용어입니다. 서비스는 이 데몬 프로그램 하나하나를 시스템이 제어할 수 있는 형태로 패키징 해 둔 것을 포괄적으로 가리킵니다.

> 실무에서는 둘을 완전히 똑같은 동의어로 혼용해서 사용합니다. "데이터베이스 데몬 죽었어?" = "데이터베이스 서비스 죽었어?"

## 2. 세대별 서비스 관리 명령어의 변천사

과거 수십 년간 리눅스를 지배했던 초기화 시스템 `init`(System V) 방식이 너무 낡고 느리다는 비판을 받자, 현대 리눅스(CentOS 7 이상, Ubuntu 16.04 이상)는 부팅을 병렬로 미친 듯이 빠르게 띄워주는 **`systemd`** 라는 거대 아키텍처로 세계를 통일했습니다. 

이로 인해 서비스를 켜고 끄는 명령어 문법도 완전히 세대가 나뉘게 되었습니다.

### 과거 명령어 (CentOS 6 및 구버전 우분투 시절)
과거에는 관리 스크립트가 `/etc/rc.d/init.d/` 디렉토리에 있었으며, **`service`** 라는 명령어를 사용했습니다.
```bash
# 구형 명령어 문법 (명령어가 앞, 액션이 뒤)
sudo service httpd start
sudo service httpd status
```

### 현대 표준 명령어 (CentOS 7, Ubuntu 최신 버전)
현대 시스템은 모든 서비스 단위를 `.service` 라는 유닛 파일로 관리하며, 통제권을 가진 **`systemctl`** (System Control) 이라는 훨씬 강력한 명령어를 사용합니다.
```bash
# 현대 표준 명령어 문법 (액션이 앞, 데몬 이름이 뒤)
sudo systemctl start httpd
sudo systemctl restart httpd

# 서버 재부팅 시에도 자동으로 서비스가 켜지게 등록하기
sudo systemctl enable httpd
```

### 호환성 (Redirection)
만약 최신 운영체제에서 옛날 버릇대로 `service httpd start` 라고 입력하더라도, 시스템이 똑똑하게 알아서 `Redirecting to /bin/systemctl start httpd.service` 메시지를 띄우며 최신 표준 명령어 규칙으로 변환해 조치해 줍니다. 하지만 향후 스크립트 자동화를 파싱할 때 에러가 날 수 있으므로 가급적 **`systemctl`** 표준 언어로 바로잡아 습관화하는 것이 중요합니다.
