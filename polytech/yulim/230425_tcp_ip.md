# TCP/IP 4계층과 패킷 통신 네트워크

컴퓨터 간의 통신은 하나의 거대한 덩어리를 쏘는 것이 아니라, 데이터를 잘게 쪼갠 **패킷(Packet)** 단위로 분할하여 전송합니다. 이 패킷들이 미아가 되지 않고 목적지까지 안전하게 도달하도록 전 세계가 합의한 인터넷 표준이 바로 **TCP/IP 프로토콜**입니다.

## 1. IP와 TCP의 환상적인 역할 분담

* **IP (Internet Protocol / 인터넷 계층):** 택배 기사 역할을 합니다. 속도에 모든 것을 걸었기 때문에, 패킷들이 순서대로 가든 말든, 중간에 잃어버리든 말든 목적지 주소(`192.168.0.2`)만 보고 정신없이 던져버립니다.
* **TCP (Transmission Control Protocol / 전송 계층):** 택배 검수반 팀장 역할을 합니다. IP가 던지고 도망간 수천 개의 패킷 조각 상자 언박싱을 맡아 꼼꼼하게 검수합니다. 중간에 누락된 번호 상자가 있으면 송신 측에 "빨리 다시 보내라"고 재요청하고, 번호 순서가 꼬이면 올바른 순차로 조립해 내는 핵심적인 신뢰성 100% 보증 수표입니다.

> 이 강력한 두 가지 콤비를 묶어 **TCP/IP** 라 부르며, 현존하는 인터넷 세계 대다수의 데이터 송수신은 이 뼈대 위에서 돌아갑니다.

---

## 2. 네트워크 표준 모델: OSI 7계층 vs TCP/IP 4계층

학자들은 오류가 발생했을 때 장애 지점을 핀셋처럼 뽑아내기 위해, 통신 단계를 양파 껍질처럼 겹겹이 층을 나누었습니다(계층화). 

* **OSI 7계층:** 국제 기구(ISO)에서 "통신을 이렇게 7단계로 쪼개어 이상적으로 설계하자"고 외친 '이론적인 교과서 모델'입니다.
* **TCP/IP 4계층:** 현업 개발자들이 이론을 다 무시하고 "당장 실무 인터넷 환경에 쓰기 편하게 핵심적으로 4단계로 합쳐보자"고 해서 탄생한 '실무 깡패, 인벤토리 표준 모델'입니다.

## 3. TCP/IP 4계층 구조 심층 분석
사용자가 클릭을 하는 순간 4계층에서 1계층으로 데이터가 내려가며 포장이 계속 덧붙여집니다. (**캡슐화**)
수신자가 받을 때는 1계층에서 4계층으로 순차적으로 포장을 뜯어가며 데이터를 읽어냅니다. (**역캡슐화**)

### 4계층: 애플리케이션 계층 (Application Layer)
우리가 직접 눈으로 보고 마우스로 누르는 크롬 브라우저, 게임 등 최상위 소프트웨어가 직접 통신하는 구역입니다.
* **사용 프로토콜:** 웹(HTTP/HTTPS), 이메일(SMTP), 파일 전송(FTP), 원격 접속(SSH), 도메인 주소록(DNS)

### 3계층: 전송 계층 (Transport Layer)
데이터가 목적지에 신뢰성 있게 도달했는지 확인하고, 포트 번호(`80`, `22`)를 통해 데이터가 내부에 도착했을 때 아파치 엔진으로 갈지 톰캣으로 갈지 알맞은 프로세스 방으로 꽂아주는 문지기 계층입니다.
* **사용 프로토콜:** 꼼꼼한 TCP, 속도 지향의 UDP

### 2계층: 인터넷 계층 (Internet Layer)
서울에서 아프리카까지 가장 빠르고 막히지 않는 최적의 네트워크 경로(라우팅)를 맵 스캐닝하여 안내하는 내비게이션 계층입니다.
* **사용 프로토콜:** IP 패킷 전송, 에러 조기 경보 기구(ICMP)

### 1계층: 네트워크 접근 계층 (Network Access Layer)
실질적으로 방 안의 랜카드에서 노트북과 공유기, 지하 케이블을 오가는 전기적/물리적 전파 신호로 통신하는 바닥 논리 구역입니다. MAC 주소를 사용합니다.
* **사용 프로토콜:** 이더넷(Ethernet), Wi-Fi 공유 기술 등
