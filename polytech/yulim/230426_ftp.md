# FTP 전송 포트와 능동/수동 통신 모드

웹(HTTP)이 대중화되기 이전 수십 년간 **FTP(File Transfer Protocol)**는 파일 업로드와 다운로드를 책임지던 일등 공신이었습니다. 대량의 시스템 파일과 수백 GB의 영상을 무식할 정도로 가장 빠르게 전송할 수 있는 이 장점 때문에 오늘날 IT 인프라 배치 환경에서도 FTP는 끈질기게 살아남아 있습니다.

하지만 보안 벽(방화벽) 뒤에 숨는 현대 네트워크 구조상 FTP를 쓸 때 알아야 할 핵심 모드 차이가 있습니다. 

## 1. FTP 통신의 특수성 (포트 2개 사용)
보통 웹과 같은 통신은 구멍(포트)을 하나만 씁니다. 하지만 FTP는 '명령'을 내리는 채널과, 실제 대량의 '데이터'가 쏟아져 나오는 채널 두 가지를 별도로 사용합니다.

* **명령 제어 포트 (보통 21번):** 사용자가 아이디/비밀번호를 치고, "저 폴더 내놔!" 라고 지시하는 전용 통신 파이프.
* **데이터 전송 포트:** 영화나 로그 파일 등 거대한 덩어리가 실제 트래픽으로 흘러가는 파이프.

## 2. 방화벽과 맞짱 뜨는 능동/수동 모드

### 🔥 능동 모드 (Active Mode)
* **어떻게 동작하나요?** 
  클라이언트가 21번 구멍(명령 포트)으로 "나 파일 줘!" 하면, **서버가 오히려 20번 데이터 전송 전용 데이터 포트를 강제로 열고 거꾸로 클라이언트를 찔러 데이터를 쑤셔 넣어 주는** 능동적인 방식입니다. 
* **치명적인 단점:** 요즘 시대에 클라이언트(사무실/가정집 PC) 앞에는 공유기 및 살벌한 윈도우 방화벽이 막고 있습니다. 서버가 밖에서 역으로 나를 강제로 찌르면 공유기가 "어디 외부 침입자야!" 하고 100% 차단해 버립니다. 결국 로그인까지는 잘 되는데 '목록을 불러올 수 없습니다' 하며 에러가 나는 전통적인 원흉입니다.

### 🛡 수동 모드 (Passive Mode / PASV)
* **어떻게 동작하나요?**
  능동 모드의 치명타를 해결하기 위한 현대의 표준입니다. 클라이언트가 데이터를 달라고 하면, 서버가 **"내가 너한테 찌르면 네 방화벽이 막으니까, 내가 문(1024 이상의 임의의 자유 포트)을 열어둘 테니 네가 이쪽 문으로 몸을 빼내서 데이터를 가져가렴"** 하고 듣기(Listening) 자세를 취해 주는 것입니다.
* **장점:** 클라이언트가 자발적으로 먼저 서버를 찔러 데이터를 가져오기 때문에 클라이언트 측 보안 공유기 설정에서 전혀 필터링에 걸리지 않고 아주 깔끔하게 다운로드 / 업로드가 성사됩니다.

## 3. 현대 시대에 FTP가 퇴출당하는 이유 (명백한 단점)
FTP 프로토콜은 1970년대의 유물입니다. 그 시절 인터넷은 서로 믿을 수 있는 착한 대학생 해커들끼리의 망이었습니다.

**설계 자체에 아예 암호화(Encryption) 기능이 구비되어 있지 않습니다.** 카페 와이파이에서 누군가 불법 해킹 툴(스니핑)로 나의 공기 중 전파를 훔쳐보면, 여러분이 친 관리자 아이디와 비밀번호가 전혀 섞이지 않고 `ID: admin / PW: 1234` 같은 생생한 영어 알파벳 형태로 100% 해커 모니터에 노출됩니다. 크롬과 파이어폭스 같은 최신 브라우저가 보안을 이유로 수년 전에 FTP 내장 코드를 완전히 폭파해 버린 이유입니다.

### 대안
현재의 금융 기업과 IT 인프라는 오직 SSH의 인증 암호를 덮어쓴 **SFTP (Secure FTP)**만 사용하거나, 인증서를 장착한 **FTPS**를 통해 이 치명적인 데이터를 보호합니다. (파일질라 사용 시 무조건 포트를 22번으로 세팅한 SFTP 모드를 쓰시기 바랍니다.)
