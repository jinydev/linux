# 11.3 초고속 웹 서버 신예, Nginx (엔진엑스)

과거 아파치 천하였던 수십 년의 웹 서버 시장을 최근 몇 년 만에 완전히 박살 내버리고, 넷플릭스와 네이버 등 대형 IT 기업들의 메인 고속도로 엔진으로 100% 자리 잡은 가벼운 초고속 웹 서버 `Nginx` 를 소개합니다.

![엔진엑스 비동기 루프 구조](./img/nginx_event.svg)
> **동작 원리**: 뚱뚱한 아파치는 클라이언트 1명이 모바일 앱 접속 버튼을 누를 때마다 무조건 서버 전산실의 메모리를 쪼개서 방을 파주는 할당 작업(Thread)을 합니다. 반면, 엔진엑스는 **엄청나게 거대한 단일 방(Event Loop) 하나만 파놓고**, 요청이 1만 개가 들어와도 비동기 카운터 신호로 넘기며 1개의 머리 안에서 재빠르게 넘겨 처리합니다. 컴퓨터 하드웨어 부하가 충격적일 정도로 적습니다.

---

## 1. 아파치 1대장 시대 종말의 이유 (C10k Problem)

2000년대 후반 스마트폰이 보급되면서, 회사 인터넷 접속망이 감당할 수 없을 정도로 폭주하기 시작했습니다. 이것을 **C10K(Connection 10,000) Problem**, 즉 "1만명 동시 접속 에러"라고 부릅니다.
* **아파치 진영**: 접속자 1만명의 신호가 오면, 프로세스 방을 1만 개 만들어내느라 리눅스 통째로 CPU가 녹아버리고 뻗어버렸습니다.
* **Nginx 진영**: IO 멀티플렉싱이라는 기술을 적용하여, 똑같은 1만명이 들어와도 단 1개의 비동기 이벤트 워커(Worker) 프로세스가 큐(Queue)에 데이터를 넘기면서 멈추지 않고 빠른 응답성을 보장해 주며 승리했습니다.

## 2. Nginx의 주요 확장 기능들
과거에는 Nginx가 껍데기 홈페이지(HTML, 그림)만 가볍게 서빙하는 툴이었지만 폭발적으로 성장하며 아파치의 모든 기능을 삼켰습니다.

### 2.1 리버스 프록시 (Reverse Proxy)
클라이언트가 인터넷 창에 주소를 치면, 엔진엑스가 자신이 웹서버인 "척" 하고 악수만 맺어준 뒤에, 해커 몰래 뒤쪽에 안전하게 짱박혀있는 진짜 WAS(Tomcat, Node.js) 서버에게 통신을 토스해 버리는 보안/중계 서버의 역할을 수행합니다. 실무 포트포워딩의 핵심입니다.

### 2.2 로드 밸런싱 (Load Balancing)
수만 명의 사용자가 앱을 켜서 트래픽이 몰릴 때 혼자 짐을 짊어지지 않고, 내 뒤쪽에 있는 3대의 분신 컴퓨터들에게 트래픽 양을 균등하게(밸런싱) 분산시켜 뿌려주는 역할을 기본 기능으로 막강하게 제공합니다.

## 3. [실습] 패키지를 통한 Nginx 다운로드 설치

여러분의 로컬 우분투 서버 혹은 가상 환경에 Nginx를 설치하고 띄우는 과정입니다.
(주의: 포트는 80번 1개뿐입니다. 앞선 예제에서 아파치를 켜두셨다면 `sudo systemctl stop apache2` 명령으로 아파치를 먼저 강제 넉다운시켜서 80번 자리를 비워 줘야만 엔진엑스가 이사 올 수 있습니다!)

### 실습 1. Nginx 최신 버전 설치
```bash
# APT 툴킷으로 다운로드를 실행합니다.
sudo apt update
sudo apt install -y nginx

# Nginx의 엔진 버전 스펙트럼이 몇으로 찍히는지 터미널에서 확인하세요.
nginx -v
```

### 실습 2. 데몬 리모콘 활성화 및 재부팅 영구 등록
```bash
# 엔진엑스의 심장에 시동을 걸어줍니다!
sudo systemctl start nginx

# 다음번에 리눅스 전설 컴퓨터가 꺼졌다가 재부팅되어도 죽지 않게 데몬을 영구 등록합니다!
sudo systemctl enable nginx
```

### 실습 3. 나만의 Nginx 웹화면 로딩 확인
크롬 브라우저를 다시 켜고 여러분의 IP 주소 `192.168.x.x` 나 `localhost` 를 치고 들어갑니다. 화면의 웅장한 아파치 문구가 완전히 사라지고, **"Welcome to Nginx!"** 라는 심플한 환영 문구가 나오면 여러분의 서버 세팅이 완벽히 뒤바뀐 것입니다.
