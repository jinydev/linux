# 9.3 텔넷(Telnet)과 보안 쉘(SSH) 원격 접속 관리

실제 데이터센터나 클라우드 인터넷망(AWS 등) 공간에 놔둔 수백 대의 리눅스 장비들은 모니터와 키보드가 달려 있지 않습니다. 내 노트북(Client)에서 지구 반대편의 장비(Server)로 네트워크 선을 타고 들어가 타건하는 **'원격 접속(Remote Connection)'** 작업이 서버 다루기의 모든 것입니다.

![원격 접속 프로토콜 안전성 비교](./img/remote_ssh.svg)
> **동작 원리**: 네트워크 IP를 알아냈다면, 이제 그 IP 위로 통신 터널을 뚫어야 합니다. 통신 터널을 뚫는 규약인 프로토콜(Protocol)을 어떤 것을 쓰냐에 따라 해커에게 털릴 수도 있고, 안전하게 보호받을 수도 있습니다.

---

## 1. 텔넷 (Telnet) 통신의 문제점
네트워크 초창기 유닉스 시절부터 쓰이던 가장 단순무식하게 원격을 연결해 주는 역사적인 첫 접속 프로토콜입니다.

### 1.1 텔넷의 평문 구조 한계
* **치명적인 보안 위협**: 텔넷은 아이디와 비밀번호를 칠 때 아무런 '암호 잠금' 처리를 하지 않고 **텍스트 그대로(평문) 인터넷 선 위로 던집니다**. 누군가 중간에 패킷을 가로채서 까보기만 해도 최고 관리자 암호가 그대로 노출되는 최악의 단점이 있습니다.
* 요즘 기업 실무나 자격증 등에서는 텔넷을 절대 쓰지 않도록 강하게 규칙으로 정해 두고 있습니다.

## 2. 보안 원격 접속, SSH (Secure Shell)의 등장
구형 텔넷의 끔찍한 보안 수준을 혁신하기 위해 통신 터널 전체를 강력한 RSA/Ed25519 공개키 방식으로 겹겹이 랩핑하여 묶어버리는 철통 보안 프로토콜입니다.

### 2.1 SSH의 특장점
* **암호화 통신**: 지금 내 컴퓨터와 지구 반대편 서버 사이에서 왔다 갔다 하는 모든 통신 타이핑 글씨들이 전부 암호 연산 모듈에 의해 섞여서 날아갑니다. 중간에 누가 선을 뜯어서 까보아도 해독이 불가능합니다.
* **현재의 무조건적인 국제 표준**: 여러분이 다루게 될 AWS, 구글 클라우드, 사내 물리장비 등 모든 접속은 오로지 이 SSH 22번 포트 규약을 통해 이루어집니다. `Putty`, `MobaXterm`, `Mac 터미널` 등 모든 곳에서 쓰입니다.

## 4. [실습] SSH로 타겟 원격 서버 뚫기
맥북 터미널, 혹은 다른 우분투 PC에서 SSH 규약으로 내 타겟 장비로 원격 접속을 시도하는 실무 실습입니다.

### 실습 1. SSH 통신 명령어 던지기
```bash
# 내 서버의 접속 아이디가 'root' 이고 아까 구한 IP 통신 주소가 '192.168.1.12' 인 경우.
# 타겟 장비를 22번 포트로 강제로 찌릅니다.
ssh root@192.168.1.12
```

### 실습 2. 지문 인증 및 접속 확인
```bash
# 최초 접속 시 "The authenticity of host... can't be established." 경고창이 뜹니다.
# 통신 터널을 뚫고 지문(Fingerprint)을 처음 각인시키는 중요한 물음이므로 'yes' 라고 칩니다.

# 이어서 타겟 장비의 Password(비번)을 입력하면, 화면이 까맣게 깜빡 넘어감과 동시에 
# 드디어 원격지에 깔려 있는 머신 안으로 접속이 완료됩니다!
```
