# 7.3 레드햇 계열 (Rocky/CentOS) DNF 패키지 관리

대형 글로벌 금융권 서버 등에서 압도적으로 많이 쓰이는 RHEL(레드햇) 운영체제 기반의 패키지 관리 도구인 **DNF**의 개념과 실무 활용법을 알아봅니다.

---

## 1. YUM의 진화, DNF (Dandified Yum) 개요

윈도우와 다르게 레드햇 리눅스는 초창기에 `*.rpm` 이라는 껍데기 파일 포맷으로 소프트웨어를 유통했습니다. (데비안 계열의 `.deb`와 대척점인 개념입니다).

이 소스 구조의 네트워크 의존성을 해결해 주는 최고참 원조 매니저로 **`yum`** 명령어를 십수 년 동안 써왔습니다.
그러나 얌(`yum`)은 세월이 흐르며 구형 아키텍처 탓에 너무 느리고 오류가 잦아지는 문제가 발생했습니다.

그래서 현재 Rocky Linux 8, 9 등 최신 엔터프라이즈 환경에서는 `yum`의 메모리 소모를 대폭 개선한 **차세대 패키지 관리 툴인 `dnf`** 가 완벽히 표준으로 자리를 잡았습니다. 

### 1.1 YUM보다 DNF를 100% 무조건 써야 하는 이유
* **더 빠른 다운로드/설치 성능**: C++ 언어로 완전히 밑바닥부터 싹 재작성된 알고리즘으로 구성되어, 수백 개의 패키지 종속성 연결 고리를 번개같이 풀어내어 프로그램 설치 속도가 매우 향상되었습니다.
* **더 나은 오류 처리 역량**: 설치 도중 패키지가 깨지는 현상을 잘 견뎌내고, 더 직관적인 에러 메세지를 출력하여 초보 엔지니어도 트러블슈팅(문제 해결)을 하기가 월등히 수월합니다.
* **호환성**: 옛날 옛적 서버에 익숙한 현장의 꼰대 개발자들이 `yum` 이라고 쳐도, 서버 내부에서 눈치껏 알아서 `dnf` 모드로 돌려주는 파이프라인 호환성을 갖췄습니다. 하지만 아키텍트라면 가급적 `dnf`라고 손에 완전히 익혀 두는 것이 좋습니다.

## 2. 필수 시스템 패키지 명령어 (DNF)

우분투 서버의 `apt` 문법 체계와 비교해보면 알파벳 단어만 바뀌었을 뿐 매커니즘은 매우 흡사합니다. (마찬가지로 최상위 관리자 권리인 `sudo`가 강제됩니다.)

### 2.1 서버 패키지 카탈로그 업데이트 (`update`)
```bash
sudo dnf update
# (apt update + apt upgrade 두 가지 명령어를 이 dnf 한 줄이 전부 흡수하여 처리해 줍니다!)
```

### 2.2 새 패키지 강력 설치 (`install`)
```bash
sudo dnf install 패키지이름
```

### 2.3 시스템에서 패키지 지우기 (`remove`)
```bash
sudo dnf remove 패키지이름
```

### 2.4 원하는 패키지가 있는지 창고에서 색출 (`search / info`)
```bash
# 창고에 nginx 서버용 파일이 존재하는지 이름으로 검색합니다
sudo dnf search nginx

# 다운받기 전에 그 패키지의 용량, 제작사 등 엄청 상세한 정보를 표출합니다.
sudo dnf info nginx
```

## 4. [실습] DNF를 활용한 로키(Rocky) 리눅스 패키지 제어

로키 리눅스 혹은 레드햇 서버 환경에서 패키지를 다루는 기초 실무입니다. (자신의 서버가 데비안/우분투 계통이라면 동작하지 않습니다.)

### 실습 1. 웹(Web) 통신용 `curl` 인프라 프로그램 설치하기
```bash
# 1단계. 설치 전 이 패키지가 구비된 창고(Repository) 버전을 상세히 정보 조회합니다.
sudo dnf info curl

# 2단계. 정보를 확인 후 내 시스템에 설치를 확정합니다.
sudo dnf install curl

# 3단계. 깔린 프로그램의 버전을 검증합니다.
curl --version
```

### 실습 2. 깔리지 않은 가상의 게임 패키지 검색 시도
내 컴퓨터에 없는 마인크래프트 게임 관련 패키지가 레드햇 공식 창고에 등록되어 있는지 검색(Search) 망을 돌려보는 테스트입니다.
```bash
# 관련 패키지나 플러그인이 나오는지(혹은 없다고 나오는지) 화면 출력을 봅니다.
sudo dnf search minecraft
```
